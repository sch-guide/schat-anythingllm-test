# AI 모델 교체 안내

Gemini 요금이 바뀌어도 품질을 확인한 뒤 다른 Gemini 모델로 바꿀 수 있도록 정리한 안내임. 다른 회사 모델과 병원 내부 설치형 모델은 이번 범위에 넣지 않음.

## 용도별 모델

| 용도 | 설정 | 따로 정하지 않으면 | 바꾸는 방법 |
|---|---|---|---|
| 직원 답변 | `GEMINI_LLM_MODEL_PREF` | 없음(필수) | 관리자 → 시스템 상태 → 자세히 보기 → AI 설정 |
| 퀴즈 생성 | `SCHAT_QUIZ_MODEL` | 답변 모델 | 기술 담당자가 `docker/.env` 수정 후 재시작 |
| 동의어 후보 제안 | `SCHAT_SYNONYM_MODEL` | 답변 모델 | 기술 담당자가 `docker/.env` 수정 후 재시작 |
| PDF 그림 설명(문서 등록) | `SCHAT_PDF_IMAGE_DESCRIPTION_MODEL` | compose 기본값 `gemini-3.8-flash` | 기술 담당자가 `docker/.env` 수정 후 재시작 |
| 검색 Embedding | `EMBEDDING_MODEL_PREF` | `gemini-embedding-2` | 바꾸지 않음(전체 재색인과 승인 필요) |

- 현재 값은 관리자 → 시스템 상태 → 자세히 보기 → `용도별 AI 모델`에서 확인함. API 키는 표시하지 않음.
- 답변 모델만 바꾸면 PDF 그림 설명은 compose 기본값 때문에 계속 `gemini-3.8-flash`를 씀. 비용을 줄이려면 `SCHAT_PDF_IMAGE_DESCRIPTION_MODEL`도 함께 정해야 함.
- 검색 정확도는 Embedding과 단어 검색(BM25)이 결정함. 답변 모델을 바꿔도 검색 결과는 같음. 다만 근거 안에서만 답하는지, 없을 때 "확인되지 않습니다"라고 하는지는 모델마다 다르므로 아래 비교 시험을 먼저 함.

## 바꾸기 전 비교 시험

`server/scripts/schatModelCompare.js`로 같은 질문을 후보 모델마다 실제 답변 경로에 넣어 비교함.

- 문항: 승인된 21문항 중 단독 실행 가능한 19문항(정답 쪽 포함), 중심정맥관·진정절차 2문항, 범위 밖 22문항
- 결과: 정답 쪽 인용 수, "확인되지 않습니다" 수, 근거 없이 답한 수, 범위 밖 추측 수, 첫 글자·완료 시간, 토큰 수
- 답변 기록이 DB에 저장되므로 운영·3001 DB에서 실행하지 않음. 저장소 복사본을 쓰는 별도 컨테이너에서만 실행함.
- 실행 조건: `SCHAT_ALLOW_MODEL_COMPARE=true`. 실제 Gemini 호출 비용이 듦.
- 결과 JSON에는 답변 원문이 있으므로 Git에 넣지 않음.

```bash
SCHAT_ALLOW_MODEL_COMPARE=true node scripts/schatModelCompare.js \
  --models gemini-3.8-flash,gemini-3.5-flash-lite --out /tmp/model-compare.json
```

## 교체 순서

1. 후보 모델로 비교 시험을 실행함.
2. 범위 밖 추측 0건과 근거 없는 답변 0건을 확인함. 정답 쪽 인용 수가 기준 모델보다 크게 낮지 않은지 확인함.
3. 사람이 후보 답변 일부를 읽어 품질을 확인함.
4. 3001에서 관리자 화면으로 답변 모델을 바꾸고 직접 질문해 봄.
5. 운영 반영은 별도 승인 후 진행함.

## 요금 표시

- 관리자 요금 카드는 단가를 확인한 `gemini-3.8-flash`와 `gemini-3.5-flash-lite`(2026-10-14 확인, 입력 $0.30·출력 $2.50/100만 토큰, 인상 예고 없음)만 계산함.
- 그 밖의 모델로 바꾸면 요금은 "계산 불가"로 표시됨. 공식 단가를 확인해 `server/utils/aiUsageFees.js`에 추가해야 계산됨.
- 비교 시험 결과의 토큰 수에 공식 단가를 곱하면 모델별 예상 비용을 계산할 수 있음.

## 모델을 바꾸면 적용되는 범위 (2026-10-14 코드 확인)

- 관리자 화면에서 답변 모델을 저장하면 서버 재시작 없이 다음 질문부터 적용됨.
- 2026-10-14 이전 코드는 재시작하면 컨테이너를 만들 때의 예전 모델·API 키로 돌아갔음(복사본에서 재현). 서버 시작 때 관리자 관리 값 3개(`GEMINI_LLM_MODEL_PREF`, `GEMINI_API_KEY`, `GEMINI_EMBEDDING_API_KEY`)만 `.env`를 우선하도록 고침(`server/utils/boot/adminManagedEnv.js`). 다른 값은 지금처럼 컨테이너 설정을 따름.
- 운영 서버는 이 수정을 반영하기 전까지, 모델을 바꾼 뒤 컨테이너를 다시 만들어야(`docker compose up -d`) 재시작 후에도 유지됨.
- 코드에는 모델 이름별 분기가 없음(이름이 `gemini`로 시작하는지만 확인). 문맥 한도는 3.8·3.5-lite·3.1-lite 모두 1,048,576 토큰으로 같음.
- 작업 공간에 따로 지정된 모델이 없어 관리자 설정이 그대로 쓰임. 작업 공간 온도(2.0)는 Automatic 답변에 쓰이지 않음.
- 3001 테스트 서버는 2026-10-14 사용자가 관리자 화면에서 `gemini-3.5-flash-lite`로 바꿈. 같은 날 수정 반영 후 재시작해도 3.5-lite가 유지됨을 확인함.

## 2026-10-14 비교 결과 요약

| 항목 | gemini-3.8-flash | gemini-3.5-flash-lite |
|---|---|---|
| 범위 밖 질문 추측(66회) | 0 | 0 |
| 출처 없이 답함(63회) | 1 | 0 |
| 지침 질문 근거 답변(63회) | 59 | 54 |
| 답이 있는데 "확인되지 않습니다"(63회) | 3 | 9 |
| 정답 쪽 인용(57회) | 48 | 45 |
| 완료 시간 중간값 | 6.5초 | 1.7초 |
| 그림 설명 자기 쪽 5위 안(60장) | 40 | 37 |

- 답변 비교는 43문항을 3회씩 실행함. 원본 PDF와 대조했을 때 두 모델 모두 지어낸 숫자는 없었음.
- 3.5-lite는 여러 쪽을 묶어 정리하는 질문에서 "확인되지 않습니다"가 더 많음.
