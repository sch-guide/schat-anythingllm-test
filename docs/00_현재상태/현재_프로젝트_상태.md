# SCHAT 기능 비교 테스트 현재 상태

## 이 저장소의 목적

기존 SCHAT을 교체하기 전에 문서 등록, 검색, AI 답변, 출처, 직원 로그인과 도구 기능을 별도 환경에서 확인하는 저장소입니다.

## 현재 확인된 상태

| 구분 | 현재 상태 |
|---|---|
| 저장소 | 기존 SCHAT과 분리된 별도 Git 저장소 |
| 화면 | SCHAT 병원용 이름과 기본 디자인 적용 |
| 문서 화면 | 이 저장소 전용 `docs_view`로 분리 완료 |
| 폴더 정리 | 불필요한 배포·홍보 자료는 제거하고 웹 삽입 원본과 필수 자동검사 도구는 보존 |
| Explorer 순서 | 웹 문서, 현재 상태와 작업일지를 위로, 개발자용 파일을 맨 아래로 배치 |
| 검색 | Gemini Embedding 2 + ChromaDB 주 검색 + BM25 용어 보완 구현 |
| MiniLM | 새 SCHAT 검색 경로에서는 사용하지 않음 |
| 답변 생성 | Docker 실행 환경에서 Gemini 답변 모델 사용 |
| Docker | SCHAT 웹, ChromaDB, 내부 Python 안전검사 서비스 동시 실행 및 영구 저장 구성 완료 |
| 최소 기능 확인 | 테스트 문서 1개 등록, 임베딩, 색인, 질문, 답변과 출처 확인 성공 이력 있음 |
| 직원 로그인 | 다중 사용자 모드 전환, 관리자·일반 직원 계정 분리, 일반 직원 로그인 및 관리자 API 차단 확인 |
| 임상 안전검사 | 일반 직원 채팅에서 Gemini 후보를 화면에 보내기 전에 기존 Python 검사 실행. 실패·오류·시간초과 시 원문 기반 답변으로 대체 |
| 답변 표시 방식 | 안전검사가 끝나기 전 실시간 출력 중단. 통과한 답변 또는 원문 기반 안전 답변만 한 번에 표시 |
| 출처 표시 | 직원에게 문서명·페이지·항목명만 표시하고 내부 식별자는 숨김 |
| 실제 질문 검수 | 합성 비민감 질문 1건 실행. 구조화 형식은 정상 처리됐으나 필수 근거 누락으로 AI 후보를 차단하고 원문 기반 답변으로 대체 |
| 검색 정밀도 | 같은 질문에서 약한 두 번째 결과를 제거하고 직접 관련된 근거 1개만 반환 |
| 실제 병원 사용 | 안전검사 PASS 사례와 실제 승인 문서의 출처 메타데이터를 추가 확인하기 전까지 금지 |

## 다음 확인 순서

1. 실제 승인 문서를 등록할 때 문서명·페이지·항목명이 정상 보존되는지 확인합니다.
2. 안전검사를 통과하는 대표 질문 1건을 별도 승인 후 확인합니다.
3. 같은 질문으로 기존 SCHAT과 검색·답변을 비교합니다.
4. 검증 결과를 바탕으로 제한된 직원 시범운영 여부를 승인합니다.

## 현재 주의사항

- 이 문서의 성공 기록은 최소 테스트 문서 1개로 확인한 결과입니다.
- 전체 병원 지침서와 다양한 질문에 대한 성능 검증은 아직 완료되지 않았습니다.
- API 키, 환자정보와 병원 원문은 문서 화면에 저장하지 않습니다.
- 실제 Gemini 질문 1건에서 검사 전 후보는 노출되지 않았고 원문 기반 대체는 동작했지만, 안전검사 PASS 사례는 아직 확인하지 못했습니다.
- 기존 합성 문서는 등록 당시 한글 문서명이 이미 손실되어 원래 이름을 복구할 수 없습니다. 화면에서는 깨진 문자를 제거한 `SCHAT_.txt`를 표시하고, 없는 페이지·항목은 생략합니다.
- 구조화 JSON 형식 오류는 해결됐지만, 이번 후보는 검색 근거의 필수 문장을 모두 포함하지 않아 `evidence_coverage`로 차단됐습니다.
- 이번 연결은 시범운영 후보이며 정식 Production 승인으로 간주하지 않습니다.
