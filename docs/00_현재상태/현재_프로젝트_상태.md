- **현재 표시(파란색):** 빨간 테두리를 제거하고 확인된 직접 근거의 텍스트 줄·표 칸만 연한 파란색(#60A5FA, 불투명도 22%)으로 표시함. 떨어진 근거 사이의 일반 문장은 칠하지 않음. 기존 인용 선택·페이지 이동·원본 좌표·metadata는 유지함. 관련 자동 검사 36개, 화면 빌드와 합성 PDF 이미지 확인을 통과하고 로컬 3001에 반영함. 실제 병원 PDF·브라우저 클릭·휴대폰 육안 검증은 미실시이며 정확한 이미지 영역 강조는 추가하지 않음. [파란색 UI 작업 기록](../01_작업일지/2026-10-10_출처_파란색_하이라이트_UI.md), [합성 PDF 예시](http://localhost:3001/schat-blue-highlight-test.pdf?blue=1). 이번 작업은 commit/push/tag 없이 진행함.


- 최신 구현: 답변 생성 시 선택한 원문 인용을 출처별로 검증·저장하고 PC·모바일 표시에서 우선 사용하도록 연결함. 문장 그대로 일치 방식의 한계를 보완하는 변경이며 과거 답변에는 소급 적용되지 않음. 관련 합성 검사 75개와 화면 빌드를 통과하고 로컬 서버에 반영함. 사용자 실제 질문의 새 답변 화면 확인은 아직 남아 있음. [원문 인용 구간 저장 기록](../01_작업일지/2026-10-10_출처_원문인용구간_저장.md).

- 사용자 재확인: 같은 질문의 출처 3개 모두 위치 미확정으로 표시되어 근거 박스 기능은 미완료임. 검색 출처에는 실제 사용한 원문 구간 기록이 없어, 답변과 원문의 문장 일치만으로는 해결할 수 없음을 확인함. 다음 작업은 답변 생성 단계의 원문 인용 구간 전달·저장 및 검증임. 상세 다음 시작 위치는 빨간색 네모표시 작업일지 참고.

- 최신 수정: 검색 chunk 전체가 아닌 답변과 정확히 일치하는 원문 문장 구간만 박스 대상으로 선택함. 인접한 일치 문장은 함께 표시하고, 확인되지 않는 경우 원문 안내를 유지함. 표현이 바뀐 답변의 실제 사용 구간을 추적하는 기능은 미완료이며, 현재 방식은 정확한 문장 일치에 한정됨.

- 최신 사용자 요청: 단어·줄·표 칸별 작은 네모 대신 근거 chunk 전체를 큰 빨간 네모 하나로 감쌈. 서로 다른 근거는 각각 별도 네모로 표시함. 공유 좌표 계산을 바꾸어 PC·모바일 모두 적용하며 관련 검사 12개 통과.

- 샘플 링크 404 복구: 컨테이너 재실행 뒤 사라진 합성 PDF를 복구함. 다음 빌드에도 포함되도록 frontend/public에 보관함. 응답 형식 application/pdf와 PDF 내부 빨간 테두리 5개를 확인함. 실제 출처 클릭 검증은 별도임.

- 출처에 연결된 근거 전체가 인용 페이지에서 정확히 일치할 때 노란 표시를 제공하도록 구현함. 같은 페이지의 여러 근거를 모두 보존하고 첫 위치로 이동하도록 연결함.
- PC는 원본을 바꾸지 않고 브라우저 안에서 표시를 넣은 임시 PDF를 기본 뷰어에 열며, 모바일은 같은 좌표를 PDF 화면에 그림. 외부 AI 호출·서버 자료 변경은 없음.
- 여러 근거 중 하나라도 위치를 확정하지 못하면 부분 표시 없이 “정확한 위치를 찾지 못해 원문을 표시합니다.”와 원문만 표시함. 페이지를 넘는 근거·반복 문구·글자 단위 위치 추정이 필요한 구간·읽기 순서가 다른 표도 이 방식으로 처리함.
- 관련 자동 검사 30개, 화면 빌드, 합성 PDF 저장·재열기와 이미지 확인을 통과함. 이후 사용자 요청으로 로컬 3001 컨테이너의 화면 파일에 반영함. 실제 PC 기본 PDF 뷰어·모바일의 클릭·자동 이동은 브라우저 연결이 없어 미확인임.
- 로컬 확인 주소는 `http://localhost:3001`이며, 합성 PDF 미리보기는 `http://localhost:3001/schat-highlight-test.pdf`임. 기존 화면은 임시 폴더에 백업하고 서버·DB·검색 자료·컨테이너 재시작 없이 화면 파일만 갱신함. 컨테이너를 새로 만들면 해당 이미지의 화면으로 바뀌므로 다음 전체 빌드에도 구현 커밋 `49035667`을 포함해야 함.
- 상세 내용: [형광 표시 구현 기록](../01_작업일지/2026-10-10_출처_노란색_형광표시_구현.md). 다른 창의 문서 업데이트 완료 여부와는 별도로 기록함.

- 2026-10-10 로컬 코드 수정: 대기 중 멈추기 버튼을 회전하는 원으로 교체함. 내용이 있는 답변 아래 직접 근거 미확인 경고와 일부 주제 미확인 안내를 제거함. 검색된 참고 자료 목록과 목록 안 안내, 실제 근거 부족 답변 안내는 유지함. Node.js 실행 파일을 찾지 못해 화면 검사·빌드·실행 중 서비스 반영은 미확인임. 외부 API 호출은 하지 않음.

- 최신 표시 방식(사용자 요청): 노란 형광 대신 속이 빈 빨간색 네모 테두리로 변경함. PC 임시 PDF와 모바일 화면에 동일하게 적용함. 관련 자동 검사 12개와 화면 빌드를 통과했고, 합성 PDF 이미지에서 글자를 가리지 않는 테두리를 확인함. 로컬 3001 화면 파일을 갱신하고 HTTP 응답 및 빨간 PDF 테두리 5개를 확인함. [빨간 네모 샘플](http://localhost:3001/schat-redbox-test.pdf), [변경 기록](../01_작업일지/2026-10-10_출처_빨간색_네모표시.md).

## 1. SCHAT이 무엇인지

> 로컬 개발 중: 같은 이름 문서 업데이트 팝업과 서버 교체 연결을 작성하고 관련 자동 검사 87개를 통과함. 다른 업로드·작업공간 삭제와 동시에 실행할 때의 보호가 미완료이므로 새 업데이트 요청은 파일 수신 전에 차단함. 실제 DB·Chroma 교체와 3001 화면 검증은 미완료이며 Docker 반영·기능 커밋은 하지 않음. 출처 형광 표시는 아직 미구현임. [진행 기록](../01_작업일지/2026-10-10_문서업데이트_안전처리_진행중.md)에서 이어서 할 일을 확인함.

SCHAT은 AnythingLLM을 기반으로 만든 병원 실무지침 AI 시스템임.

- 현재 버전은 SCHAT 버전 3임.
- 버전 1~4의 구분은 [SCHAT 공식 버전 체계](SCHAT_버전_체계.md)를 기준으로 사용함.
- 현재 단계는 시범운영임.
- 검색 핵심 기능은 직접 개발·검증하고, 로그인·권한·문서관리 기반은 AnythingLLM을 활용함.
- 관리자가 등록한 병원 지침과 교육자료를 검색함.
- 검색된 근거 안에서 Gemini가 답변함.
- 직원에게 답변, 문서명 출처, 근거 원문과 원본 PDF를 제공함.
- 로컬 출처 화면에서 CT·MRI 등 질문 주제를 구분함. 근거 부족 답변은 출처를 숨기고 안내만 표시하며, 내용이 있지만 직접 근거를 특정하지 못하면 검색 자료를 접어서 표시함. 3001 실제 화면 검증·반영은 아직 하지 않음.
- 환자정보를 저장하는 시스템이 아니라 병원 문서 활용을 돕는 실무지원 시스템임.

## 2. 현재 동작 방식

### 질문 처리

`직원 질문 → 동의어·띄어쓰기 보완 → Vector + BM25 검색 → 관련 근거 선택 → Gemini 답변 → Citation(출처)·원본 PDF 제공`

| 기술 | 쉬운 설명 |
|---|---|
| Gemini Embedding | 질문과 문서의 의미를 비교하는 데 사용함. |
| ChromaDB | 의미가 비슷한 문서를 찾는 데 사용함. |
| BM25 | 약물명·검사명처럼 정확한 단어를 찾는 데 사용함. |
| Hybrid | 의미 검색 75%와 단어 검색 25%를 함께 사용함. |
| Gemini | 검색된 병원 근거를 읽고 답변을 작성함. |

### 문서 등록

`PDF 등록 → 텍스트·이미지 추출 → 검색용 조각 생성 → Embedding 생성 → ChromaDB·BM25 저장 → 검색 가능`

- 새 PDF를 등록하면 검색용 자료와 원본 PDF를 함께 보관함.
- 원본 PDF는 로그인과 workspace 권한을 확인한 뒤 제공함.
- 이미지 설명은 관련 이미지 검색을 돕는 보조 자료로 사용함.
- 체크리스트 추출이 실패해도 PDF 등록과 본문 검색은 유지함.
- 체크리스트는 `검사 및 시술`과 `수술` 문서에서만 자동 추출함.
- 새 버전 문서를 올리면 이전 공개본과 내용이 완전히 같은 체크리스트는 자동 공개하고, 바뀐 것과 새로 생긴 것만 "검토 필요"로 둠.
- 체크리스트 추출 실패는 관리자 시스템 기록에 쪽과 이유로 남김.
- 한 PDF 쪽에 체크리스트 표가 여러 개 있으면 좌표 영역별로 나누어 각각 생성함.
- `3Position BP`는 제목·별칭의 띄어쓰기와 영문 표기 차이를 확인해 검사 및 시술로 분류함.
- 관리자 체크리스트 수정 화면에서 자료 분류를 직접 지정하거나 자동 분류로 되돌릴 수 있게 로컬 구현·검증함. 관리자 지정값을 우선하며 내용·공개 상태는 유지함. 실제 Docker 3001 클릭 검증은 아직 하지 않음.
- 관리자 체크리스트는 문서명 → 쪽 번호 → 고정 ID 순서로 정렬함. 문서가 바뀌는 곳에 문서명을 표시함.
- 검사 및 시술 문서 p.63은 누락이 아니라 수술·검토 필요로 저장된 초안임. 상태와 자료를 모두 전체로 선택하면 p.62~64를 함께 확인함. 로컬 코드·자료 검증을 완료했으며 Docker 실제 화면 확인은 남아 있음.
- 직원 체크리스트는 체크 상태를 사용자·체크리스트별로 브라우저에 유지하고, 다시 열 때 이전 체크 안내와 `체크 모두 해제`를 제공함. 위아래에 `환자정보`·`기타메모` 칸이 있으며 메모는 서버로 보내지 않고 사용자·로그인 세션·체크리스트별로 브라우저에만 12시간 보관함(로그아웃 시 삭제).
- 직원 화면은 출처의 문서명만 표시하고, 내부 쪽 정보는 원본 PDF의 정확한 위치를 여는 데 계속 사용함.

## 3. 현재 사용 가능한 주요 기능

- 로컬 사용 통계에 시작일·종료일과 복수 부서 선택을 추가하고 Docker 3001에 반영함. 기존 기록을 삭제하지 않고 시범운영 기간의 질문·저장된 토큰을 집계함. 새 화면 파일 제공과 컨테이너 정상 상태를 확인함. 소수 인원 보호를 유지하며 실제 로그인 후 클릭 확인·운영 반영은 별도 진행함. [사용 방법과 제한](../01_작업일지/2026-10-10_사용통계_기간과부서_선택.md)을 확인함.
- 로컬 Docker 3001 직원 채팅에 답변 대기 표시를 추가함. 진행 문구, 20초 안내, [멈추기]·[다시 시도], 70초 자동 멈춤을 제공하고 멈춘 질문은 빈 답변으로 남기지 않음. 방식 C(추가 검색 제한)는 답을 못 찾는 경우가 늘어 켜지 않음. 운영 반영은 별도 진행함. [측정 결과와 원인 조사](../01_작업일지/2026-10-10_답변대기표시와_방식C측정.md)를 확인함.
- 로컬 Docker 3001에 동의어 후보 자동 제안을 추가함. 문서를 등록하면 제목·용어 줄만 Gemini에 보내 후보를 만들고 모두 `검토 필요`·`자동 제안`으로 넣음. 관리자가 `사용`으로 바꾸거나 추가 후보를 승인해야 검색·체크리스트에 적용됨. 문서는 한 개씩 처리하고 호출 한도에 걸리면 최대 3번 재시도함. 이미 등록된 문서는 한 번 실행 도구로 처리하며, 결과는 동의어 관리의 자동 생성 결과에서 확인함. 운영 반영과 운영 문서 실행은 별도 진행함. [동작과 실제 문서 확인 결과](../01_작업일지/2026-10-10_동의어_후보_자동제안.md)를 확인함.

| 구분 | 현재 기능 |
|---|---|
| 검색·답변 | 병원 문서를 Hybrid 방식으로 검색하고 근거 기반 답변을 제공함. |
| 출처 | 직원에게 문서명만 표시하고 근거 원문 또는 정확한 쪽의 원본 PDF를 제공함. 관리자는 검토를 위해 쪽 정보를 확인함. |
| 체크리스트 | 검사·시술·수술 자료를 체크 가능한 작업창으로 제공함. 한 쪽의 여러 표도 각각 생성함. 문서 새 버전에서도 같은 체크리스트는 이어서 공개함. 관리자 자료 분류는 체크리스트 표 구조와 추출 형식을 우선 사용함. |
| 퀴즈 | 등록된 지침서를 바탕으로 퀴즈를 제공함. 관리자는 문제 검토 화면에서 문제를 고치거나 지우고, 퀴즈 통계에서 주제별·부서별 정답률과 자주 틀리는 문항을 확인함. |
| 직원 기능 | 개인 계정, 채팅, 이용 가이드, 문제 신고를 제공함. 직원은 처음 로그인할 때 등록된 직원인지 확인한 뒤 비밀번호를 직접 만듦. |
| 관리자 기능 | 문서·사용자·체크리스트·퀴즈·동의어·FAQ·설정을 관리함. 체크리스트는 상태와 실제 성격에 따른 자료 종류를 함께 골라 볼 수 있음. 직원 0명인 부서는 삭제할 수 있음. |
| 직원 일괄 등록 | 부서·사번·이름·권한을 적은 양식(xlsx, csv)을 올리면 확인 결과를 먼저 보여 주고, 등록 버튼을 눌러야 계정을 만듦. 비밀번호는 양식에 넣지 않음. |
| 연결 설정 | Gemini 답변용·검색 임베딩용 API 키의 등록 상태와 현재 모델을 보여 주고, 새 키 저장과 연결 테스트를 할 수 있음. 임베딩 모델은 바꾸면 모든 문서의 검색 데이터를 다시 만들어야 해서 이 화면에서 바꿀 수 없음. |
| 브랜드 | 서비스 이름과 작업 공간 이름을 바꿀 수 있음. 병원 로고와 로그인 화면은 미리보기만 제공하고, 화질 확인이 필요해 이 화면에서 바꾸지 않음. |
| 운영 관리 | 사용 통계와 저장공간 확인·정리 기능을 제공함. 어디에서도 쓰지 않는 원본 PDF는 서버 재검증 후 삭제할 수 있음. |

- 동의어 23개를 모두 검토함.
- 안전한 17개를 검색에 사용하고 범위가 넓거나 혼동 가능한 6개는 끔 상태로 유지함.
- 검토 필요 동의어는 0개이며 관련 회귀 테스트 60건을 통과함.
- 새 문서를 등록하면 AI 동의어 후보가 `검토 필요`로 들어오므로, 등록 후 동의어 관리에서 확인이 필요함.

## 4. 실행·서버 구조

`직원 브라우저 → Caddy(HTTPS 연결) → SCHAT Web → ChromaDB·BM25 → Gemini → 답변과 출처`

- Google Cloud 서버에서 시범 운영함.
- Docker Compose로 `schat-web`, `schat-chromadb`, `schat-safety-evaluator`를 실행함.
- Caddy가 HTTPS 접속을 담당함.
- 운영 데이터는 `server/storage`와 Docker volume에 저장함.
- 서버 업데이트 전 DB와 필요한 운영 데이터를 백업함.
- 상세 절차는 [서버 배포 및 업데이트 안내](../../05_인수인계/서버_배포_및_업데이트_안내.md)에서 확인함.

## 8. 꼭 지켜야 할 안전 규칙

- 등록된 병원 문서 근거 안에서만 답변함.
- 근거가 없으면 일반 의학지식으로 추측하지 않음.
- API 키, 비밀번호, 환자정보를 문서나 Git에 저장하지 않음.
- 운영 DB·ChromaDB·PDF를 승인 없이 삭제하거나 초기화하지 않음.
- 검색 변경 뒤 기존 질문의 결과가 나빠지지 않았는지 회귀검사함.
- 운영 변경 전 로컬과 테스트 웹환경에서 먼저 확인함.

## 2026-10-14 진료지원 Excel 근거 위치 보완

여러 줄 업무형태 셀의 일부 인용 때문에 원본 근거 위치 연결이 끊기는 화면 문제를 수정했다. 실제 저장 답변에서 142행과 단축번호 1796 연결을 확인했으며, 화면 파일만 로컬 3001에 반영했다. 검색·답변·출처 선택은 변경하지 않았다. 브라우저 직접 클릭은 미확인이다. 상세 내용은 같은 날짜의 진료지원 근거위치 복원 작업일지를 참고한다.


## 2026-10-14 Excel 삭제 안전 점검

등록 전 Excel이 안전 점검에서 빠져 삭제 버튼이 표시되지 않는 문제를 수정했다. Excel 보관 폴더도 점검하며 실제 문서 삭제는 실행하지 않았다. 현재 사용 자료와 과거 답변·퀴즈 보호 정책은 유지했다. 로컬 3001에 관련 서버 파일만 반영했다.

## 2026-10-14 예전 문서 삭제 규칙과 퀴즈 근거

예전 문서는 현재 퀴즈 문제가 있을 때만 삭제를 막고, 퀴즈 생성 기록·빈 세트는 막지 않는다. 과거 답변의 출처로만 쓰인 예전 문서는 건수를 경고한 뒤 [그래도 삭제]로 지울 수 있으며 과거 답변은 보존된다. 과거 답변 수는 문서 번호와 pdfRef를 모두 센다. 지운 출처를 열면 "이 출처는 이전 버전 문서로 현재 원문을 확인할 수 없습니다."를 보여 준다. 퀴즈는 주제가 문서 제목 자체일 때 본문 여러 쪽을 근거로 쓰도록 퀴즈 생성에만 보완했다. 검색·답변·Chroma·Citation 선택·체크리스트·동의어는 변경하지 않았다. 로컬 3001에만 반영했고 운영 서버는 변경하지 않았다. 상세 내용은 같은 날짜의 예전문서 삭제규칙과 퀴즈근거 작업일지를 참고한다.

## 2026-10-14 스캔 PDF 퀴즈 안내와 예전 형식 Excel 삭제

운영 「실무지침서_중심정맥관.pdf」는 쪽마다 머리글 30자만 읽혀 SCHAT에 내용이 없음을 확인했다. 퀴즈는 이런 문서에서 AI를 부르지 않고 글자가 있는 PDF로 다시 등록하라고 안내한다. 문서 번호 없는 예전 형식 Excel은 이름으로 안전 점검해 등록 전이면 삭제할 수 있다. 로컬 3001에만 반영했고 운영 서버는 변경하지 않았다.


## 2026-10-14 체크리스트 인쇄 및 제목 정리

로컬 3001 체크리스트에 인쇄 버튼을 추가했다. 큰 항목은 제목만 표시하고 세부 항목과 단독 항목은 기존 저장 키를 그대로 사용한다. 인쇄는 모든 구역을 펼쳐 A4 내용으로 구성하며 체크·취소선과 기존 이름 가리기를 적용한다. 자동 검사 69개 및 화면 build 통과. 실제 PC·모바일 브라우저와 Edge·Chrome 인쇄 미리보기는 브라우저 연결 불가로 미확인이다. 사용자 기록 변경과 운영 배포는 하지 않았다. 자세한 범위와 한계는 같은 날짜 체크리스트 작업일지에 기록했다.

## 2026-10-14 한컴 PDF 글자 읽기와 퀴즈 주제 일치

「실무지침서_중심정맥관.pdf」는 그림 PDF가 아니라 등록에 쓰는 옛 pdf.js(1.10)가 한컴 PDF 글자를 못 읽은 것이 원인이었다. 옛 pdf.js로 거의 못 읽은 PDF만 최신 pdf.js(4.8.69)로 다시 읽도록 문서 처리기를 고쳤고, 기존 PDF 4개는 그대로 읽힘을 확인했다. 퀴즈는 주제 핵심 단어가 모두 있는 근거만 쓴다. 3001에서 중심정맥관 10문항 생성·삭제·재생성과 다른 PDF 회귀를 확인했다. 운영 반영 후 이 문서를 같은 이름으로 다시 업데이트해야 한다.

## 2026-10-14 체크리스트 관리 삭제 기능

체크리스트 관리에 관리자 [삭제] 버튼을 추가했다. 삭제한 체크리스트는 직원·관리자 화면에서 사라지고, 같은 문서를 다시 읽어도 되살아나지 않는다. 잠시 숨기려면 기존 '숨김' 상태를 쓴다. 로컬 3001에서 가상 체크리스트로 확인했고 운영 서버는 변경하지 않았다.
