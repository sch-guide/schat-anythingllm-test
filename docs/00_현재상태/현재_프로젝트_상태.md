# SCHAT 현재 프로젝트 상태

## 1. SCHAT이 무엇인지

SCHAT은 AnythingLLM을 기반으로 만든 병원 실무지침 AI 시스템임.

- 현재 버전은 SCHAT 버전 3임.
- 버전 1~4의 구분은 [SCHAT 공식 버전 체계](SCHAT_버전_체계.md)를 기준으로 사용함.
- 현재 단계는 시범운영임.
- 검색 핵심 기능은 직접 개발·검증하고, 로그인·권한·문서관리 기반은 AnythingLLM을 활용함.
- 관리자가 등록한 병원 지침과 교육자료를 검색함.
- 검색된 근거 안에서 Gemini가 답변함.
- 직원에게 답변, 출처, 근거 원문, 원본 PDF 쪽을 제공함.
- 환자정보를 저장하는 시스템이 아니라 병원 문서 활용을 돕는 실무지원 시스템임.

## 2. 현재 동작 방식

### 질문 처리

`직원 질문 → 동의어·띄어쓰기 보완 → Vector + BM25 검색 → 관련 근거 선택 → Gemini 답변 → Citation(출처)·원본 PDF 제공`

| 기술 | 쉬운 설명 |
|---|---|
| Gemini Embedding | 질문과 문서의 의미를 비교하는 데 사용함. |
| ChromaDB | 의미가 비슷한 문서를 찾는 데 사용함. |
| BM25 | 약물명·검사명처럼 정확한 단어를 찾는 데 사용함. |
| Hybrid | 의미 검색 75%와 단어 검색 25%를 함께 사용함. |
| Gemini | 검색된 병원 근거를 읽고 답변을 작성함. |

### 문서 등록

`PDF 등록 → 텍스트·이미지 추출 → 검색용 조각 생성 → Embedding 생성 → ChromaDB·BM25 저장 → 검색 가능`

- 새 PDF를 등록하면 검색용 자료와 원본 PDF를 함께 보관함.
- 원본 PDF는 로그인과 workspace 권한을 확인한 뒤 제공함.
- 이미지 설명은 관련 이미지 검색을 돕는 보조 자료로 사용함.
- 체크리스트 추출이 실패해도 PDF 등록과 본문 검색은 유지함.
- 체크리스트는 `검사 및 시술`과 `수술` 문서에서만 자동 추출함.
- 새 버전 문서를 올리면 이전 공개본과 내용이 완전히 같은 체크리스트는 자동 공개하고, 바뀐 것과 새로 생긴 것만 "검토 필요"로 둠.
- 체크리스트 추출 실패는 관리자 시스템 기록에 쪽과 이유로 남김.

## 3. 현재 사용 가능한 주요 기능

| 구분 | 현재 기능 |
|---|---|
| 검색·답변 | 병원 문서를 Hybrid 방식으로 검색하고 근거 기반 답변을 제공함. |
| 출처 | 문서명과 쪽을 표시하고 근거 원문 또는 원본 PDF를 제공함. |
| 체크리스트 | 검사·시술·수술 자료를 체크 가능한 작업창으로 제공함. 문서 새 버전에서도 같은 체크리스트는 이어서 공개함. 관리자 보기·수정 화면은 직원 화면과 같은 구조로 보여줌. |
| 퀴즈 | 등록된 지침서를 바탕으로 퀴즈를 제공함. |
| 직원 기능 | 개인 계정, 채팅, 이용 가이드, 문제 신고를 제공함. |
| 관리자 기능 | 문서·사용자·체크리스트·퀴즈·동의어·FAQ·설정을 관리함. 직원 0명인 부서는 삭제할 수 있음. |
| 운영 관리 | 사용 통계와 저장공간 확인·정리 기능을 제공함. 어디에서도 쓰지 않는 원본 PDF는 서버 재검증 후 삭제할 수 있음. |

- 동의어 23개를 모두 검토함.
- 안전한 17개를 검색에 사용하고 범위가 넓거나 혼동 가능한 6개는 끔 상태로 유지함.
- 검토 필요 동의어는 0개이며 관련 회귀 테스트 60건을 통과함.

## 4. 실행·서버 구조

`직원 브라우저 → Caddy(HTTPS 연결) → SCHAT Web → ChromaDB·BM25 → Gemini → 답변과 출처`

- Google Cloud 서버에서 시범 운영함.
- Docker Compose로 `schat-web`, `schat-chromadb`, `schat-safety-evaluator`를 실행함.
- Caddy가 HTTPS 접속을 담당함.
- 운영 데이터는 `server/storage`와 Docker volume에 저장함.
- 서버 업데이트 전 DB와 필요한 운영 데이터를 백업함.
- 상세 절차는 [서버 배포 및 업데이트 안내](../../05_인수인계/서버_배포_및_업데이트_안내.md)에서 확인함.

### 버전 4 이후 개선사항

- 21문항 전체 실제 Automatic 재검증을 진행함.
- Citation 추가 정밀 개선을 진행함.
- 문서 최신 버전과 최신 버전만 검색하는 기능을 검토함.
- RAGAS 실제 적용을 후속 평가로 진행함.
- 표 구조 검색은 현재 버전 3 범위에서 제외함.
- 기타 UX 개선을 계속 진행함.

## 7. 주요 폴더

| 위치 | 역할 |
|---|---|
| `frontend/` | 직원·관리자 화면 코드가 있음. |
| `server/` | 로그인, 검색, Gemini 답변, 출처, API 코드가 있음. |
| `collector/` | PDF에서 텍스트와 이미지를 추출함. |
| `docker/` | 서버 실행 설정이 있음. |
| `docs/` | 현재 상태, 작업일지, 멘토링 문서가 있음. |
| `docs_view/` | 공식 문서를 웹에서 읽기 쉽게 보여줌. |
| `server/storage/` | DB, 등록 문서, 이미지, 원본 PDF를 저장함. Git에 올리지 않음. |

## 8. 꼭 지켜야 할 안전 규칙

- 등록된 병원 문서 근거 안에서만 답변함.
- 근거가 없으면 일반 의학지식으로 추측하지 않음.
- API 키, 비밀번호, 환자정보를 문서나 Git에 저장하지 않음.
- 운영 DB·ChromaDB·PDF를 승인 없이 삭제하거나 초기화하지 않음.
- 검색 변경 뒤 기존 질문의 결과가 나빠지지 않았는지 회귀검사함.
- 운영 변경 전 로컬과 테스트 웹환경에서 먼저 확인함.
