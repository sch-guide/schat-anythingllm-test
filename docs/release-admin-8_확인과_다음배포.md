## 후보 찾기 호출 수·금액

- 하루 한 번 새벽 3시, 기본 최대 20회. 관리자 설정 0이면 끔. 반복 표현이 없으면 실제 호출은 0회일 수 있음. 실패 요청도 상한에 포함하며 숨은 자동 재전송은 하지 않음.
- 사용량이 확정되기 전 정확한 원화 비용은 알 수 없음. 프로그램에 지정한 2026년 요금·환율로, 한 번에 보내는 분량 2,000단위와 받는 분량(생각 포함) 500단위라고 가정하면 약 5원, 20회는 약 95원임. 실제 사용량이 아니며 답변 분량·모델·요금 시기에 따라 달라짐.
- 문서 등록 때 후보 찾기는 기존 자동 경로를 유지함. 이번 직원 질문 후보 예약과 별개이며, 20회는 모든 SCHAT 호출의 통합 한도가 아니라 직원 질문 후보 찾기 한도임.

1. 수동 VM 스냅샷과 일관된 DB/storage/Chroma 백업을 확보하고 현재 커밋·이미지·설정을 기록함. 키와 비밀번호는 출력하거나 새 문서에 복사하지 않음.
2. 정확한 release-admin-8 커밋을 받아 차이를 확인함. 기존 서버 변경과 storage를 강제로 덮어쓰지 않음.
3. 이번에는 DB 변경이 있음. 백업 사본에서 새 migration을 먼저 확인하고 기존 배포 방식으로 새 이미지를 빌드함. 현재 시작 스크립트는 Prisma 생성과 migrate deploy 후 서버를 시작하므로 적용 성공 여부를 확인함. 초기화·reset·db push 명령으로 대체하지 않음.
4. 로그인·기존 질문 기록·출처·체크리스트·관리자 화면과 싫어요를 확인함. 새벽 후보 찾기는 기본 20회로 작동하므로 원치 않으면 관리자에서 0으로 설정함. 로컬 전용 호출 차단 설정을 운영 설정으로 무심코 복사하지 않음.
5. 서비스 확인과 다른 빌드가 끝난 뒤 `sudo docker builder prune -f` 실행. DB·Chroma·storage·원본을 정리 대상으로 삼지 않음.
6. 문제가 있으면 신규 사용을 멈추고 이전 이미지/설정과 검증한 백업으로 복구할지 판단함. DB 변경 이력을 임의로 지우지 않음. 스냅샷 복원은 스냅샷 이후 자료가 빠질 수 있으므로 현재 자료도 보존하고 점검 시간에 수행함.
