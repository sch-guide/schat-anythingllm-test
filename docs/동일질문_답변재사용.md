# 같은 질문의 답변 재사용 — 5단계

로컬 구현과 자동 검증을 마친 기능 설명임. 운영 서버와 로컬 3001 반영 완료를 뜻하지 않음.

## 무엇을 줄이는 기능인가

같은 부서에서 같은 독립 질문을 다시 하면, 안전하게 재사용할 수 있는 답변과 출처를 잠시 보관했다가 보여주는 기능임. 이를 ‘답변 캐시’라고 부름. 재사용한 요청은 답변 생성 대기열에 들어가지 않고 Gemini를 다시 부르지 않음. 직원의 새 질문과 답변 기록은 별도로 남음.

## 같다고 보는 범위

- 공백·일반 영문 대소문자·문장 끝 물음표와 느낌표 차이를 보수적으로 통일함.
- 의미가 비슷하다는 이유로 서로 다른 질문을 합치지 않음.
- `0.5`와 `5`, `1~3`과 `13`, `1:2`와 `12`, `mM`과 `mm` 등 숫자·범위·비율·단위 차이는 구별함. 안전을 위해 모든 문장부호를 지우지는 않음.
- 부서, 모델, 답변 설정, 등록 문서 상태가 다르면 재사용하지 않음.

## 처음 적용하는 안전 범위

현재 SCHAT의 근거 기반 일반 query 경로에서 대화 이력과 첨부가 없는 독립 질문부터 적용함. 새 대화의 첫 질문이나 같은 부서의 다른 직원이 처음 묻는 같은 질문이 해당할 수 있음.

다음은 기존 방식으로 새 답변을 생성함.

- 앞선 대화를 이어서 묻는 질문, 개인 첨부 자료를 사용하는 질문
- Agent·자동 도구 선택·명령·모델 라우터를 사용하는 질문
- 별도 안전 평가 게이트를 사용하는 경로, 자동 동기화 문서가 있는 작업 공간
- native 임베딩 또는 임베딩 설정이 없는 경우(별도 문서 처리 프로세스의 변경 보호를 보장하지 못하므로 제외)
- 자료나 설정 상태를 확인할 수 없는 경우, 출처 없는 답변·오류·취소된 답변

사전 확인 후 대기 중 개인 파일이나 대화 이력이 생겼더라도, 실제 그 자료를 읽은 답변은 공유 캐시에 저장하지 않음. 따라서 모든 반복 질문이 재사용되는 것은 아님.

## 자료를 바꾸면 어떻게 되는가

문서 등록·수정·삭제와 개인 파일 변경 중에는 영향을 받는 부서의 재사용을 막고 이전 답변을 비움. 변경 전 질문이 뒤늦게 끝나도 다시 저장하지 않음. 기존 미완성 문서 업데이트 기능에도 별도 보호 연결을 추가했으나, 그 기능 전체의 완료·배포 여부는 해당 작업일지를 따름.

답변 보관소는 서버 메모리에서 전체 부서 합계 최대 100개임. 가득 차면 가장 오래 사용하지 않은 항목부터 비움. 서버를 재시작하면 비워짐. 문서·대화 기록·체크리스트를 삭제하는 기능이 아님.

## 관리자가 확인할 항목

관리자 설정 → **답변 재사용**에서 작업 공간을 선택하면 저장된 질문, 재사용 횟수, 저장 시각을 확인함. 개별 삭제와 모든 작업 공간의 캐시 비우기를 제공하며, 전체 비우기는 확인창에서 승인해야 실행함. 화면 연결과 최종 코드 검토를 마침.

절약 횟수는 이 서버에서 캐시가 적중한 답변 호출 수 기준임. Gemini 전체 사용액이나 실제 잔액이 아니며 임베딩·퀴즈·Agent 비용 전체를 계산하지 않음. 서버 재시작 시 누계도 초기화됨.

## 검증 범위

가짜 모델과 DB를 사용하는 자동 검사로 동일 질문 재사용, 다른 부서·숫자 구별, 출처 유지, 문서 변경·개인 파일 경쟁 조건을 확인함. 외부 통신 없는 임시 Docker의 캐시 검사 24개가 통과함. 전체 앱 HTTP·실제 브라우저·병원 자료의 답변 품질 검증과는 다름. 실제 Gemini 호출 없이 진행함.

진행 상태와 남은 일은 [5단계 작업일지](01_작업일지/2026-10-11_5단계_동일질문_캐시_진행.md)를 확인함.

## 추후 로컬 3001 반영 후 직접 확인할 순서

1. 관리자 설정에서 ‘답변 재사용’ 메뉴가 보이는지 확인함. 직원 계정에는 보이면 안 됨.
2. 작업 공간을 바꾸며 목록과 작업 공간 이름이 함께 바뀌는지 확인함. 서버 시작 직후에는 0개가 정상임. 불러오기 실패는 0개 대신 안내로 표시함.
3. 테스트 자료로 캐시를 만든 뒤 사용 횟수와 출처를 확인함. 같은 대화에서 계속 묻는 것이 아니라, 같은 작업 공간의 이력 없는 새 대화에서 질문해야 대상이 됨. 질문 생성은 실제 API를 호출할 수 있으므로 이번 가짜 검사와 구분하고 별도로 승인한 범위에서만 진행함.
4. 항목 하나를 삭제하면 목록에서 그 항목만 빠지는지 확인함. 등록 문서·체크리스트·대화 기록은 그대로 있어야 함.
5. ‘전체 비우기’ 확인창에서 취소하면 그대로인지 확인함. 승인하면 모든 작업 공간의 캐시만 비워지며, 서버 시작 후 아낀 답변 호출 누계는 유지함.

현재 실행 중인 3001 컨테이너는 이번 작업으로 재빌드하지 않았으므로 새 메뉴가 아직 보이지 않을 수 있음.
