# SCHAT 21문항 근거 선택 개선 결과

> 이 문서는 `15_21문항_실패원인분석.md` 뒤에 수행한 검색 이후 단계의 최소 수정과 검증 결과를 정리합니다. 검색기, Hybrid 75:25, 임베딩, Top-K, 관리자 답변 규칙은 바꾸지 않았습니다.

## 1. 결론

- 병원 질문 감지, 후속질문 문맥 보완, 요청 표현 제거, 본문 우선 근거 선택을 작은 규칙으로 보완했습니다.
- 관련 회귀 테스트는 **55/55 통과**했습니다.
- 저장된 A8 기준선과 현재 Top-10 스냅샷은 세 방식 모두 **완전히 동일**합니다.
- 본문 vector는 **654개**로 유지됐습니다.
- 다만 이번 21문항 Automatic 재실행은 수집 도구가 Agent WebSocket을 연결하지 않아 답변·Citation을 받지 못했습니다. 같은 질문을 다시 외부 API로 보내지 않았으므로 **수정 후 21문항 답변 통계와 실제 브라우저 판정은 미확인**입니다.

## 2. 최소 수정 내용

| 문제 | 보완 |
|---|---|
| `진정할`, `관찰해` 같은 활용형 | 의료 용어·영문 약어·숫자는 보존하고 필요한 한국어 어미만 제한적으로 정리 |
| `전체적으로`, `핵심`, `요약`, `알려줘` | 임상 내용어가 아닌 요청 표현으로 분리 |
| `그중`, `그 후` 후속질문 | 직전 사용자 질문의 명확한 임상 주제만 검색어에 보완 |
| `피 넣기 전에…` | 기존 의도 판별 경로에서 제한적으로 `수혈`로 정규화 |
| 이미지 설명만 남는 문제 | 절차·숫자 답변은 본문 근거를 우선하고 이미지 설명은 보조로 제한 |
| 병원 질문인데 source 0 | 이전 대화의 구체 답변을 근거처럼 넘기지 않고 기존 근거 부족 원칙 적용 |

수정 범위는 다음 파일로 제한했습니다.

- `server/utils/vectorDbProviders/chroma/schatBm25.js`
- `server/utils/agents/aibitat/utils/hospitalDocumentIntent.js`
- `server/utils/agents/aibitat/index.js`
- 위 동작의 회귀 테스트

## 5. 21문항 Automatic 재실행 상태

### 발생한 일

1. 실제 직원이 아닌 로컬 전용 가상 직원 계정을 만들었습니다.
2. 30분 JWT를 프로세스 메모리에서만 사용했습니다.
3. 각 문항마다 독립 thread를 만들고 HTTP 시작 요청을 보냈습니다.
4. 수집기가 Agent WebSocket을 열지 않아 `agentInitWebsocketConnection`, `statusResponse`까지만 받았습니다.
5. 따라서 Gemini 답변 본문과 Citation은 생성·수집되지 않았습니다.
6. 같은 질문을 다시 보내지 않았습니다.
7. 임시 계정, workspace 연결, thread, chat을 삭제했고 기존 JWT 접근이 거부되는 것을 확인했습니다.

### 판정 가능한 것과 없는 것

| 항목 | 상태 |
|---|---|
| 질문 재시도 | 0회 |
| 실제 Gemini 답변 호출 | Agent WebSocket 미연결로 시작되지 않음 |
| 수정 후 21문항 답변 | 미확인 |
| 수정 후 Citation 없음 건수 | 미확인 |
| 수정 후 기대 페이지 포함 건수 | 미확인 |
| 실제 브라우저 Citation | 검증할 저장 답변이 없어 미확인 |
| 임시 계정·토큰 폐기 | 확인 완료 |

로컬 결과 파일 `SCHAT_21문항_근거선택개선_실행결과.json`의 빈 답변은 제품 실패 결과가 아니라 **수집기 실패 결과**이므로 성능 통계에 사용하면 안 됩니다.

## 6. Citation 과다

- 이번에는 실제 수정 후 답변을 수집하지 못했으므로 과다 Citation을 새로 집계하지 않았습니다.
- 검색 결과나 Citation frontend를 추가로 바꾸지 않았습니다.
- 기존 분석에서 확인된 원인은 첫 검색과 추가 `rag-memory` source 누적, 그리고 답변이 실제 사용한 source ID를 반환하지 않는 구조입니다.
- 실제 결과를 확보하기 전에는 안전한 정리 범위를 확정할 수 없어 추가 코드를 수정하지 않았습니다.

## 7. 테스트 웹과 기존 기능

- 로컬 `schat-web`, `schat-chromadb`, `schat-safety-evaluator`: 모두 healthy
- 최신 서버 파일 3개를 로컬 테스트 컨테이너에만 반영했습니다.
- 운영 서버: 변경하지 않음
- 브라우저 자동화 경로는 준비했지만 저장 답변이 없어 실제 Citation 검증을 완료하지 않았습니다.
- Automatic, AgentHandler, rag-memory, PDF viewer, checklist, 로그인, 문제 신고 코드는 이번 후속 검증에서 추가 변경하지 않았습니다.

## 8. 다음 확인 조건

21문항을 다시 실행하려면, 앞선 시작 요청과 별개로 **실제 Agent WebSocket 경로에서 질문을 다시 한 번 보내도 된다는 명시적 승인**이 필요합니다. 승인 전에는 외부 API 호출을 반복하지 않습니다.

## 9. SCHAT 1.0 확정 결정

2026년 9월 30일 사용자가 21문항 전체 실제 재실행을 1.0 필수 조건에서 제외하고 이후 품질검증으로 이관했습니다. Hybrid 검색 기준, 범위 밖 질문, A8 회귀, Top-10 유지, 핵심 실패 문항 회귀 테스트와 기존 주요 기능 상태를 기준으로 **SCHAT 1.0을 확정**합니다.

문서 최신 버전 관리는 **SCHAT 1.1 개선 항목**으로 이관합니다.
