# 프롬프트 관리

## 답변 규칙 우선순위

1. workspace에 별도로 설정한 prompt
2. 관리자 화면의 `SCHAT 기본 답변 규칙`
3. `server/config/prompts/answer-system.yaml` 기준본
4. 코드 내부 최후 fallback

관리자 DB 값은 수정하거나 덮어쓰지 않았습니다. YAML은 DB 값이 없을 때만 쓰는 기준본·fallback입니다.

## 보존 검사

- 관리자 DB prompt: 1,167자
- YAML prompt: 1,167자
- SHA-256: `b9d76f...b1d22b7` (동일)
- 결론: 사용자가 제공한 17개 공식 규칙과 답변 형식을 축약·통합하지 않고 그대로 보존

## 실제 prompt 위치

| 위치 | 용도 | 사용 여부 |
|---|---|---|
| `server/models/systemSettings.js` | 기본 답변 규칙 우선순위 | 사용 |
| `server/utils/chats/index.js` | workspace/기본 prompt를 일반 채팅에 전달 | 사용 |
| `server/utils/agents/aibitat/providers/ai-provider.js` | Automatic Agent에 답변 규칙 전달 | 사용 |
| `server/utils/documentImages.js` | 이미지 설명 추출 지시 | 사용 |
| `server/utils/schatQuiz/generation.js` | 퀴즈 구조화 생성 지시 | 사용 |
| `safety_evaluator/` 및 `schat-core/` | 답변 안전성 평가 | 사용 |

체크리스트는 현재 규칙 기반이므로 사용하지 않는 LLM prompt YAML을 만들지 않았습니다.

## 서버 반영

- 관리자 화면 prompt 수정: 기존처럼 DB에 저장되며 다음 답변부터 적용됩니다.
- YAML 기준본 수정: 소스코드 파일이므로 테스트 이미지를 다시 build하고 container를 재시작해야 합니다.
- runtime reload는 구현하지 않았습니다.
- 운영 서버에는 이번 작업을 반영하지 않았습니다.

## 검색 영향

YAML은 검색 후 Gemini 답변 단계에서만 fallback으로 읽힙니다. Vector, BM25, Hybrid 75:25, Top-K, embedding, source/Citation filtering을 수정하지 않았습니다.

Node 실제 런타임에서 YAML version 1.0과 1,167자 prompt를 정상적으로 읽었고, production Docker image build와 로컬 테스트 웹 재시작을 완료했습니다. 재시작 후 DB 개수·관리자 prompt hash·본문 vector 654개·A8 Top-10이 변경 전과 모두 같았습니다.
