# 평가 체계 정리

## 현재 사람이 만든 정답

- 원본: 예전 SCHAT의 `schat_v1_operational_gold_reviewed.json`
- 전체 질문: 36개(진정 14, 수혈 18, 범위 밖 4)
- 최종 승인되어 검색 평가에 쓴 양성 질문: **21개**
- 별도 검토 대기 양성 질문: 11개
- 범위 밖 질문: 4개
- 형식: 질문 ID, 문서 범위, 정답 조각 ID, 핵심 사실·숫자·단계, 검토자, 승인 상태

### 부족한 점

1. 예전 정답 조각 ID는 현재 운영 조각 ID와 달라, 이번 A8 평가에서는 현재 운영 문서명·쪽으로 다시 연결했습니다.
2. 문서명·쪽 기준의 정답 연결을 계속 관리하지 않으면 다음 문서 버전에서 다시 연결해야 합니다.
3. 실제 병동의 다양한 말투와 오타·약어 질문이 더 필요합니다.
4. ‘근거 없음’ 질문과 답변 내용 정확성 평가는 검색 평가와 분리해야 합니다.

간호사가 추가할 수 있는 양식은 `간호사_정답데이터_입력양식.xlsx`로 만들었습니다.

## 현재 운영 버전 A8 재평가

승인 정답 21문항, 본문 조각 654개, 상위 10개를 동일하게 두고 검색 방식만 바꿨습니다.

| 방식 | Hit@10 | MRR |
|---|---:|---:|
| 의미 검색(Vector) | 100% (21/21) | 0.743 |
| 단어 검색(BM25) | 71.4% (15/21) | 0.560 |
| 하이브리드 | 100% (21/21) | 0.738 |

의미 검색과 하이브리드는 21개 정답을 모두 10위 안에서 찾았습니다. 단어 검색은 정확한 표현이 겹치는 질문에서는 강하지만, 표현이 달라지는 질문 6개를 놓쳤습니다. 상세 결과와 원문은 Git 제외 엑셀에 보관했습니다. 질문 임베딩을 만들기 위한 Gemini Embedding 요청은 6회였고, 답변 생성이나 RAGAS 채점은 실행하지 않았습니다.

## RAGAS 도입 준비(이번에는 실행하지 않음)

필요한 것은 질문, 실제 답변, 검색된 근거, 사람이 적은 기준 답안입니다. Gemini를 채점 모델로 연결한 뒤 faithfulness(근거 충실성), answer relevancy(질문 적합성), context precision/recall(검색 정확도)을 계산합니다.

### 비용을 안전하게 잡는 방법

- 정확한 금액은 실행 시점 Gemini 공식 요금표와 실제 토큰 수로 다시 계산해야 합니다.
- 21문항 × 4개 지표 × 지표당 1회 채점이면 약 84회 호출입니다.
- 문항당 입력 3,000토큰·출력 500토큰으로 넉넉히 잡으면 전체 약 입력 25.2만·출력 4.2만 토큰입니다.
- Flash급 모델의 토큰 단가를 적용하면 보통 **수백 원~수천 원 범위**로 예상되지만, 모델명·thinking 사용·재시도에 따라 달라집니다. 실행 직전 [Gemini API 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 원화 환산값으로 다시 승인받습니다.
- 먼저 5문항으로 토큰 사용량과 원화 비용을 확인한 뒤 21문항으로 넓힙니다.
- 병원 원문 외부 전송은 별도 승인 후 실행하고, 환자정보가 없는 평가 자료만 사용합니다.

이번 문서에서는 가격을 임의로 확정하지 않았고 RAGAS 호출도 하지 않았습니다.
