# 문서 버전 관리 설계

> **진행 상태:** SCHAT 1.0 범위에서 제외하고 **SCHAT 1.1 개선 항목**으로 이관했습니다. 이 문서는 다음 버전 구현을 위한 설계 기록이며, 현재 운영 검색에는 적용하지 않았습니다.

## 현재 구조

- `document_id`는 DB와 Chroma metadata에 있습니다.
- `document_version` metadata 칸은 있지만 현재 운영 문서는 비어 있습니다.
- 문서 계열(family), 현재 버전(current), 교체 문서(replacedBy)를 관리하는 공통 DB 구조가 없습니다.
- 따라서 같은 지침서의 구버전과 신버전이 모두 workspace에 연결되면 둘 다 검색 후보가 될 수 있습니다.

## 변경 전 안전 조치

- SQLite online backup: `server/storage/backups/anythingllm-pre-1.0-20260929-221627.db`
- 기준선 snapshot: `로컬전용_원자료/SCHAT_1.0_변경전_기준선.json`
- 백업 당시 주요 개수: 사용자 28, workspace 1, 문서 행 543, vector 연결 1,985, 채팅 212
- 복구 방법: 테스트 컨테이너를 중지한 뒤 테스트 DB를 백업 본으로 되돌리고 컨테이너를 재시작합니다. 운영 DB에는 적용하지 않았습니다.

## 권장 구조

| 칸 | 용도 |
|---|---|
| familyKey | 같은 지침서 계열을 묶는 안정적 값 |
| documentId | 기존 문서 ID |
| version | 관리자가 확인한 버전 |
| isCurrent | 직원 검색에 사용할지 |
| uploadedAt | 등록 시각 |
| replacedBy | 다음 현재 문서 ID |

Vector와 BM25가 각자 버전을 추측하지 않고, 하나의 `현재 사용 document_id 집합`을 공통으로 받아야 합니다. 등록 정보가 아직 없는 기존 workspace는 현재처럼 연결 문서 전체를 허용하는 하위 호환을 사용합니다.

## 이번 작업에서 구현하지 않은 이유

현재 세션에서 Node/Docker 테스트 웹을 실행할 수 없습니다. 이 상태에서 검색 필터를 적용하면 A8 Top-10을 즉시 비교할 수 없고, 사용자가 지정한 중단 조건을 위반합니다. 따라서 **DB migration과 최신 문서 필터는 아직 적용하지 않았습니다.**

테스트 환경이 준비되면 migration → 기존 결과 동일성 확인 → 구/신 버전 fixture 확인 → A8 21문항 Top-10 비교 순으로 진행합니다.
