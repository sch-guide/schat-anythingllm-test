이 문서는 준비 안내임. 이번 작업에서 GitHub push·Google Cloud 접속·운영 반영은 하지 않음.

추가: 3003은 합성 지침 두 개로 실제 Gemini 답변을 시험할 수 있도록 별도 통신 어댑터와 합계 30회 제한을 추가함. 이 어댑터는 81ffe720 앱 소스 변경이 아닌 로컬 시험용이며 운영에 복사하지 않음. 3002는 실제 API 호출 없이 메모만 확인함. [실제 답변 시험 범위](01_작업일지/2026-10-11_시험환경_실제답변_30회제한.md).

## 반영 범위

- 1차 확인 주소: http://localhost:3003 (합성 자료 전용).
- 개인 메모 별도 확인 주소: http://localhost:3002. 이 기능 ce89927e는 1차에 포함하지 않음.
- 로컬 origin/main b5aa77bd와 비교한 81ffe720에는 Prisma schema·migration 변경이 없음. 미커밋 동의어 migration이나 개인 메모 migration을 끼워 넣지 않음.
- 운영 서버가 어떤 버전인지 먼저 확인해야 함. 현재 로컬 main은 ce89927e이므로 아무 생각 없이 최신 main을 받으면 1차만 반영하는 것이 아님.

## 사용자가 나중에 진행할 순서

1. **백업**: 점검 시간을 잡고 새 업로드·질문을 멈춘 뒤, 운영 서버의 현재 커밋과 작업공간 변경 목록을 기록함. 복원 가능한 VM 스냅샷과 DB·storage·Chroma 보관 상태를 확인함. 실행 중인 SQLite의 DB 파일 하나만 복사하면 WAL의 최근 내용이 빠질 수 있으므로 SQLite 온라인 백업 또는 관련 서비스를 정상 중지한 일관된 백업을 사용함. 백업 파일의 존재·크기뿐 아니라 복원 가능 여부도 확인함.
2. **반영할 코드 확보**: 별도 승인 후 GitHub에 1차 커밋이 있는지 확인함. 운영의 기존 변경·storage는 보존하며, 정확히 81ffe720을 반영하는 경로를 선택함. 단순 `git pull`로 ce89927e나 다른 미검증 코드까지 들어오게 하지 않음. 충돌 시 강제 덮어쓰기·reset·clean을 하지 않음.
3. **범위 검사**: 배포 전후 차이에서 `server/storage`, `.env`, DB 파일과 원본 자료 변경이 없는지 확인함. 운영 현재 커밋에서 81ffe720까지의 `server/prisma` 차이도 다시 확인함. 차이가 있으면 위의 ‘migration 없음’ 가정으로 진행하지 않음.
4. **빌드·반영**: 기존 배포 compose와 설정을 유지해 빌드·실행함. 이번 로컬 시험용 폴더·중계 컨테이너·계정·비밀번호는 운영에 복사하지 않음.
5. **확인**: 컨테이너 상태, 직원 로그인·질문·원본 보기·체크리스트·퀴즈, 관리자 동시답변 설정·답변 재사용·검색 조각 조회를 확인함. 문서 등록·삭제 후 이전 캐시가 재사용되지 않는지 합성 자료로 확인함. 1차에는 개인 메모 서버 저장이 없음을 구분함.
6. **빌드 캐시 정리**: 빌드 완료와 서비스 정상 확인 후 다른 빌드가 없는 때 아래만 실행함.
