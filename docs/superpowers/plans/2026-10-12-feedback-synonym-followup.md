# 동의어 실패 재시도와 직원 답변 평가 후속 작업

## 승인 범위와 공통 조건

2026-10-12 사용자 승인: 기존 C를 먼저 마무리한 후 싫어요와 직원 질문 기반 후보 찾기를 구현한다. 새 표는 schat_answer_feedback 하나만 추가하며 기존 표 변경·삭제는 하지 않는다. release-admin-8에서만 기능별 커밋한다. 전체 검사와 3001 백업·반영·확인 후 민감 파일 포함 여부를 점검하고 해당 갈래만 일반 push한다. 실제 Gemini는 질문 기반 후보 확인 1회 이내이며 자동 검사에서는 외부 호출을 막는다. 기존 미커밋 변경·자료를 보존한다.

## Task 1: 기존 C의 안전한 부분 재시도

- 과거 기록은 재시도 불가 안내. 새 기록부터 기존 실행 documents JSON에 문서 식별자·내용 지문·묶음별 성공/실패 범위와 성공 결과를 기록한다.
- 이미 성공한 묶음은 다시 호출하지 않는다. 현재 문서가 바뀌거나 삭제되면 재시도를 거절한다. 같은 실행의 중복 재시도는 막는다. 저장 실패 후 성공했다고 표시하지 않는다.
- 관리자만 전체 실패/특정 실패 범위를 재시도한다. 실제 호출은 시험 중 금지한다.
- 평상시 마지막 실행 한 줄과 접힌 기록. 실패 시 주황 요약과 펼친 실패 목록, 쉬운 이유, 과거 기록 안내. 내부 실행명 대신 날짜. 관리자 알림에도 실패를 표시한다.
- 가짜 부분 실패·중복 재시도·기록 저장 실패·문서 변경·권한 검사를 실행한다. 기존 업로드 자동 후보 연결을 유지한다. 테스트 후 C만 커밋.

## Task 2: 싫어요

- 새 schat_answer_feedback 표에 답변·사용자별 유일 평가, 이유, 가린 200자 메모, 처리 상태와 날짜를 저장한다. 기존 좋아요는 보존하고 평가 전환 시 feedbackScore와 한 transaction에서 변경한다. 직원 소유 대화만 수정 가능. 기존 표를 재생성하거나 기존 칸을 삭제하는 migration 금지.
- 직원 답변 버튼 순서 읽어 주기·복사·다시 답변·👍·👎. 다시 답변의 기존 마지막 답변 제한 등은 유지. 기존 관리자 작업 기능과 사용자 질문 수정은 유지.
- 👎를 누르면 답변 바로 아래 작은 창: 어떤 점이 아쉬웠나요? 필수 이유 [틀린 내용이 있어요] [원하는 내용을 못 찾았어요], 선택 한 줄 메모 200자, 주황 안내 환자 이름·등록번호는 적지 마세요, 취소/보내기. 성공하면 알려 주셔서 고마워요 잠깐 표시하고 닫음. 실패면 저장된 상태로 오인시키지 않음.
- 같은 답변에 한 사람은 👍/👎 하나만 선택. 이미 선택한 버튼은 취소. 전환하면 기존 이유/메모가 남아 잘못 집계되지 않음. 중복 전송 방지. 과거 좋아요도 유지.
- 관리자 문제 신고 기존 통계/FAQ 기능 보존. 목록에 종류 | 질문(메모 회색) | 부서 | 날짜 | 상태. 👎 틀림 빨강 / 👎 못 찾음 주황 / 신고 회색. 확인 전 / 처리 완료. 전체/틀림/못 찾음/신고/확인 전만 필터. 상세는 질문·답변 전체·참고 지침/쪽, 처리 완료. 기존 신고 상세와 처리/FAQ 연결 보존.
- 한글 2~4자+님/환자 등 이름 문맥과 8자리 이상 숫자를 서버에서 저장 전에 가림. 예 김민지님→김○지님, 12345678→1234****. 클라이언트 우회도 검사. 오류·로그·사용 통계에 메모 포함 금지.
- 못 찾음 평가는 Task3에서 읽을 수 있게 원본 대화 ID를 유지. 취소/이유변경은 다음 수집에 반영.
- 가짜 자료로 소유권·이유/길이 검증·가리기·평가 상호배타/취소·실패 롤백·목록 필터·상태 변경을 검사. 격리 DB에서 새 표만 추가되고 기존 schema/데이터가 그대로인지 검사. PC/휴대폰 화면 직접 클릭 검사는 최종 반영 때도 수행. 테스트 후 별도 커밋.

## Task 3: 직원 질문에서 후보 찾기

출처 없는 답변 및 못 찾음 평가를 중복 제거하여 수집한다. 가린 질문에서 두 번 이상 나온 말만 지침과 비교한다. 기존 후보·실행 기록·설정 저장소를 재사용한다. 새벽 하루 한 번, 일일 호출 상한 기본 20·0이면 끔, 재시작해도 사용량을 보존한다. 거절 후보 재등록 금지, 직원 질문 출처와 횟수 표시. 가짜 호출 상한·중복·개인정보 검증 후 별도 커밋.

- 하루 기준은 한국 날짜, 정기 실행은 새벽 3시. 같은 날짜 중복 실행과 재시작 후 호출 횟수 초기화를 막는다. 외부 요청 직전 횟수를 기존 설정에 먼저 저장하고 실패하면 호출하지 않는다. SDK 자동 재시도는 끈다. 관리자만 상한을 바꿀 수 있다.
- 질문마다 같은 표현은 한 번만 센다. 같은 대화가 검색 실패와 못 찾음 평가에 동시에 해당하면 한 번만 센다. 낯선 말이 서로 다른 질문에서 2번 이상 나온 경우만 검토한다.
- 서버에서 질문의 이름·긴 번호를 가리고, 짧은 표현과 관련 지침의 짧은 용어 줄만 전송한다. 질문 메모는 전송하지 않는다. 임의의 AI 응답·질문 원문을 로그에 남기지 않는다.
- AI가 고른 낯선 표현과 지침 용어가 실제 입력에 있는지 검사한다. 확실하지 않으면 후보를 버린다. 약물/용어 두 분류만 사용하고, 승인 전 검색에 적용하지 않는다.
- 기존 묶음에 더하는 후보와 새 묶음을 구분한다. 기존 제외·무시 기록은 보존하고 재제안하지 않는다. 출처는 후보마다 '직원 질문에서 · N회'와 가린 질문 예시 한 줄을 표시한다.
- 마지막 AI 후보 찾기 요약에 '직원 질문에서 N개'를 함께 표시한다. 관련 설정은 동의어 관리 안의 접힌 상세 영역에 둔다.
- 가짜 자료로 cap 0/20, 동시 실행/재시작, 2회 기준, 같은 대화 중복 제거, 제외 후보 재제안 차단, 개인정보 가리기, 새 묶음/추가 후보 표시를 검증한다. 기존 문서 후보 찾기 검사를 유지한다.
- 비용은 실제 호출 수와 기록된 사용량이 있을 때만 계산한다. 실측이 없으면 정확한 비용을 확정하지 않고 가정한 계산과 제외 범위를 구분한다.

## Task 4: 최종 검사와 반영

새 표만 추가하는 migration 검토 및 격리 DB 적용, 회귀 검사, 문서 갱신. 3001 DB/storage 일관된 백업 후 반영, PC/휴대폰 검사. 업로드 자동 후보 호출이 실제 Gemini 시험 제한을 넘지 않도록 가짜 자료는 격리 검사로 수행한다. 완료 후 갈래 전체 커밋·민감 파일 검사, release-admin-8만 push하고 원격 HEAD 일치 확인. 미완료 상태로 push하지 않는다.
