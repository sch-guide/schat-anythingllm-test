## 2. 정리 계획 제안

### 2-1. 추천 방식: "보이는 구조는 새로, 실제 이동은 최소로"

- 문서 도구·검사·규칙 문서 여러 곳이 `docs/00_현재상태`, `docs/01_작업일지`, `05_인수인계`, `04_화면디자인`, `docs_view` 경로를 직접 씁니다.
- 한꺼번에 옮기면 문서 화면 생성과 자동 검사가 깨집니다.
- 그래서 다음 순서로 하는 것을 제안합니다.
  1. 새 구조의 **새 문서**는 `docs/` 아래에 만듭니다(공식 정본 규칙 유지).
  2. 기존 문서는 이동 목록대로 옮기되, 옮길 때마다 **경로를 쓰는 도구·검사·링크를 같은 작업에서 함께 고칩니다.**
  3. VS Code 쉬운 화면(작업 공간 파일)은 새 구조 이름으로 바꿔 비개발자는 새 구조만 보게 합니다.

### 2-4. VS Code 쉬운 화면 의견

- **새 파일을 따로 만들기보다 기존 `SCHAT_테스트_쉬운화면.code-workspace`를 새 구조로 고치는 것을 추천합니다.**

- 비개발자가 코드 폴더를 실수로 건드리지 않게 하는 효과가 있습니다.
