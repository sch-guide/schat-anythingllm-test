# SCHAT 독립 검색 이식 설계

## 목표

이 테스트 저장소 안에서 기존 문서 등록·대화·로그인·도구 화면은 유지하면서, SCHAT 검색을 다음 구조로 고정한다.

`질문 → Gemini 임베딩 → ChromaDB 의미 검색 → BM25 용어 보완 → 근거 → AI 답변`

최종 실행은 원본 AnythingLLM 저장소나 별도의 AnythingLLM Docker 실행 여부에 의존하지 않는다. 이 저장소의 Docker 구성 하나로 웹 서버와 ChromaDB를 함께 실행한다.

## 저장소 경계

- 변경 허용: 현재 `schat-anythingllm-test` 저장소
- 변경 금지: 부모 `sch-guide-ai` 저장소와 다른 모든 저장소
- 외부 Gemini 실제 호출: 이번 구현·자동 테스트에서는 금지
- Git commit/tag/push: 수행하지 않음

## 검색 구조

### 1. Gemini 임베딩 고정

- 문서와 질문 모두 `gemini-embedding-2`를 사용한다.
- 설정이 없을 때 MiniLM으로 자동 대체하지 않는다.
- Gemini 키가 없으면 명확한 설정 오류로 중단한다.
- 기존 MiniLM 기반 문서 검색과 MiniLM 재정렬은 SCHAT 검색 경로에서 사용하지 않는다.

### 2. ChromaDB 주 검색

- 웹 서버와 ChromaDB를 같은 Docker Compose 구성에서 실행한다.
- 웹 서버는 `http://chroma:8000`으로 ChromaDB에 연결한다.
- 저장된 벡터는 Docker 볼륨에 보존한다.
- 거리 방식은 기존 Chroma 구현의 코사인 거리(`cosine`)를 유지한다.

### 3. BM25 보완

- BM25는 별도 문서 사본이 아니라 ChromaDB에 저장된 동일 문서 청크를 대상으로 계산한다.
- Gemini·Chroma 결과를 주 순위로 두고 BM25 결과에는 낮은 가중치를 준다.
- 점수 단위가 다른 두 결과는 원점수를 직접 더하지 않고 순위 기반 결합을 사용한다.
- 정확한 병원 용어가 포함된 청크가 의미 검색에서 밀리는 경우에만 BM25가 순위를 보완한다.
- 개별 질문을 위한 문자열 하드코딩은 하지 않는다.

## 사용자 화면과 로그인

- 실제 웹 화면의 서비스명은 `병원 실무지침 AI`와 `SCHAT`을 사용한다.
- 실제 웹 화면에 원래 제품명은 노출하지 않는다.
- 기존 로그인과 사용자 권한 로직은 재사용하되 로그인 화면은 직원용 문구를 사용한다.
- 라이선스와 원저작자 고지는 내부 파일에서 유지한다.

## 오류 처리

- Gemini 키가 없거나 잘못된 임베딩 엔진이 설정되면 MiniLM으로 대체하지 않고 중단한다.
- ChromaDB가 꺼져 있으면 검색 실패 원인을 표시한다.
- BM25 보완 계산이 실패해도 Chroma 결과가 정상이라면 Chroma 결과만 반환한다.
- 근거가 없으면 일반 지식으로 답하지 않는 기존 질의 모드를 유지한다.

## 검증 기준

- 검색 엔진 선택기는 Gemini 외 엔진을 허용하지 않는다.
- 벡터 저장소 선택기는 ChromaDB 외 엔진을 허용하지 않는다.
- BM25 보완기는 한글·영문·숫자 용어를 처리하고, 동일 입력에서 같은 순서를 반환한다.
- 검색 결합 결과는 Gemini·Chroma 결과를 우선하고 정확 용어 일치 결과를 보완한다.
- Docker Compose에 웹 서버와 ChromaDB가 모두 존재하고 데이터 볼륨이 선언된다.
- 테스트 중 외부 네트워크 호출은 0회다.
- `docs/`와 `docs_view/`를 함께 갱신한다.

## 제외 범위

- 부모 SCHAT Production 코드 변경
- 병원 원문 또는 API 키 저장
- 기존 Gold/fixture 변경
- 외부 Gemini 실호출
- 운영 배포와 도메인 연결
