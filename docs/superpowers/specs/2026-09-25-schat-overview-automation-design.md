# SCHAT 설명 화면 자동화 설계

## 목적

비개발자가 `docs_view/index.html` 하나만 열어 SCHAT의 목적, 동작 흐름, 주요 구성, 현재 상태, 안전장치, 인수인계 내용을 이해할 수 있게 한다. 설명은 저장소의 안전한 정적 정보와 공식 문서를 바탕으로 자동 생성한다.

## 화면 구조

1. SCHAT 한눈에 보기: 소개, 사용자, 핵심 기술
2. 어떻게 동작하나요?: 문서에서 답변까지의 흐름과 관리자·직원 사용 흐름
3. 프로젝트 구성: 주요 폴더만 우선 표시하고 상세는 펼침
4. 현재 상태와 안전장치: 완료·진행 중·예정, 실제 검사와 보호 장치
5. 변경 이력: 작업일지를 날짜·제목·짧은 설명으로 접어서 표시
6. 인수인계 안내: 실행, 문서 등록, 필수 검사, 변경 금지 대상, 문제 확인 순서를 HTML에서 충분히 제공

## 데이터 흐름

`실제 저장소와 docs` → `문서도구/SCHAT_개요데이터_만들기.py` → `docs_view/schat-overview-data.json` → `문서도구/문서화면_만들기.py` → `docs_view/index.html`

HTML에는 같은 JSON을 내장해 `file://`로 직접 열어도 별도 서버 없이 동작하게 한다. JSON 파일은 자동 생성 결과를 사람이 확인하거나 테스트할 수 있도록 별도로 보존한다.

## 자동으로 수집하는 정보

- allowlist에 포함된 최상위 폴더의 존재 여부와 쉬운 설명
- 코드와 예제 설정에서 확인된 답변 모델, embedding, vector DB, BM25, Docker 구성
- Compose 파일에 선언된 서비스 이름
- `검사`, frontend, server, collector, safety evaluator의 테스트 파일 수
- 현재 상태 문서의 완료·진행 중·예정 내용
- 날짜별 작업일지의 날짜, 제목, 첫 설명, 관련 기능
- 공식 인수인계 문서의 전체 내용

값을 확인할 수 없으면 `확인 필요`로 표시하고 추측하지 않는다.

## 자동 실행

- 기존 `문서도구/문서화면_만들기.py` 실행 시 JSON과 HTML을 함께 갱신한다.
- 기존 AGENTS 규칙에 따라 코드·설정·문서 작업을 마칠 때 생성기를 실행한다.
- frontend 개발/production build 전에 비차단 wrapper가 생성기를 실행한다.
- 저장소의 pre-commit hook은 관련 경로가 staged 되었을 때 생성기를 실행하고 생성물을 함께 stage한다.
- Python을 찾지 못하거나 생성에 실패하면 경고만 출력하고 앱 실행, build, commit을 막지 않는다.

## 보안 경계

- `.env` 파일은 읽지 않는다. `.env.example`에서도 승인된 비밀이 아닌 설정 이름과 모델 기본값만 제한적으로 읽는다.
- API key, password, token 형태의 키와 값은 결과에 포함하지 않는다.
- PDF와 등록 문서의 본문, ChromaDB 문서 내용, 진단 로그는 읽지 않는다.
- 내부 ID, Git hash, 긴 절대 경로는 기본 화면에 표시하지 않는다.
- SCHAT 검색, 답변, embedding, ChromaDB, BM25, 업로드와 사용자 기능은 변경하지 않는다.

## 검증

- 격리된 fixture 저장소로 데이터 수집, secret 제외, 설정 변경 반영을 테스트한다.
- 생성 HTML에 6개 섹션, 반응형 CSS, 접기/펼치기, 인수인계 내용과 변경 이력이 있는지 검사한다.
- 저장된 JSON·HTML이 fresh generation과 같은지 검사한다.
- 원래 설정 파일은 변경하지 않고 fixture의 모델 값을 바꿔 JSON 변경을 검증한다.
- 기존 문서 검사, production build, `git diff --check`를 실행한다.
