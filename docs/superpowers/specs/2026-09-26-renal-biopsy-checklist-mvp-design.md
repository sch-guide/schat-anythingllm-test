# Renal biopsy 체크리스트 MVP 설계

## 목적

관리자가 병원 PDF를 업로드하면 SCHAT이 체크리스트형 페이지를 보수적으로 감지하고, PDF 원문에서 확인되는 제목과 내용만 구조화해 즉시 사용할 수 있는 체크리스트로 저장한다. 관리자는 승인 절차 없이 필요할 때만 체크리스트 정의를 수정하며, 직원은 Renal biopsy 관련 질문의 답변 아래에서 체크리스트를 열어 사용할 수 있다.

이번 MVP는 현재 등록된 `검사 및 시술(26.04.07).pdf`의 Renal biopsy 페이지인 실제 PDF p.56 하나만 end-to-end로 지원한다. 저장·API·UI 구조는 이후 다른 검사·시술·수술 체크리스트를 같은 형식으로 추가할 수 있게 공통화한다.

## 변경하지 않는 영역

- Automatic 및 AgentHandler 답변 생성
- rag-memory와 검색 순위
- ChromaDB, BM25, embedding 및 본문 벡터
- Gemini prompt와 호출 횟수
- Citation, 원본 PDF 보존, pdfRef 및 PDF viewer
- image_description 및 관련 이미지 기능
- 기존 로그인과 workspace 권한 구조
- PDF의 기존 처리·색인 결과

체크리스트 추출 실패는 PDF 업로드·처리·색인의 성공 여부에 영향을 주지 않는다.

## 전체 흐름

### 새 PDF

1. 관리자가 기존 관리자 화면에서 PDF를 업로드한다.
2. 기존 Collector가 PDF를 페이지 JSON으로 처리한다.
3. 기존 업로드 로직은 그대로 문서 등록과 색인을 수행한다.
4. 별도 체크리스트 processor가 처리된 페이지 텍스트를 검사한다.
5. Renal biopsy 체크리스트 구조가 엄격한 조건으로 확인되면 파일 저장소에 즉시 `active` 상태로 저장한다.
6. 추출 오류나 후보 없음은 기록만 하며 업로드 결과를 실패로 바꾸지 않는다.
7. 해당 문서가 workspace에 등록되면 직원과 권한 있는 관리자가 체크리스트를 조회할 수 있다.

### 현재 등록된 Renal biopsy 문서

현재 ChromaDB에 보존된 동일 SourceUnit 텍스트를 읽기 전용으로 한 번 사용해 같은 extractor를 실행한다. 체크리스트 JSON만 생성하며 기존 Chroma 레코드, BM25 자료, 본문 벡터 및 workspace_documents를 수정하지 않는다. 이 동작은 idempotent한 유지보수 명령으로 제공한다.

### 직원 질문

1. 현재 workspace의 active 체크리스트 정의를 한 번 조회한다.
2. 사용자 원문 질문을 정규화한 뒤 등록된 alias와 비교한다.
3. alias가 포함된 경우에만 Automatic 답변 아래에 체크리스트 버튼을 표시한다.
4. 버튼을 누르면 modal에서 체크리스트를 표시한다.
5. modal의 체크 상태는 해당 React 화면이 유지되는 동안만 메모리에 보존한다.
6. 체크 상태는 DB나 서버 파일에 저장하지 않는다.

## 저장 구조

체크리스트 정의는 기존 Docker storage volume 아래의 전용 디렉터리에 JSON 파일로 저장한다.

```text
server/storage/document-checklists/<opaque-storage-key>.json
```

파일명은 내부 `document_id`를 그대로 사용하지 않고 HMAC 또는 SHA-256 기반의 안정적인 storage key를 사용한다. JSON 내부에는 서버 연결에 필요한 `documentId`를 보존하지만 공개 API 응답에서는 제거한다.

```json
{
  "version": 1,
  "id": "공개용 opaque checklist id",
  "documentId": "서버 내부 전용 document id",
  "title": "Renal biopsy 체크리스트",
  "aliases": [
    "renal biopsy",
    "renal bx",
    "신장 조직검사",
    "신생검"
  ],
  "sections": [
    {
      "id": "안정적인 section id",
      "title": "검사 전",
      "items": [
        {
          "id": "안정적인 item id",
          "type": "informational",
          "label": "검사목적",
          "details": ["PDF 원문에서 확인된 설명"]
        },
        {
          "id": "안정적인 item id",
          "type": "checkable",
          "label": "동의서",
          "details": [
            "① PDF 원문의 첫 번째 세부 내용",
            "② PDF 원문의 두 번째 세부 내용"
          ]
        }
      ]
    }
  ],
  "source": {
    "filename": "검사 및 시술(26.04.07).pdf",
    "page": 56
  },
  "status": "active",
  "autoGenerated": true,
  "editedByAdmin": false,
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601"
}
```

저장은 임시 파일 작성 후 rename하는 방식으로 원자적으로 처리한다. 같은 document/page/checklist 조합은 같은 파일을 갱신하므로 중복 저장하지 않는다. 관리자 편집 후에는 자동 추출이 기존 수정을 덮어쓰지 않는다.

## 감지와 추출

### 후보 감지

모든 PDF를 체크리스트로 만들지 않는다. Renal biopsy MVP 후보는 한 페이지 안에서 다음 조건을 모두 만족해야 한다.

- 제목 영역에서 `신장조직검사` 또는 `Renal biopsy`가 원문으로 확인됨
- `검사 전`과 `검사 후` 구획이 모두 원문으로 확인됨
- 각 구획 안에 복수의 짧은 행 제목과 뒤따르는 내용이 존재함
- 체크리스트형 확인 항목이 최소 기준 이상 존재함

세로로 쪼개진 `검\n사\n전` 같은 추출 결과는 탐색을 위한 정규화에서만 결합한다. 저장되는 label과 details는 원문에서 대응되는 실제 문자열을 사용한다.

### 구조 추출

- 제목부터 `검사 전`, `검사 후` 구획 경계를 찾는다.
- 구획 안에서 짧은 행 제목과 다음 행 제목 전까지의 세부 내용을 하나의 항목으로 묶는다.
- ①·② 같은 번호 세부 내용은 `details`에 유지하고 별도 item으로 분리하지 않는다.
- 출력하는 모든 label과 detail은 원문 페이지에 존재하는지 검증한다.
- 검증되지 않는 문자열이 하나라도 있으면 그 문자열은 저장하지 않는다.
- 필수 구획이나 충분한 행을 복원할 수 없으면 해당 페이지의 자동 생성을 중단한다.

### 항목 유형 판정

판정은 일반 의학지식이나 Gemini를 사용하지 않고 원문의 행 제목과 구획만 사용한다.

- `informational`: 제목이 목적, 정의, 설명, 참고 성격을 명시함
- `checkable`: 제목이 확인, 준비, 수행, 관찰, 검사 결과 확인 성격을 명시함
- 모호함: checkbox를 만들지 않고 `informational`로 처리하거나, 구조 자체가 불명확하면 항목에서 제외

Renal biopsy MVP의 강제 계약은 다음과 같다.

- `검사목적`: `informational`
- `동의서`: `checkable`; ①·②는 같은 항목의 details
- `금식여부`: `checkable`
- `IV line`: `checkable`
- `검사 전 준비`: `checkable`
- `Prepare`: `checkable`
- 검사 후 식이·자세·X-ray 및 Lab·관찰사항: 원문 구획에서 확인 가능한 확인/수행 항목으로 `checkable`

이 계약은 체크리스트 내용을 만들어내는 값이 아니라 원문 행의 성격을 분류하는 보수적인 규칙이다. 원문에 해당 행이 없으면 item도 만들지 않는다.

## 서버 경계와 API

체크리스트 모듈은 다음 책임으로 나눈다.

- `extractor`: 페이지 원문에서 후보 감지, 구획/항목 추출, 원문 포함 검증
- `repository`: 전용 JSON 파일의 원자적 생성·조회·수정
- `public presenter`: 내부 documentId를 제거하고 pdfRef를 파생해 공개 shape 생성
- `workspace authorization`: 기존 workspace_documents의 document_id 연결을 사용해 접근 권한 확인

API는 기존 workspace endpoint에 최소 범위로 추가한다.

- `GET /workspace/:slug/checklists`
  - workspace 접근 권한이 있는 사용자에게 active 체크리스트 공개 데이터 반환
  - 직원 질문 alias matching과 modal 표시에 사용
- `PUT /workspace/:slug/checklists/:checklistId`
  - 기존 관리자/manager 권한 사용
  - title, aliases, section title, item label/details/type/order의 편집 결과 저장
  - PDF, ChromaDB, BM25 및 벡터에 접근하지 않음

공개 응답에는 checklist id, title, aliases, sections, filename, page, pdfRef만 포함한다. documentId, storage path, metadata 원문은 포함하지 않는다.

## 관리자 화면

기존 PDF 부모 행에 해당 문서의 체크리스트가 있을 때만 다음 상태와 동작을 추가한다.

- `체크리스트 자동 생성됨`
- `보기`: 직원과 같은 read-only modal
- `수정`: 제목·section 제목·항목 문구·유형·순서·추가·삭제를 편집하는 modal
- `원본 보기 p.56`: 기존 pdfRef와 PDF viewer를 재사용

승인 버튼과 필수 검수 단계는 만들지 않는다. 저장하면 checklist JSON만 변경하고 `editedByAdmin: true`로 기록한다. 자동 processor는 이 파일을 재생성하거나 덮어쓰지 않는다.

## 직원 화면

채팅 기록의 각 assistant 응답과 그 직전 사용자 질문을 연결한다. 질문을 NFKC, 소문자, 공백·구두점 정리 방식으로 정규화하고 alias를 비교한다.

- 일치: 답변 아래, Citation 위에 `[Renal biopsy 체크리스트 보기]` 표시
- 불일치: 체크리스트 UI를 전혀 렌더링하지 않음
- `수혈 절차 알려줘`: 버튼 없음

modal은 기존 공용 Modal 구조를 재사용한다.

- 중앙 표시와 overlay
- X 버튼 및 하단 닫기 버튼
- ESC 닫기
- desktop max-width 640px
- mobile 좌우 16px
- 긴 내용 내부 스크롤
- light/dark mode 지원
- 모든 section 기본 펼침
- section별 독립 접기/펼치기
- `informational`: label과 details만 표시
- `checkable`: label 앞에 실제 checkbox, details는 아래 일반 텍스트

체크 상태는 modal launcher 컴포넌트의 React state에 보존해 닫았다 다시 열어도 유지한다. 페이지 새로고침, 다른 브라우저, 다른 직원 또는 환자 단위로 저장하지 않는다.

## 오류 처리

- extractor 예외: 경고 로그만 남기고 기존 PDF 처리 결과 반환
- 후보 없음: 정상적인 `체크리스트 없음` 상태
- 파일 저장 실패: PDF 업로드·색인은 성공, 관리자 UI에는 체크리스트 없음
- 잘못된 JSON: 해당 파일만 무시하고 다른 체크리스트 조회 계속
- 권한 없는 조회/수정: 기존 workspace 권한 응답 사용
- 존재하지 않는 checklist id: 안전한 404
- PDF 원본 없음: 체크리스트는 표시하되 원본 보기만 기존 viewer 오류/fallback 사용

## 테스트 전략

### Extractor 계약

- 실제 Renal biopsy p.56 형태의 fixture에서 검사 전·검사 후 추출
- 검사목적은 informational이며 checkbox 대상이 아님
- 동의서·금식여부·IV line·검사 전 준비는 checkable
- 동의서의 ①·②는 details이며 별도 item이 아님
- 추출 결과의 모든 label/details가 fixture 원문에 존재
- 체크리스트 구조가 아닌 페이지는 생성하지 않음
- 추출 실패가 업로드 성공을 바꾸지 않음

### Repository와 API

- 자동 생성 즉시 active 저장
- 동일 document/page 재처리 시 중복 없음
- 관리자 편집 후 editedByAdmin true
- 관리자 편집 전후 Chroma/BM25/본문 벡터 호출 없음
- workspace 권한 없는 접근 차단
- 공개 응답에 documentId와 내부 경로 없음
- pdfRef와 p.56 연결

### 직원 UI

- `Renal biopsy 준비 알려줘` 버튼 표시
- `신생검 검사 후 간호 알려줘` 버튼 표시
- `수혈 절차 알려줘` 버튼 미표시
- informational 항목에 checkbox 없음
- checkable 항목에 checkbox 있음
- modal 열기·닫기, ESC, section 접기·펼치기
- 닫고 다시 열었을 때 같은 화면의 체크 상태 유지
- 새로고침 영구 저장 기능 없음
- mobile 및 dark mode class 계약

### 관리자 UI

- 체크리스트가 있는 PDF에만 상태와 보기·수정·원본 보기 표시
- 항목 편집·순서 변경·추가·삭제 저장
- 원본 보기에서 기존 PDF p.56 viewer 사용
- 승인 단계 없음

### 회귀 검증

- 기존 Citation/PDF viewer 테스트
- 관련 frontend/server 테스트
- production build
- Docker 서비스 health
- 본문 벡터 개수와 snapshot 불변 확인
- `git diff --check`
- 문서 자동 갱신과 분리 검사

## 보안 및 개인정보

- API key, 환자정보, 병원 PDF 원문 전체를 로그나 문서에 저장하지 않는다.
- 공개 API는 checklist에 필요한 항목과 원본 표시용 공개 pdfRef만 반환한다.
- 내부 documentId, 파일 경로 및 metadata 원문은 직원 화면에 노출하지 않는다.
- 체크리스트 정의는 병원 문서와 동일한 workspace 권한으로만 조회한다.

## 완료 기준

- Renal biopsy p.56에서 원문 기반 체크리스트가 자동 생성되고 즉시 active 상태임
- 검사목적은 설명형, 실제 확인·수행 행만 checkbox임
- 원문에 없는 항목과 세부 내용이 하나도 없음
- 관리자 승인 없이 직원 질문에서 사용 가능함
- 관리자는 checklist JSON만 수정하며 재색인이 발생하지 않음
- alias 일치 질문에만 버튼이 표시됨
- 기존 검색·답변·출처·원본 PDF 기능과 벡터가 변하지 않음
