## 3. 원문 구조에서 확인된 위험

1. **줄바꿈 = 항목 경계가 아님.** 추출 원문은 PDF 줄 단위로 끊겨 있어 한 문장이 두 줄로 나뉜다. 줄마다 체크박스를 만들면 한 문장이 두 개의 체크 항목이 되는 과잉 분할이 생긴다.
2. **경우별 분기.** EBUS 등은 `<C-EBUS인 경우>`처럼 조건별로 서로 다른 동의서 목록을 가진다. 한 목록으로 합치면 분기가 섞인다.
3. **부연·주의문.** `※…`, `(…따라 다름)` 같은 설명 줄은 수행 항목이 아니다.
4. **항목 ID 충돌.** 기존 항목 ID는 `섹션명+행이름`으로만 만들어져, 체크리스트가 여러 개가 되면 모든 `동의서` 항목 ID가 같아진다.
5. **짧은 약어 오탐.** 현재 alias 매칭은 부분 문자열 방식이라 `CT`, `PFT`, `EVL` 같은 약어가 다른 단어 속에서 잘못 걸릴 수 있다.
6. **같은 검사 여러 쪽.** 요추천자(성인/소아), 흉수천자(장소별), 전립선생검(교수별), PEG(장소별), 케모포트(수술실/RA협진)는 제목의 구분 표기(`:병동`, `(소아)` 등)가 달라 한 질문에 여러 체크리스트가 함께 매칭될 수 있다.

## 4. 설계안

### 4.1 추출 엔진 일반화 (server/utils/documentChecklists)

- Renal biopsy 전용 `SECTION_DEFINITIONS`를 **표준 양식 정의 1개**로 일반화한다. 행 이름 목록과 순서는 이 PDF 양식에서 확인된 11개를 그대로 사용한다.
- 페이지 판정: 세로 구획 표기(`검/사/전`, `검/사/후`)가 있고, 11개 행 이름이 원문에 순서대로 모두 있고, 분기 표기가 없을 때만 자동 생성한다. 하나라도 어긋나면 생성하지 않는다(C로 남김).
- 항목 분류는 Renal biopsy와 동일하다. 검사목적·검사장소/이동수단은 정보성, 나머지는 checkable이다.
- **세부 줄 분리(승인 필요)**
  - 권장안: 저장된 원본 PDF의 글자 좌표(pdf.js)로 표 셀 폭을 확인한다. 줄이 셀 오른쪽 끝까지 차서 다음 줄로 넘어간 경우는 한 줄로 합치고, ①②… 번호가 있으면 번호 단위로 나눈다.
  - 대안: 기존 Renal biopsy처럼 추출 원문 줄 단위로 나눈다. 구현은 단순하지만 과잉 분할이 생긴다.
- `※` 줄과 괄호로만 된 부연 줄은 체크박스 없는 설명 줄로 둔다. 이를 위해 항목 detail에 설명 줄 표시값을 추가한다(기존 필드는 유지).
- ID: 새 체크리스트의 항목 ID에는 체크리스트 ID를 포함한다. Renal biopsy JSON은 다시 만들지 않으며 ID도 그대로 둔다.
- 제목·alias: 원문 제목 줄에서만 만든다. 한글명, 영문명, 원문 약어를 쓰고, 제목의 구분 표기(`:병동` 등)는 제목에만 남긴다. Renal biopsy alias는 변경하지 않는다.
- 자동 검증: 모든 label·detail이 해당 페이지 원문(공백 무시)에 존재하는지, 중복 항목이 없는지, page 연결이 맞는지 확인한다. 실패하면 `status: needs_review`, `active: false`로 저장해 직원 화면에 노출하지 않는다.
- 일괄 처리: 기존 `processDocumentChecklists`를 재사용해 20쪽 단위로 처리하고, 한 쪽의 실패가 전체를 멈추지 않게 한다. 배치별 생성·제외·오류·검증 결과를 `server/storage/schat-diagnostics/`에 원문 없이 기록한다.
- 기존 등록 문서 적용: 기존 backfill 스크립트를 일반화해 재색인 없이 checklist JSON만 만든다.

### 4.2 직원 화면

- 버튼 문구를 `{체크리스트 제목} 체크리스트 보기`로 일반화한다.
- alias 매칭: 영문 약어는 단어 경계로만 인정하고, 한글명은 기존처럼 포함 여부로 판단한다.
- 체크리스트별 상태 분리: 위치·크기·최소화·체크·접힘 상태를 체크리스트 ID별로 따로 보관한다.
- 여러 개 동시 열기(구현 가능 판단): 열린 체크리스트 ID 목록을 두고 panel을 하나씩 띄운다. 새 panel은 조금씩 비껴서 열고, 클릭한 panel이 맨 위로 온다. 별도 창은 이미 체크리스트별 창 이름을 쓰므로 그대로 분리된다.

### 4.3 관리자 화면

- 기존 보기·수정·원본 보기 버튼을 문서 행 아래 체크리스트 목록 전체로 확장한다. `needs_review` 상태는 표시만 하고 승인 버튼은 두지 않는다.

### 4.4 변경하지 않는 것

Automatic, AgentHandler, rag-memory, Gemini, BM25, ChromaDB, Citation과 필터링, PDF viewer, 원본 PDF API, 본문 벡터, 검색 ranking, 로그인·권한, Renal biopsy checklist JSON 내용.

## 5. 승인이 필요한 결정

1. 세부 줄 분리 방식: 권장안(원본 PDF 좌표로 줄바꿈 병합) 또는 대안(추출 원문 줄 단위).
2. 1차 생성 범위: A 63쪽만 먼저 생성하고 C 15쪽은 보류해도 되는지.

4. `※`·괄호 부연 줄을 체크박스 없는 설명 줄로 두는 규칙.
5. 여러 checklist 동시 열기를 이번에 함께 구현할지(권장: 함께 구현).
