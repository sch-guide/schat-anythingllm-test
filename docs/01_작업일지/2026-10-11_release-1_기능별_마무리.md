# release-1 기능별 마무리

## 승인된 순서와 보호 범위

완료된 미커밋 네 기능 → Gemini 예산 → 출처 후속 → 동의어 후보 → 새 대화 첫 질문 캐시 → 문서 업데이트 순서로 검사하고 각각 커밋함. 전체 완료 전 release-1 준비 완료로 표시하지 않음.

3001·3002·3003 재시작, push, 운영 반영을 하지 않음. preview-storage·시험 PDF·계정·DB·stash·upstream 변경은 커밋 대상에서 제외함. 실제 Gemini 호출은 이번 작업에서 0회이며 기존 누적 횟수를 초기화하지 않음.

## 다음 작업

### 6단계 추가 진행 — 삭제·초기화 API 연결

- 실제 `DELETE /workspace/:slug` 및 `DELETE /workspace/:slug/reset-vector-db`의 권한·작업공간 확인 이후, 어떤 DB 삭제보다 먼저 작업공간 전용 잠금을 취득하도록 연결함. 기존 삭제 순서 자체는 유지함.
- 같은 작업공간에 문서 작업 표식이 있으면 HTTP 423과 “이 문서는 지금 업데이트 중입니다. 잠시 후 다시 시도해 주세요.”를 반환함. 다른 부서의 잠금은 이 처리와 별개임.
- 실제 등록된 API 처리 함수를 호출하는 합성 검사에서 수정 전에는 200으로 삭제가 진행되는 실패를 확인함. 수정 후에는 삭제 부작용 0개·423 응답, 표식 해제 후 정상 처리임을 확인함. DB·Vector는 가짜 장치이며 운영 데이터 삭제 시험은 하지 않음.
- 일반 실패 후 초기화 잠금이 해제되어 재시도가 가능한 검사도 추가함. 기초 및 API 선별 검사 9개 통과함.
- 중요: 현재 교체 서비스는 아직 전역 잠금을 사용하며 작업공간 표식 연결이 남아 있음. 이번 API 변경만으로 교체 중 삭제 방지가 전체 완성됐다고 판단하지 않음. 일반 업로드·삭제 파일명 조회 연결, 교체 서비스 표식 수명 관리, 실패·재시작 journal 복구가 다음 작업임.
- 기존 변경은 보존하고 readiness=false 유지함. 이번 변경 미커밋, 실제 API 호출·기존 서버 재시작·push 없음.

### 6단계 이어서 진행 — 범위별 충돌 보호 기초

- 기존 `service.js`가 아직 전역 잠금을 취득하고 Chroma·문서 모델 등도 전역 읽기 보호를 쓰는 것을 확인함. 범위별 잠금 기능이 있다는 것만으로 실제 다른 문서 작업이 보장되는 상태는 아님.
- `scopes.js`에 문서 이름·작업공간 식별 규칙과 일반 문서 작업/작업공간 초기화 보호의 공통 처리를 추가함. 같은 이름은 폴더·확장자 대소문자·한글 조합 차이를 맞춰 같은 보호 대상으로 취급함. 경로 우회 입력은 거절함.
- 새 격리 파일 잠금 검사 3개 통과함: 같은 문서만 충돌, 같은 부서의 다른 문서 허용, 작업 중인 부서 초기화 거절 및 다른 부서 허용, 실패한 일반 작업 표식 해제임.
- 아직 실제 경로에 연결하지 않음. 교체 실패 복구는 단순 finally 잠금 해제로 처리하면 안 되므로, 교체 서비스에는 이 초기화 도우미를 그대로 사용하지 않음. 교체 journal 검증과 잠금 유지/해제를 함께 연결해야 함.
- 다음: 일반 업로드에서 파일명을 알 수 있는 시점·삭제에서 문서명을 조회하는 시점·작업공간 초기화 진입점을 각각 연결 → 교체 서비스의 문서별 잠금 및 작업공간 생존 보호 → journal 기반 재시작 복구 → 실제 격리 Collector/Chroma 검사 순서임.
- `DOCUMENT_UPDATE_READY=false` 유지, 이번 기초 변경은 미커밋임. 기존 서버 재시작·실제 API 호출·push·운영 데이터 변경 없음. 6단계 완료로 판정하지 않음.

- 수정 후 관련 검사 36개와 실제 Prisma 임시 DB 프로세스 재시작 검사 1개가 통과함. 실제 Gemini 호출 0회, 기존 3001·3002·3003 변경·재시작 없음.
- 관리자 실제 클릭 시험을 위해 브라우저 연결 상태 조회를 시도했으나 도구가 시간 초과되어 수행하지 못함. 정적 화면 렌더링 검사 통과를 실제 브라우저 검증으로 기록하지 않음.
- 2단계는 아직 커밋하지 않음. 다음은 별도 격리 관리자 화면에서 예산 저장·새로고침·80/95%·계산 불가 동작 확인, 격리 빌드, 예산 관련 변경만 분리 검토 후 커밋임. 그 뒤 3단계 출처 후속으로 진행함.

1단계 네 기능의 커밋을 마침. 관련 자동 검사 51개, 문서 생성 후 분리 검사 11개 통과함. 문서 생성기의 기존 invalid escape sequence 경고는 남아 있음. 현재 작업 문서·생성 화면은 다른 미완성 기능 설명도 포함하므로 일괄 stage하지 않고 남겨 둠.

다음은 2단계 Gemini 예산의 관리자 화면·격리 재시작 후 유지 검증부터 진행함. 2~6단계는 아직 완료하지 않음. 문서 업데이트 준비 차단은 그대로 유지함. 이번 통과 결과는 작업 코드의 선별 검사이며 전체 앱 격리 빌드·운영 배포 검증을 대신하지 않음.
