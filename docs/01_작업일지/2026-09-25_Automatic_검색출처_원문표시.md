# Automatic 실제 검색 출처 표시

## 무엇을 바꿨나

- 직원 workspace의 Automatic·AgentHandler 자유형 답변 방식은 그대로 유지했습니다.
- Agent가 실제 `rag-memory`로 검색한 병원 문서만 답변 아래 출처로 저장합니다.
- 한 답변에서 검색이 여러 번 실행되면 출처를 누적하되 같은 근거는 한 번만 표시합니다.
- 각 출처의 `근거 원문 보기`를 펼치면 실제 검색 source에 붙어 있던 원문을 보여줍니다.
- 실제 검색 source가 이미지 설명 근거인 경우에만 해당 원문 이미지를 출처 안에 표시합니다.

## 잘못된 원문 연결 방지

- 검색 본문 배열과 출처 배열이 같은 순서일 것이라고 추정하지 않습니다.
- 각 source 자체에 이미 연결된 text를 원문으로 사용합니다.
- 중복 제거에는 서버 내부의 안정적인 식별값을 쓰지만 직원 화면에는 내부 ID, vector ID, 저장 경로와 metadata 전체를 보내지 않습니다.

## 이미지 제한

- 단일 `image_key`로 직접 연결된 `image_description` source만 사용합니다.
- 같은 페이지의 전체 이미지 목록은 사용하지 않습니다.
- 로고·장식 이미지를 제외하고 같은 이미지를 중복 표시하지 않으며 출처별 최대 3개로 제한합니다.
- 이미지가 없는 출처는 기존처럼 원문만 표시합니다.
- Query 답변에서 사용하던 별도 관련 이미지 영역은 그대로 보존했습니다.

## 확인 결과

- 서버 회귀 검사 21개와 화면 회귀 검사 11개가 통과했습니다.
- production frontend build가 성공했습니다.
- Docker의 SCHAT 웹, ChromaDB, 안전검사 서비스가 모두 healthy였습니다.
- 설명 화면 자동 생성기가 검사 파일 수를 셀 때 `node_modules` 폴더 안으로 들어가지 않도록 해 자동 갱신이 불필요하게 오래 걸리는 문제를 막았습니다.
- 실제 Automatic 경로의 다섯 질문에서 답변 내용은 자유형으로 생성됐고 실제 검색 출처가 저장됐습니다.
- 직접 이미지 설명 근거가 검색된 질문에는 이미지 1개가 연결됐고, NRS 출처에는 FPRS 이미지나 로고·장식 이미지가 연결되지 않았습니다.

## 변경하지 않은 것

- Gemini prompt와 Automatic 답변 생성 방식
- Query 모드의 structured response와 관련 이미지 기능
- ChromaDB, BM25, Embedding, 재색인과 검색 순위
- Python 안전검사 Gate 설정
