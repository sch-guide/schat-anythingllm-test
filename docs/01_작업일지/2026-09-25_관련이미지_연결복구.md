# 관련 이미지 연결 복구

## 원인

- 검색에서는 관련 `image_description` 보조 벡터가 선택되고 있었습니다.
- 하지만 Gemini가 최종 답변에서 텍스트 SourceUnit만 인용하면 서버가 이미지 설명 SourceUnit을 관련 이미지 후보에서 제외했습니다.
- 그 결과 같은 질문에서도 답변 근거는 정상인데 관련 이미지가 0개로 저장될 수 있었습니다.

## 무엇을 바꿨나

- Gemini가 직접 인용한 이미지 설명은 가장 먼저 관련 이미지 후보에 넣습니다.
- Gemini가 텍스트 근거만 인용해도 검색과 질문 초점 필터를 통과한 이미지 설명을 검색 순서대로 이어서 넣습니다.
- 동일 `image_key`는 중복 제거하고 기존 화면 계약대로 최대 3장만 공개합니다.
- 후속 실제 확인에서 이미지 설명이 본문 top-N 이전 단계에서 탈락하면 위 연결만으로는 부족한 것을 확인했습니다.
- 이에 본문 근거 선택 결과와 별개로 질문 초점 검사를 통과한 `image_description` 후보를 최대 3개 보존해 `relatedImages`로 전달하도록 검색 응답 경로를 보완했습니다.
- 이 별도 후보는 Gemini 프롬프트와 직원 출처 목록에는 추가하지 않으므로 기존 본문 근거 수와 순위를 바꾸지 않습니다.

## 유지한 안전 기준

- 단순히 같은 페이지에 있다는 이유로 `related_image_keys` 전체를 표시하지 않습니다.
- NRS/FPRS 질문 초점 필터, 검색 순위, ChromaDB, BM25, Embedding과 기존 색인은 변경하지 않았습니다.
- 내부 파일 경로, 문서 ID와 vector ID는 공개하지 않습니다.
- 관련 이미지가 없으면 이미지 영역을 표시하지 않습니다.

## 확인 결과

- 일반 답변·절차 답변·직접 사용 이미지 우선·중복 제거·최대 3장 회귀검사를 추가했습니다.
- SCHAT 안전 답변 영역 회귀검사 48건이 모두 통과했습니다.
- Chroma/BM25 정책 및 검색 회귀검사 64건이 모두 통과했습니다.
- 화면의 중복 제거·최대 3장·관련성 미검증 이미지 숨김 검사 3건이 모두 통과했습니다.
- production Docker 이미지를 다시 만들고 SCHAT 웹, ChromaDB, 안전검사 컨테이너가 모두 healthy인 것을 확인했습니다.
- 실행 중인 SCHAT 웹 컨테이너에서도 관련 이미지 연결 검사 3건이 모두 통과했습니다.
- 후속 수정 후 SCHAT 답변 회귀검사 49건과 Chroma/BM25 회귀검사 66건이 모두 통과했습니다.
- 현재 717개 벡터를 사용한 API 비호출 점검에서 `NRS`, `NRS 통증척도는 어떻게 평가해?`, `통증 점수 설명`, `통증 점수 알려줘`, `FPRS` 모두 관련 이미지 후보가 생성됐습니다. NRS 질문에는 실제 NRS가 선택된 화면만 남고 FPRS 선택 화면은 제외됐습니다.
- 실제 Gemini 호출과 재색인은 실행하지 않았습니다.

- Git commit, tag, push는 실행하지 않았습니다.
