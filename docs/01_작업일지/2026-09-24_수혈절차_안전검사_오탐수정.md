# 수혈 절차 안전검사 오탐 수정

## 어떤 문제였나요?

수혈 절차 후보의 임상 의미와 `즉시` 강도는 근거와 같았습니다. 하지만 근거의 대상 목록에 있던 쉼표가 후보에서 `와`로 바뀌면서, 기존 검사기가 `즉시`의 적용 범위를 다르게 나눠 행위 강도 변경으로 오판했습니다.

## 무엇을 바꿘나요?

- 쉼표 자체를 무조건 행위 경계로 사용하지 않습니다.
- 같은 동사 연결 구간에서 쉼표 양쪽에 실제 행위가 모두 있을 때만 별도 행위 구문으로 나눕니다.
- 대상 목록의 쉼표가 `와`, `및`, `그리고`로 바뀌는 경우는 같은 행위와 강도로 인식합니다.
- `확인 후 서명`처럼 완료된 선행 행위를 단순 시간 명사로 제외하지 않습니다. `투여 전 상태 확인`처럼 아직 수행되지 않은 행위를 새 지시로 오인하지 않는 보호는 유지했습니다.

## 안전 기준을 낮췄나요?

아닙니다. 다음 실제 변경은 계속 차단합니다.

- `즉시 중단` → `중단 고려`
- `반드시 시행` → `권고`
- `금지` → `주의`
- `시행` → `확인`
- `중단` → `즉시 중단`

검색, 생성 Prompt, ChromaDB, 재시도 0회 정책은 바꾸지 않았습니다.

## 어떻게 확인했나요?

- 행위·강도 검사 집중 회귀 검사: 22개 통과
- 관련 상위 제어 생성 검사: 54개 통과
- 기능 비교 저장소 Python 안전검사: 51개 통과
- Ruff: 통과
- 저장된 수혈 절차 근거 6개와 후보 6문장 로컬 재생: `PASS`, 재시도 0회

실제 Gemini는 호출하지 않았습니다. 전체 상위 pytest는 1,046개 통과, 2개 건너뜀, 5개 실패였습니다. 실패 중 4개는 기존 평가 산출물 읽기 권한 문제였고, 1개는 기존 운영 UAT의 현재 31/36건과 문서의 36/36건 기대치 차이였습니다. 이번 action/strength 변경과 직접 관련된 검사는 모두 통과했습니다.
