# 체크리스트 별도 창 로그아웃 후 PC 저장

## 승인 범위

- 이미 열어 둔 별도 창은 로그아웃 후에도 체크·가린 환자정보·자유 메모를 유지함. 같은 PC의 같은 브라우저를 쓰는 다음 사람이 볼 수 있음을 사용자가 승인함.
- 로그아웃 후 서버 저장·조회·자동 병합을 중단함. 나중에 로그인해도 해당 PC 저장본을 서버로 옮기지 않음.
- 마지막 내용 수정 후 24시간 보관함. 조회·새로고침·같은 값 입력만으로 기한을 늘리지 않음.
- 창 상단에 `로그아웃됨 · 이 PC에만 저장` 표시함. 기존 입력 칸과 이름 가리기를 유지함.
- 작은 체크리스트 창의 로그아웃 삭제와 서버 개인 자료 보관 규칙은 변경하지 않음.

## 구현

- 별도 창 전용 브라우저 저장 계층을 기존 서버 세션과 분리함. 복원용 체크리스트 양식도 보관하여 로그아웃 후 새로고침에 서버 조회가 필요하지 않음.
- 보관 키는 `schat_popup_v1:`로 구분하며 기존 브라우저 사본 정리에 포함하지 않음. API 키·로그인 토큰은 이 저장본에 넣지 않음.
- 로그아웃 직후 들어온 오래된 HTTP 응답은 PC 저장본에 반영하지 않음. 이미 전송된 요청의 서버 처리를 되돌리는 기능은 아님.
- 로그인 만료 시에도 보관된 별도 창만 로그인 화면 강제 이동에서 제외함. 일반 채팅·관리자 화면의 인증 보호는 유지함.
- 만료 시 개인정보와 체크를 지우되, 로그인 없이 사용하는 모드 표시와 체크리스트 양식은 유지함. 열린 창은 주기적으로 검사하며, 브라우저를 끈 동안에는 실행할 수 없어 다음에 해당 창을 열 때 만료 자료를 정리함. 디스크에서 복구 불가능한 보안 삭제를 보장하는 방식은 아님.
- 브라우저 저장 차단·용량 부족 시 기존 저장 실패 안내를 표시함. 다른 PC·다른 브라우저로는 동기화하지 않음.

## 검증

- 최종 production build 통과함. 기존 Browserslist·대형 번들 경고는 남음. 문서 화면 검사 11개와 이번 추적 파일 diff 공백 검사 통과함.

- 가짜 저장소·API를 사용하는 동작 검사와 기존 이름 가리기·개인 세션 검사 28개, 기존 화면 구조 검사 13개 통과함(합계 41개).
- 로그아웃 보존, 다른 계정으로 재접속해도 서버 호출 없음, 새로고침 복원, 24시간 만료, 기한 불필요 연장 방지, 늦은 읽기·쓰기 응답 차단, 저장 실패, 충돌 후 명시적 다시 불러오기를 확인함.
- 코드 검토에서 충돌 복구·상위 인증 이동·인증 조회 실패 후 로그아웃 때 사본 소실 문제를 발견하여 회귀 검사 후 보완함. 실제 브라우저 다중 창 이벤트 시험은 아직 미실시함.
- 실제 Gemini 호출, DB 변경, 운영 접속, Docker 재시작·재배포, push 없음. 다른 미커밋 기능과 storage 데이터는 커밋에서 제외함.

## 반영 후 확인 순서

1. 합성 체크리스트를 별도 창으로 열고 체크와 가짜 메모를 입력함.
2. 본창에서 로그아웃함. 별도 창 내용과 상단 PC 저장 표시를 확인함.
3. 별도 창에서 내용을 바꾸고 새로고침하여 남는지 확인함.
4. 본창에서 다른 시험 계정으로 로그인해도 별도 창은 PC 저장 상태를 유지하는지 확인함.
5. 작은 체크리스트는 로그아웃 때 지워지는지 확인함. 실제 환자정보로 시험하지 않음.

현재 실행 중인 3001·3002·3003에는 이번 코드를 재배포하지 않음. 위 수동 확인은 이번 커밋을 적용한 별도 시험 환경에서 진행해야 함.
