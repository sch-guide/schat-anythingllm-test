# 문서 관리 표시 정리와 `custom-documents (2008)` 조사

## 1. 화면 표시 정리

- 문서 관리 화면의 `custom-documents` 폴더는 화면에서만 `등록된 문서`로 보입니다. 내부 폴더 이름과 저장 위치는 그대로입니다.
- 업로드 칸의 `텍스트 파일, CSV, 스프레드시트, 오디오 파일 등 다양한 파일을 지원합니다!` 문구를 지웠습니다. `클릭하여 업로드하거나 파일을 끌어다 놓으세요`와 업로드 기능은 그대로이고, 칸 높이는 내용만큼 자동으로 줄어듭니다.
- 폴더 옆 숫자 `(2008)`은 이번에 바꾸지 않았습니다.

## 2. `2008`의 뜻

- 서버가 `server/storage/documents/custom-documents` 폴더 안의 `.json` 파일 개수를 그대로 셉니다.
- 이 파일은 PDF를 올릴 때 한 쪽마다 하나씩 만들어지는 페이지 기록입니다. 원본 PDF 수나 검색 벡터 수가 아닙니다.

| 항목 | 현재 수 |
|---|---|
| 작업 공간에 등록된 원본 PDF | 2개 |
| 페이지 수 | 543쪽(461 + 82) |
| 폴더 안 페이지 기록 파일 | 2,008개 |
| 그중 현재 작업 공간에 등록된 것 | 543개 |
| 예전 업로드에서 남은 페이지 기록 | 1,465개(실무지침서 3번분 1,383 + 검사 및 시술 1번분 82) |
| Chroma 검색 벡터 | 1,985개(본문 654 + 이미지 설명 1,331) |
| 롤백용 예전 collection | 151개(검색에 사용 안 함) |

- 예전 업로드 기록 1,465개에는 검색 벡터가 하나도 없어 현재 검색 결과에 나오지 않습니다.

## 3. 쌓이는 방식

- 같은 PDF를 다시 올리면 새 문서 ID로 페이지 기록과 PDF 내부 이미지를 새로 만듭니다. 그래서 숫자가 페이지 수만큼 늘어납니다.
- 이미지 설명은 이미지 해시로 재사용하므로 다시 만들지 않습니다.
- 자동 교체는 없습니다. 새 버전을 올려도 이전 버전이 작업 공간에서 자동으로 빠지지 않습니다.
- 작업 공간에서 문서를 빼면 본문과 이미지 설명 벡터가 함께 지워지지만, 페이지 기록 파일은 남습니다.
- `내 문서`에서 파일을 삭제하면 페이지 기록, 벡터 캐시, 벡터가 지워집니다. PDF 내부 이미지 폴더와 원본 PDF 보관 파일은 지워지지 않습니다.
- 현재 예전 업로드의 이미지 폴더 2개(각 약 383MB)가 남아 있습니다.
- 정정: 처음에 `연결되지 않은 이미지 폴더 1개`로 적은 것은 이미지 설명 저장본(`.description-cache`, 1,177개)이었습니다. 지우면 안 되는 캐시이고, 실제로 연결되지 않은 이미지 폴더는 0개입니다(같은 날 저장공간 정리 조사에서 확인).

## 4. 판단

- 성능: 폴더 파일 수를 세고 목록을 나눠 읽는 수준이라 2,008개로는 문제가 없습니다.
- 검색 품질: 예전 기록은 검색 데이터가 없어 영향이 없습니다. 다만 `내 문서` 목록에 예전 페이지가 한 줄씩 보이므로, 관리자가 이를 골라 다시 작업 공간으로 옮기면 같은 내용이 중복 검색될 수 있습니다.
- 저장 용량: 예전 페이지 기록은 약 7MB로 작지만, 남은 이미지 파일이 약 0.8GB입니다.
- 즉시 정리는 필요하지 않습니다. 정리할 때는 백업 후 예전 문서 ID 단위로 따로 승인받아 진행하는 것을 권장합니다.

## 확인

- 실제 Docker 화면에서 확인한 내용
  - `등록된 문서 (2008)`로 표시되고, `custom-documents` 글자와 형식 안내문은 보이지 않습니다.
  - 폴더 펼치기가 정상입니다.
  - 오른쪽 작업 공간 PDF 2개와 체크리스트 목록이 정상입니다.
- 끌어다 놓기와 파일 선택 모두 업로드 요청이 만들어지는 것을 확인했습니다. 이 요청은 서버로 보내지 않았고, 페이지 기록 수는 전후 2,008개로 같습니다.
- 화면 테스트 102개 통과, Docker production build 성공.
- 삭제, 정리, 재색인은 하지 않았습니다.
