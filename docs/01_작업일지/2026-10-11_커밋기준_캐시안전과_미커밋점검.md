# 커밋 기준 캐시 안전 및 미커밋 기능 점검

## 확인 범위

- 기준 커밋은 `81ffe720`임. 오늘 작업일지와 현재 변경 파일을 읽고 점검함.
- 운영 서버·실제 Gemini 호출·기존 데이터 삭제·push는 하지 않음.
- 문서 업데이트의 좁은 충돌 보호와 실패·재시작 복구는 별도로 진행 중이며 이 보고서의 캐시 검사 통과로 완료 판단하지 않음.

## 커밋된 코드만으로 캐시 검사

미커밋 문서 업데이트 코드를 제외하기 위해 Node의 파일 읽기를 시험 프로세스 안에서만 바꾸고 `git show HEAD:<경로>`의 코드를 메모리에서 실행함. 저장된 파일과 Git 작업공간은 바꾸지 않음.

사용 파일:

- `server/__tests__/utils/answerCacheDocuments.node.test.js`
- `server/__tests__/utils/answerCache.node.test.js`
- `server/models/documents.js`, `server/models/workspace.js`
- `server/utils/answerCache.js`

결과: 11개 통과, 실패 0개임. 가짜 DB와 실제 캐시·문서 모델을 연결한 검사이며 실제 운영 HTTP·Gemini 시험은 아님.

- 일반 문서 등록·부서에서 문서 제거 시 해당 부서 캐시를 비움.
- 변경 작업 중에는 이전 답변 재사용과 새 캐시 저장을 막음.
- 변경 전에 시작하여 뒤늦게 끝난 답변은 캐시에 다시 저장하지 않음.
- 문서 변경 실패 후에도 오래된 답변은 제거하고 캐시 변경 잠금을 해제함.
- 특정 부서 모델 작업에서 다른 부서 캐시는 보존됨.
- 커밋된 일반 등록 API가 `Document.addDocuments`, 부서 문서 제거가 `Document.removeDocuments`를 호출함을 확인함.
- 자료 전체 삭제의 `purgeDocument`는 부서들을 순회해 `removeDocuments`를 호출함. 이 경로는 안전상 다른 부서 캐시도 비울 수 있으며, 모든 삭제 경로가 오직 한 부서만 비운다는 뜻은 아님.

판정: 일반 등록·삭제의 캐시 보호는 미커밋 문서 업데이트 기능에 의존하지 않음. 보호 누락을 이유로 캐시를 강제로 끄는 변경은 하지 않음. 단일 서버 프로세스 기준이며 native/미설정 임베딩·감시 문서 등은 커밋된 재사용 조건에서 제외됨. 운영 배포 전체가 안전하다는 포괄 인증은 아님.

## 미커밋 기능의 현재 수준

아래 수준은 구현과 현재 선별 검사 기준임. 커밋·운영 배포 여부와 구분함.

| 기능 | 수준 | 하는 일 | 남은 확인 |
| --- | --- | --- | --- |
| Gemini 예산 추정 | 거의 완성 | 기록된 채팅 입력·출력 토큰과 관리자가 정한 단가로 추정 비용 계산, 80/95% 경고와 계산 불가 표시 | 최신 전체 관리자 화면·재시작 통합 확인 및 변경 묶음 검토 |
| 동의어 후보 | 거의 완성 | 문서에서 후보를 만들고 간호사가 승인한 단어만 검색에 적용, 순차 실행·재시도·실행 결과 표시 | 새 DB 변경 2개와 업로드 연결을 포함한 독립 배포 검증, 미완성 문서 교체 경로와 커밋 분리 |
| 체크리스트 메모·이전 체크 안내 | 거의 완성 | 브라우저에 메모 저장, 이전 체크가 남았음을 안내, 로그아웃·세션·시간별 메모 구분 | 현재 합쳐진 화면에서 실제 계정·작은 창·별도 창 최종 확인 및 개인정보 보관 안내 점검 |
| 출처 표시 후속 변경 | 거의 완성 | 답변의 원문 인용을 검증해 출처에 저장하고 PDF에서 해당 구간 표시 | 실제 PC·모바일 출처 클릭과 원문 위치 확인, 최신 전체 변경 검토 |

초기 단계로 볼 기능은 없으나 이번 점검만으로 모두 완성됨이라고 판정하지 않음. 이전 작업일지의 브라우저·Docker 확인은 당시 기록이며 이번에 재실행한 것으로 표시하지 않음.

## 이번 선별 검사

- Gemini 예산, 동의어 후보와 검토 화면, 체크리스트 메모·체크 상태, PDF 근거 선택·인용 검사: 72개 통과함.
- 별도 Agent 인용 연결 검사 파일 1개는 로컬 `openai` 의존성 누락으로 로드 실패함. 기능 단정 실패와 환경 실행 실패를 구분함. 이 결과를 전체 통과로 표시하지 않음.
- 후속으로 외부망 차단·빈 임시 storage·읽기 전용 소스의 별도 Docker에서 Agent 인용 연결 검사 2개를 통과함. 최초 실행은 테스트 암호화 값이 없어 읽기 전용 환경 파일을 쓰려다 실패했고, 임시 컨테이너에 합성 암호화 값만 지정하여 해결함. 실제 환경 파일을 수정하거나 보호를 풀지 않음. 외부 모델 목록·가격표 조회는 네트워크 차단으로 실패하며 예상된 환경 경고임. 실제 모델 응답 대신 가짜 응답을 사용함.
- 실제 API는 호출하지 않음. 새 migration을 적용하지 않음. 원본 자료·DB를 수정하지 않음.

## 다음 작업

문서 업데이트 담당 작업에서 동일 자료·작업공간만 보호하는 키별 잠금과 복구 검증용 기초 함수를 추가함. 실제로 별도 시험 프로세스를 종료하여 남긴 잠금을 사용함. 신규 10개 포함 관련 76개 검사를 주 담당자도 재실행하여 통과함. 이것은 실제 서버 시작 시 자동 복구가 연결됐다는 뜻이 아님.
