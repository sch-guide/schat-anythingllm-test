# 관리자 설정 통합과 직원 화면 단순화

## 1. 설정 들어가는 곳을 하나로

- 왼쪽 아래 렌치 아이콘 하나만 남겼습니다. 누르면 `SCHAT 관리자 설정`이 열립니다. 관리자 계정에만 보이며, 직원 계정에는 보이지 않고 주소를 직접 입력해도 들어갈 수 없습니다.
- 작업 공간 이름 옆 톱니바퀴를 없앴습니다. 예전 작업 공간 설정 주소로 들어오면 `SCHAT 관리자 설정`으로 이동합니다.
- 관리자 설정 메뉴는 여섯 가지입니다: 브랜드 관리, 답변 설정, 사용자 관리, 시스템 연결, 시스템 상태, 위험 설정.
- 글자 크기와 다크모드는 채팅 화면 오른쪽 위 화면 설정에 그대로 두었습니다.

## 2. 관리자 설정 메뉴별 내용

| 메뉴 | 할 수 있는 일 |
|---|---|
| 브랜드 관리 | 서비스 이름(로그인 화면 문구), 작업 공간 이름 변경. 현재 SCH 로고와 로그인 화면 모습 확인(파일 교체는 기술 담당자) |
| 답변 설정 | 사용 AI 모델 확인·변경(확인 단계 있음), 이전 대화 참고 수, SCHAT 기본 답변 규칙 편집, 고급 설정의 답변 표현 다양성 |
| 사용자 관리 | 직원 추가, 역할 변경(관리자·직원 두 가지), 계정 삭제, 직원별 작업 공간 사용 허용 |
| 시스템 연결 | AI 답변·검색 임베딩 API 키 등록 여부 확인, 키 변경, 연결 테스트 |
| 시스템 상태 | 등록 문서 수, 체크리스트 수, 검색 데이터 수, 연결 상태, 최근 시스템 기록(읽기 전용) |
| 위험 설정 | 작업 공간 삭제(기존 확인 창 그대로) |

- 예전 설정 메뉴(AI 제공자 세부 설정, 벡터 데이터베이스, 문서 분할, 이미지 생성, 음성, 모델 자동 선택, 에이전트 기능, 커뮤니티, 채팅 삽입, 개발자 API, 답변 규칙 변수, 브라우저 확장, 모바일, 지원팀 연락, 개인정보, 버전 표시, 초대)는 메뉴에서 숨겼습니다. 기능 코드는 지우지 않았습니다.
- 검색 데이터 초기화, 문서 유사도 기준, 검색 문서 조각 수, 임베딩 모델·차원 변경은 관리자 화면에 두지 않았습니다.
- 화면 문구는 쉬운 한국어로 썼습니다. 영어 메뉴명 대신 `답변 규칙`, `검색 임베딩`, `이전 대화 참고 수`, `답변 표현 다양성`, `시스템 기록`을 씁니다. `API 키`, `Gemini`, `SCHAT`, `PDF`는 그대로 둡니다.

## 3. 기본 답변 규칙(Default System Prompt)

- 확인한 구조: 작업 공간에 자기 답변 규칙이 있으면 그것만 쓰고, 두 규칙을 합치지 않습니다. 예전에는 작업 공간 규칙이 비어 있으면 기본 답변 규칙이 아니라 프로그램에 들어 있던 영어 기본 문장이 쓰였습니다. 기본 답변 규칙은 작업 공간을 새로 만들 때 한 번 복사될 뿐이었습니다.
- 현재 작업 공간에는 기본 답변 규칙과 글자까지 같은 복사본(1,167자)이 따로 저장되어 있었습니다.
- 이번에 작업 공간 규칙이 비어 있으면 기본 답변 규칙을 그대로 이어받도록 바꿨습니다. 그다음 작업 공간의 복사본을 지워 기본 답변 규칙 하나만 관리하도록 정리했습니다.
- 두 내용이 같았으므로 AI가 받는 지시문은 전후가 같습니다. 규칙 내용은 수정하거나 요약하지 않았습니다.
- 현재 직원 답변(Automatic)은 AI가 이 규칙을 기본 지시문으로 받습니다. 규칙을 바꾸면 모든 직원 답변에 바로 적용되므로 화면에 주의 문구를 넣었습니다.

## 4. 직원 채팅 화면

- 새 대화 버튼은 `+ 새 대화` 하나입니다. `New Thread`, `*New Thread`, 이름 없는 빈 대화 행은 목록에 보이지 않습니다. 첫 질문을 보내면 질문 내용으로 이름이 붙어 목록에 나타납니다.
- 입력창에는 글자 입력과 전송 버튼만 있습니다. 이미지 안내문, 이미지 첨부, `+ 도구`, `/` 도구 메뉴, 마이크, 채팅창 파일 끌어놓기와 붙여넣기 첨부를 화면에서 껐습니다. 서버의 이미지·도구·음성 코드는 지우지 않았습니다.
- 오른쪽 위 사용자 버튼은 이름 두 글자 대신 사람 아이콘으로 바꾸고, 누르면 `로그아웃`만 보입니다.
- 빈 화면 아래 `에이전트 생성·워크스페이스 편집·문서 업로드` 바로가기를 없앴습니다.
- 대화 목록의 영어 문구(이름 바꾸기, 삭제, 불러오는 중)를 한국어로 바꿨습니다.

## 5. 문서 업로드

- `또는 링크 제출`, 주소 입력창, `웹사이트 가져오기`를 숨겼습니다. 파일 업로드, 끌어놓기, 문서 목록, 폴더, 원본 PDF 보관, 체크리스트 자동 생성은 그대로입니다.

## 6. 다크모드

- 원인: 병원 브랜드 색을 적용할 때 다크모드에도 밝은 색 값이 들어가 있었습니다. 그래서 사이드바가 밝은 회청색으로 보이고 흰 글자가 잘 안 보였습니다.
- 다크모드 전용 색을 따로 정했습니다(블랙·차콜 바탕, 딥 네이비 선택 표시, 은은한 파란 테두리).
- 사이드바는 채팅 영역보다 한 단계 어둡게 했습니다. 검색창은 어두운 바탕에 파란 테두리, 선택된 작업 공간은 딥 네이비 바탕에 파란 왼쪽 선으로 표시합니다.
- 새 대화 버튼은 파란 테두리로 목록과 구분했습니다. 입력창과 오른쪽 위 메뉴도 같은 색으로 맞췄습니다. 라이트 모드는 바꾸지 않았습니다.

## 7. API 키 저장

- 키는 기존 방식대로 서버 설정 파일(`docker/.env`, Git 제외)에 저장되며 화면·기록에 다시 표시되지 않습니다.
- 기존 Docker 설정은 컨테이너를 다시 만들 때 AI 답변 키를 검색 임베딩 키로 덮어썼습니다. 그래서 웹에서 바꾼 AI 답변 키와 모델이 유지되도록 설정을 고쳤습니다. 현재 값은 전후가 같습니다.
- 연결 테스트는 저장된 키로 모델 정보만 조회합니다. 병원 문서나 질문은 보내지 않습니다. 외부 호출 승인이 없어 이번 검증에서는 실제로 누르지 않았습니다.

## 확인

- 실제 Docker 화면(Chrome)에서 관리자·직원 계정을 각각 확인했습니다. PC, 휴대폰 크기, 라이트·다크 모드를 모두 봤습니다.
- 관리자
  - 렌치 → 여섯 메뉴 정상, 톱니바퀴 없음, 예전 설정 주소는 관리자 설정으로 이동합니다.
  - API 키는 화면·페이지 소스 어디에도 보이지 않았습니다.
  - 기본 답변 규칙 1,167자 표시, 작업 공간 `기본 답변 규칙 사용 중`으로 전환을 확인했습니다.
  - 업로드 창에 웹사이트 가져오기가 없고 체크리스트 목록이 보입니다.
  - 작업 공간 삭제는 확인 창만 띄우고 취소했습니다.
- 직원
  - 렌치가 없고 관리자 주소로 들어가면 홈으로 돌아갑니다.
  - `+ 새 대화` 하나만 있고, 입력창 버튼은 전송 하나입니다.
  - 전송을 누르면 질문 요청이 만들어지는 것까지 확인했습니다. 이 요청은 서버로 보내지 않았습니다.
  - 화면 설정 메뉴에는 글자 크기와 다크모드만, 사용자 메뉴에는 로그아웃만 있습니다. 로그아웃도 정상입니다.
  - Citation 표시가 정상이고, 출처 p.56 PDF 보기와 Renal biopsy 체크리스트 작업창도 정상입니다.
- 관리자 화면을 휴대폰 크기로 열면 사이드바가 화면을 가리던 문제를 발견해, 좁은 화면에서는 위쪽 메뉴 선택 상자로 바꿨습니다.
- 영어 용어 검사: 관리자 여섯 화면에서 `System Default`, `Manage Users`, `Default System Prompt`, `Provider`, `Embedding`, `Vector Database` 같은 문구가 보이지 않았습니다. 남은 영문은 `SCHAT`, `API`, `Google Gemini`, 모델 이름, 아이디뿐입니다.
- 작업 전후 비교
  - 검색 벡터 1,985개, 문서 543건, 체크리스트 파일 64개(폴더 해시 동일), Renal biopsy 체크리스트 해시가 같습니다.
  - AI가 실제로 받는 답변 규칙은 작업 공간 복사본과 해시가 같습니다.
- 테스트
  - 서버: node 테스트 231개, 답변 규칙·에이전트·작업 공간 jest 77개 통과.
  - 화면: 테스트 100개 통과, Docker production build 성공, 세 컨테이너 모두 healthy.
- 외부 호출 승인 범위가 없어 새 질문으로 Gemini 답변을 만드는 검수와 연결 테스트 버튼은 실행하지 않았습니다.

## 역할 단순화 (추가 요청)

- 사용자 관리의 역할 선택을 `관리자`와 `직원` 두 가지로 줄였습니다(직원 추가와 목록 모두).
- 서버의 매니저 역할과 권한 코드는 그대로 두었습니다. 현재 매니저 계정은 없습니다. 예전 매니저 계정이 있으면 그 계정 행에만 `매니저(이전 역할)`로 보여, 역할이 모르게 바뀌지 않습니다.

## 바꾸지 않은 것

- Automatic, AgentHandler, rag-memory, BM25, ChromaDB, Gemini 답변·임베딩, Citation, PDF viewer, 원본 PDF API, 체크리스트 생성·작업창·별도 창, 본문 벡터, 문서 색인, 로그인 인증은 바꾸지 않았습니다.
- 예외적으로 답변 규칙을 고르는 한 줄(작업 공간 규칙이 없을 때 기본 답변 규칙을 쓰는 부분)만 고쳤습니다.
