# 대기 시간 단축과 바로 재시도

## 작업 범위

4단계 부하 시험은 잠시 멈추고 별도 변경으로 진행함. 기존 `tests/load`와 4단계 작업일지는 이번 커밋에 넣지 않음. 운영 서버 접속·실제 Gemini 호출·push는 하지 않음.

## 실제 기록 분석

로컬 `server/storage/anythingllm.db`를 SQLite `mode=ro`로 조회함. 질문·답변 본문·직원 정보는 출력하거나 문서로 옮기지 않고 시간 통계만 계산함. 운영 VM의 최신 기록 전체를 분석한 것이 아님.

- 전체 276건 중 양수 `metrics.duration`이 있는 242건을 사용함. 34건은 시간 누락/0이므로 제외함. 실패·중단되어 저장되지 않은 요청은 포함되지 않아 성공 기록 편향이 있음.
- 기록 범위: UTC 2026-09-22 14:44:19~2026-10-10 15:40:47. 한국 시간으로 9월 22일 23:44~10월 11일 00:40임.
- 모델은 기록상 `gemini-3.8-flash`임. provider가 `GeminiLLM`이면 일반, `GeminiProvider`이면 Agent로 구분함. 질문 내용으로 추정 분류하지 않음.
- 백분위수는 정렬 후 `ceil(건수 × 비율)`번째 값임. P95는 95%가 이 시간 이하, 나머지 약 5%가 더 느렸다는 뜻임. 느린 5%의 평균은 아님. 일반 80건의 P99는 표본이 적어 최댓값과 같음.

| 구분 | 건수 | 중앙값(보통) | P95 | P99 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 일반 채팅의 저장된 AI 시간 | 80 | 5.038초 | 14.736초 | 34.746초 | 34.746초 |
| Agent의 누적 AI 호출 시간 | 162 | 5.734초 | 18.059초 | 36.390초 | 38.586초 |
| Agent 기록 생성~마지막 저장 간격(참고) | 162 | 7.125초 | 27.330초 | 44.610초 | 69.726초 |
| 체크리스트가 함께 표시된 답변 | 별도 구분 불가 | — | — | — | — |

일반 `LLMPerformanceMonitor.measureStream`은 스트림 객체를 받은 뒤부터 측정하므로 검색·연결·첫 응답 대기 전체를 포함하지 않음. Agent는 `getCumulativeUsage`의 모델 호출 누적값이고 도구 실행 전체와 다름. Agent DB 간격은 작업 시작 시 행을 만들고 답변 저장 때 갱신한 값이지만, 나중 수정도 반영될 수 있음. 대기열 입장 전후를 구분한 전체 응답시간 통계는 아님. 체크리스트는 화면에서 질문과 연결해 표시하므로 이 DB에 표시 여부가 따로 없어 별도 수치를 만들지 않음.

## 추천과 적용값

- 대기: 30초 → **15초**.
- 서버 입장 후 생성 제한: 90초 → **80초**.
- 직원 화면 입장 후 중단: 100초 → **90초**.
- 동시 생성 4건, 대기 정원 10건은 유지함.

관측된 Agent 저장 간격 최대 69.726초보다 약 10초 여유를 두되 기존보다 줄인 보수적인 선택임. 서버는 대기 포함 약 95초, 화면 안전장치는 약 105초임. 네트워크 연결 이전 지연과 브라우저 백그라운드 타이머 지연까지 포함한 절대 상한은 아님. 정상 답변이 절대로 잘리지 않는다는 보장은 없으므로 4단계와 추후 운영 관찰로 재조정해야 함. 바로 45~60초로 줄이면 관측된 느린 응답을 자를 위험이 있음.

## 화면 및 재시도

- 순번 대기 동안 생성 시간은 시작하지 않음. 입장 이벤트 뒤 검색 표시, 검색/문맥 준비 뒤 작성 표시로 이어짐.
- 일반 HTTP 채팅에는 작성 단계 신호가 없던 것을 `generationPhase` 이벤트로 추가함. 검색 비율·검색 내용·모델 입력은 바꾸지 않음.
- 기존 Agent 검색/추가 검색 상태 처리는 유지함. 도구가 추가 검색을 요청하면 작성 중에서 추가 검색으로 돌아갈 수 있음.
- 서버 대기 만료와 생성 만료 코드를 HTTP/Agent 양쪽에서 화면까지 전달해 바로 누를 수 있는 재시도 버튼을 표시함. Gemini 429와 구분함.
- 화면 자체 시간 초과는 기존 안내/버튼을 재사용하며 부분 답변이 있어도 표시함.
- 재시도는 현재 질문과 첨부를 유지하고 이전 입장 시각·실패 응답을 빼고 다시 전송함. 자동 재시도는 하지 않음. 기존 서버의 1인 1건 제한을 유지함.

## 검증 및 남은 확인

- 대기 15초 경계, 14초 대기 후 생성 80초 별도 보장, 취소/오류 정원 반환, Agent 오류 코드 전달, 재시도 이력과 첨부, 단계 순서를 검사함.
- 관련 자동 검사 36개 통과함. HTTP/Agent 실제 화면 처리 함수에 가짜 이벤트를 넣는 검사도 포함함. 실제 Gemini 호출 없이 확인함.
- 코드 리뷰에서 발견된 재시도 이력 계약 문제를 수정함. 현재 질문까지 포함한 이력을 넘겨야 기존 `sendCommand`가 올바르게 재전송함.
- Vite production build 통과(36.52초). 브라우저 목록/번들 크기 등 경고는 남음. 실제 브라우저와 기존 3001 Docker 반영은 이번 변경에서 아직 확인하지 않음.
- 실제 Gemini 호출 0회. DB 및 기존 체크리스트·퀴즈·직원 계정 데이터 변경 없음.
- 이 변경만 선별 커밋한 뒤 4단계 시험을 15/80/90초 기준으로 재개함. 이전 30/90/100초 결과를 새 설정 결과로 재사용하지 않음.
