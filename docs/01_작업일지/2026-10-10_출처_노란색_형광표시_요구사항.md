# 출처 노란색 형광 표시 — 승인된 요구사항

## 진행 순서

- 같은 폴더에서 문서 업데이트의 팝업·실제 교체 연결과 통합 검증을 마무리하고, 해당 기능만 별도 커밋한 뒤 진행함.
- 체크리스트 등 다른 기능 파일은 수정하지 않음. 테스트용 문서만 사용하며 push하지 않음.
- 형광 표시도 검증을 통과한 뒤 별도로 커밋함.

## 표시 규칙

- 출처를 눌러 원본 PDF를 열면 출처에 연결된 근거 텍스트(chunk) 전체를 노란색으로 표시함.
- 문장과 표 모두 해당 구간 전체를 대상으로 함.
- 근거 구간이 여러 군데면 모두 표시하고 첫 위치로 자동 이동함.
- PC의 기본 PDF 뷰어와 모바일의 PDF 그리는 화면 모두 적용함.
- 띄어쓰기와 줄바꿈 차이는 무시하되, 확실하게 찾은 경우에만 표시함.
- 찾지 못하면 “정확한 위치를 찾지 못해 원문을 표시합니다.”를 안내하고 원문만 표시함.

## 준비 당시 상태

- 사용자 요구사항을 기록한 단계이며 형광 표시 구현·검증·커밋은 아직 하지 않음.
- 문서 업데이트 파일이 이전 확인 이후 추가·변경되어, 다른 작업 창의 진행 여부를 확인 중임. 확인 전에는 교체 코드 수정이나 커밋을 시작하지 않음.

## 다른 창과의 역할 분리 및 읽기 전용 준비

- 사용자가 다른 창에서 문서 업데이트를 계속 진행 중이며 이 창은 형광 표시 준비만 하도록 지정함.
- 이 단계에서 앱 코드·공용 현재 상태·생성 문서 화면·Git 커밋은 변경하지 않음. 이 요구사항 기록만 보완함. 공용 문서 화면 재생성·검사는 다른 창과의 쓰기 충돌을 피하도록 구현 통합 시 진행해야 함.
- PC의 `Citation/PdfPageViewer.jsx`는 인증된 PDF를 받아 임시 주소로 기본 PDF 뷰어에 표시함. 모바일의 `Citation/PdfPageCanvas.jsx`는 기존 pdf.js로 인용 페이지를 그림. 두 화면 모두 아직 근거 텍스트를 전달받지 않음.
- `Citation/index.jsx`의 `dedupeCitationSources`는 같은 문서·같은 페이지를 합칠 때 가장 긴 대표 텍스트만 남김. 여러 근거를 모두 표시하려면 원래 근거 텍스트들의 목록을 별도로 보존하고 두 PDF 화면에 전달해야 함. 현재 다른 창의 변경이 있는 파일이므로 이 단계에서 수정하지 않음.

### 구현 후보와 확인할 사항

1. 공통 위치 찾기: PDF 텍스트에서 공백·줄바꿈을 제외한 문자열과 원래 글자 위치의 대응을 유지하고, 근거 전체가 일치할 때만 표시 좌표를 반환함. 표 읽기 순서가 다르거나 텍스트가 없는 스캔 문서는 추측하지 않고 안내와 원문으로 처리함.
2. PC: 기본 PDF 뷰어 내부에 HTML 표시를 얹기 어려우므로 원본을 보존하면서 표시가 들어간 임시 PDF를 만들어 여는 방식을 우선 검토함. 서버에는 기존 `pdf-lib` 의존성이 있으나 브라우저에서 사용 가능한 연결 방식과 PDF 보존 여부는 구현 전에 검증해야 함. 외부 서비스나 AI 호출은 필요하지 않음.
3. 모바일: 공통 좌표를 PDF 화면 배율·회전에 맞추어 변환하고 노란 표시를 얹음. 첫 일치 구간으로 이동하고 확대 시에도 표시를 유지해야 함.
4. 안전한 실패 처리: 근거가 누락되거나 위치 확인이 실패하면 “정확한 위치를 찾지 못해 원문을 표시합니다.”와 원본만 보여 줌. 여러 근거 중 일부만 찾은 경우의 처리도 구현 전 명시적으로 정해야 함.
5. 합성 PDF 검사: 여러 줄 문장, 표, 여러 근거, 중복 근거, 불일치, 텍스트 없는 PDF, 회전·확대, 첫 위치 이동, 원본 파일 불변을 확인함. PC 기본 뷰어와 모바일 화면의 실제 표시도 별도로 확인해야 함.

### 다음 시작 위치

- 문서 업데이트 담당 창의 완료·별도 커밋을 확인하고 최신 변경을 다시 읽음.
- 공통 위치 찾기와 근거 목록 보존부터 실패하는 검사를 작성한 뒤 구현함. 현재 준비 단계에서는 형광 표시 코드·테스트를 작성하거나 실행하지 않음.
