# 3002·3003 가짜 지침과 실제 답변 확인

## 후속: 3003 TXT 출처 및 PDF 시험

- 별빛검사 실제 TXT에는 “누락된 시험카드가 있으면 시험 담당자에게 확인한다.”가 있음. 사용자가 확인한 표현은 원문에 근거가 있음.
- 무반응 원인: 검색 출처는 text로 본문을 전달하지만 SourceEvidenceRow는 excerpt만 읽어 버튼을 숨겼음. TXT 원문 전체 보기와 검색 근거 텍스트 펼치기는 구분함.
- 3003의 별도 81ffe720 시험 폴더에서 TXT text fallback과 “원문 보기는 PDF 문서만 지원합니다. 아래는 답변에 사용된 근거 텍스트입니다.” 안내를 PC·모바일에 추가함. 오래된 PDF의 기존 표시 정책은 유지함. 변경 파일은 Citation/index.jsx, MobileSourceScreen.jsx, sourceEvidence.node.test.mjs임. 주 저장소 앱 코드와 3001은 변경하지 않음. 따라서 이 시험 화면은 순수 81ffe720에 작은 미커밋 보완이 더해진 상태임.
- 먼저 버튼이 없는 실패를 재현했고 보완 후 출처 렌더링 검사 18개 통과함. 브라우저 실제 클릭은 도구 시작 오류로 미확인임.
- 최종 Vite build 성공, 안내 문구가 포함된 실제 3003 화면 파일 HTTP 200 확인함. 문서 검사 11개 통과함. 기존 대형 번들·Browserslist 등의 빌드 경고는 남음. 시험 폴더에서 git diff 검사는 Git 저장소 인식 오류로 실행하지 못했으므로 통과로 기록하지 않음.
- 합성 `시험전용_은하검사.pdf` 한 페이지를 3003 전용 DB·Chroma·원본 저장소에 추가함. 테스트 스크립트 등록이며 업로드 UI/Collector 검증은 아님. 개인정보와 실제 진료 기준은 없음. 생성 PDF를 이미지로 렌더링하여 한글·배치 확인함.
- 실제 질문 “은하검사 준비물은 무엇인가요?”에 “초록 시험카드와 빈 확인표”라고 답함. PDF 출처와 인증된 원본 HTTP 200 확인함. 실제 PDF 텍스트로 기존 형광 좌표 계산을 실행해 8개 구간 일치를 확인함. 현재 방식은 검색에 사용된 한 페이지 청크 전체를 표시하며 답변 문장만 골라 표시하는 검증은 아님.
- 시작 시 15/30회, 추가 임베딩 1회·질문 임베딩 1회·답변 1회로 18/30회가 됨. 잔여 12회(질문 12개라는 뜻은 아님). 추가 실제 호출하지 않음. 사용자 시험 시 수치는 증가함. 기존 통로의 30회 차단 유지함.
- 확인 순서: 3003에서 Ctrl+Shift+R → 메모 확인용 작업공간 → “은하검사 준비물은 무엇인가요?” → 출처의 “근거 원문 보기” 선택. TXT도 동일 버튼으로 안내·근거 텍스트 확인 가능함.
- 원본 PDF는 임시 폴더 schat-preview-pdf/synthetic-galaxy.pdf에 있으며 시험 환경 원본 저장소에도 보존됨. commit/push·운영 반영·3001 데이터 변경 없음.

## 이전에 답변이 없던 이유

- 처음에는 메모·화면 확인용으로 앱 컨테이너 외부 통신을 막고 Gemini 키를 비워 두었음. 가짜 답변 모드를 켠 것은 아니었음.
- 체크리스트 연결 확인용 문서 행만 있었으며, 질문을 검색할 본문·임베딩·별도 Chroma는 준비되지 않았음.
- 따라서 문서가 없다는 문제와 API 연결이 없다는 문제가 함께 있었음. 기존 운영 기능의 고장으로 단정하지 않음.

## 이번 준비

- 3002·3003 각각 `시험전용_달빛검사_준비안내.txt`, `시험전용_별빛검사_인계안내.txt`를 시험 저장소에 등록함. 실제로 없는 검사이며 실제 환자에게 적용 금지를 본문에 표시함. 환자정보·약물·실제 치료 수치 없음.
- 3003에는 기존 운영 Chroma와 분리된 `schat-preview-chroma`를 준비하고 두 본문을 실제 Gemini 임베딩으로 등록함. 최종 상태는 고정 첨부가 아닌 일반 검색 문서임.
- 3003 앱은 내부망에 그대로 두고, 기존 Gemini SDK의 통신 목적지만 시험용 제한 통로로 연결하는 별도 preload를 적용함. 원래 커밋의 앱 소스는 변경하지 않음. 실제 운영 배포에 이 시험 어댑터를 포함하지 않음.
- 실제 모델 설정: 답변 gemini-3.8-flash, 임베딩 gemini-embedding-2. 기존 로컬 설정의 값을 확인함.
- `schat-preview-gemini`만 외부 Gemini로 요청함. 기존 docker/.env를 읽기 전용으로 연결하여 메모리에서 키를 사용하며 키를 새 파일·콘솔·문서·Git에 복사하지 않음. 키가 든 응답 오류 원문도 반환하거나 기록하지 않음.
- 기존 3003 컨테이너는 중지 후 `schat-preview-81ffe720-offline`으로 보존하고, 같은 시험 DB·계정·인증 설정을 유지한 새 컨테이너로 전환함. 두 컨테이너를 동시에 시작하지 않음. 3001·운영 서버 변경 없음.
- 3002는 실제 API 키와 외부 호출을 계속 차단함. 시험 문서 등록 및 메모 확인만 제공함.

## 30회 제한

- 두 환경 합계 최대 30회임. 현재 실제 호출 통로는 3003만 사용하므로 3002는 0회임.
- 문서 임베딩·질문 임베딩·답변 생성·실패·재시도도 외부 요청마다 포함함. 질문 30개라는 뜻이 아님.
- 요청을 보내기 전에 사용 횟수를 파일에 저장하고 디스크 반영까지 수행함. 한도 도달 시 외부 전송을 차단함. 저장 기록 누락·손상 시에도 차단함.
- 단일 제한 통로 프로세스 기준임. 새로고침·정상 재시작·날짜 변경으로 초기화하지 않음. 관리자가 횟수 파일을 지우거나 바꾸거나 별도 통로를 만들면 보호를 유지할 수 없으므로 하지 않음.
- 키 없는 별도 단위 시험에서 31번째 차단과 기록 손상 시 차단을 먼저 실패 재현 후 구현하여 2개 통과함. 실제 API를 30번 소진시키는 시험은 하지 않음.
- 확인 시점 사용 6회: 문서 임베딩 2회, 두 질문의 임베딩 2회, 실제 답변 2회. 잔여 24회임. 이후 사용자가 시험하면 늘어남.
- 실시간 확인: http://localhost:3003/preview-usage 의 used는 사용 횟수, limit는 최대 30회임. 키나 질문 내용은 표시하지 않음.

## 실제 확인

- 첫 시험은 고정 첨부 자료로 답변 확인 후, 고정을 해제하여 정상 검색 흐름으로 다시 검사함.
- 직원 preview2로 실제 로그인하여 `별빛검사 인계 시 확인할 세 가지는 무엇인가요?`를 전송함.
- 실제 응답: 파란 시험카드, 준비 완료 표시, 빈 기록지. 가짜 시험 내용이라는 안내 포함함.
- 오류 없이 스트리밍 종료, 별빛검사 문서 출처 1개를 확인함. 실제 브라우저 자동 클릭 검사는 도구 오류 때문에 대체하지 못했으며 HTTP 전체 흐름을 검사함.
- PDF가 아닌 TXT 합성 문서이므로 PDF 원본 이동·형광 표시·실제 병원 지침 검색 품질 검증은 아님. 문서는 시험 초기화 스크립트로 등록했으므로 업로드 UI·Collector 검증도 아님.

## 사용자가 확인할 방법

1. http://localhost:3003 에서 기존 안내한 계정으로 로그인함. 사번 없는 기존 계정 로그인 선택을 사용함.
2. `메모 확인용 (가짜 자료)` 작업공간에서 질문함.
   - 달빛검사 준비 순서와 준비물을 알려줘.
   - 별빛검사 인계 시 확인할 세 가지는 무엇인가요?
   - 별빛검사에서 시험카드가 없으면 어떻게 하나요?
3. 3002는 질문하지 않아도 http://localhost:3002/workspace/memo-preview/checklist/preview-checklist 에서 메모를 확인할 수 있음.
4. 체크리스트가 보이려면 공개 상태이며 계정이 접근 가능한 작업공간 문서와 연결돼 있어야 함. 현재 합성 체크리스트는 이 조건을 만족함. 임의의 TXT 문서를 등록했다고 자동으로 체크리스트가 생기는 것은 아님.
5. 실제 환자정보·실제 임상 판단 질문은 이 시험 환경에 입력하지 않음. 30회에 도달하면 추가 실호출 없이 중단하며 별도 승인 전 카운터를 초기화하지 않음.

## 다음과 제한

- 실행 도구는 사용자 임시 폴더의 `schat-preview-*` 파일에 있음. 원본 앱 소스·기존 문서 업데이트 미완성 변경에는 섞지 않음.
- 이 환경은 운영 배포용 구성이 아님. 키 파일은 원래 위치에 있고 새 사본 없음. Gemini 호출 비용은 기존 프로젝트에 발생할 수 있음.
- commit·push·운영 반영 없음.
