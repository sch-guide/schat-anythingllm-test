# 문서 업데이트 최종 연결과 검증

## 범위

- 기존 미완성 코드를 이어서 일반 업로드·문서 삭제·작업공간 삭제/초기화·문서 교체의 충돌 보호와 재시작 복구를 완성하는 작업임.
- 기준 HEAD: `e0e5507a`. 다른 미커밋 변경을 되돌리거나 포함하지 않음.
- 실제 Gemini 호출 0회. 기존 누적 사용량을 초기화하지 않음. 기존 3001·3002·3003 재시작, Google Cloud 접속, push는 하지 않음.
- 검증 완료 전 문서 업데이트 활성화와 완료 커밋을 하지 않음.

## 안전 검토에서 확인한 문제

- 교체 서비스의 전체 잠금과 작업공간 삭제의 개별 잠금이 서로 다른 방식이라 충돌을 막지 못했음.
- 기존 전체 검색 잠금은 다른 부서 질문까지 막을 수 있었음.
- 준비 중 작업 기록과 서버 시작 시 복구 연결, 복구 도중 재시작 처리가 부족했음.
- 복원 검사는 벡터 번호뿐 아니라 본문·메타정보·DB와 실제 검색 상태를 함께 확인해야 함.

## 적용 방향

- 같은 문서의 충돌 작업과 대상 작업공간 초기화만 보호함. 실제 판본 전환 순간에는 해당 부서 검색이 잠깐 기다린 뒤 계속되도록 함. 다른 부서 검색을 일괄 막지 않음.
- 이전 원본과 연결된 체크리스트·퀴즈·과거 출처는 보존함. 새 판본으로 자동 이전하지 않음.
- 준비부터 완료까지 기록을 남기고, 정상 교체가 확인되지 않은 작업은 복구 검증 뒤에만 잠금을 해제함.
- 복구 소유권을 확인할 수 없는 자료를 시간만 지났다는 이유로 지우지 않음.

## 현재 검증 기록

- 수정 전 기준 선별 검사 65개 및 기존 기능 회귀 검사 142개 통과함. 최종 수정 후 재검증 결과와 구분함.
- Vite 화면 production build 통과함. 출력은 Windows 임시 폴더이며 기존 앱에 반영하지 않음. 기존 Browserslist·큰 번들·일부 브라우저 호환 경고는 남아 있음.
- 실제 Chroma 통합 시험을 위해 외부망 차단 내부 네트워크와 메모리 저장소만 사용하는 별도 컨테이너를 준비함. 기존 DB·storage·Chroma volume을 연결하지 않음.

## 진행 상태

아래는 진행 당시 기록이며, 현재 결과는 맨 아래 최종 검증 기록을 우선함.

## 독립 검토 후 보완

- 호스트 선별 검사 247개 중 245개 통과, 실패 0개이며 Linux 전용 2개는 별도 환경에서 검사함. Linux 잠금 검사 17개, 실제 격리 Chroma 연결 검사 14개 및 실제 Collector의 합성 PDF 준비 검사도 통과함.
- 이 결과와 별개로 독립 검토에서 연결 끊김·강제 종료 경계 문제 3개를 재현함. 브라우저 연결이 끝나도 서버 업로드가 남아 있으면 잠금을 유지해야 함. 작업 기록을 쓰다가 종료돼도 기록이 반쪽만 남지 않아야 함. 복구 도중 다시 시작해도 잠금의 주인을 확인할 수 있어야 함.
- 세 문제를 함께 보완하고 해당 실패 상황을 자동 검사에 추가하는 중임. 기존 통과 수치만으로 활성화하지 않음.
- 실제 Prisma·Collector·Chroma를 한 번에 연결한 전체 브라우저 시험과 구분함. SQLite·파일 복구, Chroma 검색 자료, Collector PDF 처리를 나누어 격리 검증한 결과임.

## 보완 결과와 활성화

- 연결 종료와 실제 업로드 완료를 구분함. 일반 업로드·외부 API 업로드·채팅 첨부 처리의 저장 작업이 끝날 때까지 같은 자료의 교체를 막음. 잘못된 제목은 400, 충돌은 423, 기타 오류는 내부 정보를 드러내지 않는 500 응답으로 끝냄.
- 복구 기록은 완전히 쓴 뒤 한 번에 공개함. 새 검색 문서도 완전한 준비 자료만 공개함. 중간에 서버 프로세스가 종료돼도 반쪽 JSON이 최종 자료로 남지 않도록 함.
- 복구 도중 다시 종료되는 경우의 잠금 소유권 연결을 보완함. Linux의 실제 커널 잠금과 서로 다른 호스트명·자식 프로세스 강제 종료로 반복 복구를 검사함.
- 독립 검토의 3건과 수정 과정의 예외 응답 1건을 모두 해결하고 재검토에서 확인함. `DOCUMENT_UPDATE_READY=true`로 소스 활성화함. 기존 실행 서버에 배포했다는 의미는 아님.
- 최종 전체 코드 검토에서도 이번 Linux Docker 배포 범위의 새 Critical·Important 문제 없이 마무리 가능 판정을 받음.

## 사용 범위와 남은 제한

- Linux Docker·PDF·Chroma·단일 앱 서버 대상임. 여러 부서 공유 문서, 자동 감시 문서, 부서에 연결되지 않은 구본은 안전상 거절함. Windows에서 서버를 직접 실행하는 경우의 복구 표식 부분 쓰기 경계까지 검증한 것은 아님. Windows Node는 합성 시험에만 사용함.
- 준비 자료와 catalog는 같은 파일시스템이며 hard-link를 지원해야 함. 프로세스 강제 종료 안전 시험이며 정전·물리 저장장치 장애 복구를 인증한 것은 아님.
- 새 DB migration은 없음. 원본과 이전 문서·연결·작업 기록은 보관함. 자동으로 영구 삭제하거나 다른 문서로 옮기지 않음.
- 직원 질문은 계속 허용하되, 구본·신본이 섞이지 않도록 해당 부서의 실제 검색 전환 순간에는 짧게 기다림. 다른 부서는 이 잠금으로 기다리지 않음. API·임베드의 긴 읽기 작업이 있으면 교체가 안전하게 시간 초과될 수 있음.
- 소유권이나 복원을 확인할 수 없는 기록은 임의로 삭제하지 않음. 그런 경우 확인 필요 상태가 남을 수 있음.
- 전체 저장소의 모든 검사를 통과했다는 뜻은 아니며, 기존 3001·3002·3003의 브라우저 화면을 최신 코드로 재확인하지 않음. 재시작 금지 요청을 유지함.
- 기능 파일만 명시적으로 골라 커밋 대상으로 함. 다른 미커밋 화면 스타일·시험 PDF·미리보기 자료·이전 문서 기록은 그대로 둠. 배포와 직접 확인 순서는 [release-1 안내](../release-1_운영반영_확인순서.md)를 참고함.
