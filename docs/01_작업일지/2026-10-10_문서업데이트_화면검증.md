# 문서 업데이트 화면 구현·검증

## 변경 내용

- 파일 선택과 폴더에 끌어놓기 모두 전체 묶음의 원래 파일명으로 기존 자료를 먼저 확인함. 확인 전에는 파일 업로드를 시작하지 않음.
- 같은 이름이 있으면 ‘기존 자료가 있습니다. 기존 자료를 지우고 업데이트하시겠습니까?’와 전체 겹침 목록, 업데이트·취소 버튼을 표시함.
- 취소하면 함께 선택한 신규 파일도 모두 올리지 않음. 이전 원본과 기존 체크리스트·퀴즈·과거 답변 출처는 보존하고 자동 이전하지 않는다고 안내함.
- 확인 오류·응답 손상은 중단하며, 교체 실패를 일반 업로드로 우회하지 않음. 연속 업데이트 클릭은 한 번만 처리함.
- 화면을 닫은 뒤 도착한 확인 결과가 뒤늦게 업로드를 시작하지 않도록 처리함.
- 성공 응답을 받으면 문서 목록을 새로 불러오고 보존된 체크리스트·퀴즈·과거 출처 목록과 경고를 표시함.
- 현재 교체 요청의 폴더 값은 하나이므로 서로 다른 폴더가 섞인 업데이트 묶음은 전송 전에 안내하고 중단함.

## 서버 연결 계약

- 사전 확인: `POST /workspace/:slug/document-update-preview`, 본문 `{names}`.
- 교체: `POST /workspace/:slug/document-update`, 파일 묶음 `files`와 `manifest`의 `{names, conflicts, folderName}`를 전달함.
- 성공 응답의 `results`, `relatedItems.checklists`, `relatedItems.quizzes`, `relatedItems.pastSources`, `warnings`를 사용함.
- 서버가 지원하지 않는 파일·복구 잠금·기존 목록 변경을 오류로 반환하면 화면도 중단함. 실제 지원 범위와 서버 안전 검증은 별도 서버 작업 결과를 따름.

## 확인 결과와 한계

- 가상 파일명만 사용한 Node 검사 8개 통과: 확인 대기, 혼합 묶음 취소, 교체 전용 요청, 연속 클릭, 응답 손상, 실패 시 우회 금지, 화면 종료 뒤 지연 응답 차단.
- 변경 화면·요청 코드 5개 파일의 자바스크립트·화면 문법 변환 통과.
- Vite 전체 화면 빌드를 테스트용 임시 폴더로 실행하여 종료 코드 0, 6,167개 모듈 변환을 확인함. 브라우저 호환 데이터 오래됨, 음성 라이브러리의 서버 모듈 참조, 혼합 import, 큰 묶음 경고는 남아 있음. 최종 지연 응답 차단 보강은 별도로 Node 검사와 문법 변환을 통과함.
- 실제 로그인 브라우저의 팝업 클릭·모바일 배치, 실제 업로드·DB·검색 교체는 이 화면 작업에서 확인하지 않음. 외부 AI 호출·병원 자료 전송·실제 저장소 변경은 하지 않음.
- Node가 기본 실행 경로에 없어 Codex 내장 Node 절대 경로를 사용함. 코드 형식 정리는 일반 권한의 경로 제한 오류 뒤 승인된 파일 범위로 실행하여 처리함.
- 이 기록은 테스트 저장소의 로컬 개발 결과이며 운영 반영 또는 기능 전체 완료를 의미하지 않음.

현재 상태·통합 작업일지·문서 화면 재생성은 통합 담당 작업에서 수행함. commit·push·Docker 반영은 하지 않음.

## 독립 검토 후 보강

- 파일을 읽는 중 화면을 닫거나 작업 공간이 바뀌면 이전 업로드 제어기를 영구 폐기함. 이전 확인 응답뿐 아니라 뒤늦게 시작되는 확인 요청도 차단함.
- 개발 모드에서 화면 효과가 정리된 뒤 다시 실행되는 경우에도 새 제어기를 만들어 정상 사용하고, 폐기된 제어기는 재사용하지 않음.
- 문서 목록 조회 실패가 예외가 아닌 반환값으로 전달되는 경우도 실패로 알리도록 보강함. 기존 목록 보존 동작은 유지함.
- 새 재현 검사 3개를 먼저 실패로 확인한 뒤 수정하여 문서 업데이트 검사 총 11개와 변경 파일 5개의 문법 변환을 통과함.
- 서버 담당과 관련 목록 항목의 `title`·`id` 표시 계약을 재확인함. 서버의 현재 교체 지원 대상은 PDF이며 다른 형식이 섞이면 묶음 전체를 거부함.
- 이 추가 검증은 순수 자바스크립트 상태 제어 검사이며 실제 브라우저의 개발 모드·모바일 클릭 검증을 대신하지 않음.
