# 7단계 답변 일관성 — 확인 결과와 구현 기록

아래 기록은 시간순임. 최초 사전 확인 뒤 현재 연결의 seed 요청 거절을 확인하여 활성화하지 않고 관리자 설명·온도 입력 보호를 보완함. 최신 결과는 마지막 절을 읽음.

## 이어받을 지점

- 5단계는 `1ba54e3b`, 6단계 검색 조각 조회는 `a8d8d003`으로 커밋 완료함. push와 운영·Docker 3001 반영은 하지 않음.
- 이번 재확인에서 문서 변경·교체 및 관리자 캐시 검사 25개 통과함. 문서 등록·삭제의 기존 캐시 연결은 5단계 커밋에 포함됨. 문서 업데이트 통합 연결은 현재 미커밋 `server/utils/documentUpdates/` 및 관련 검사에 있으므로 이 기능 전체가 커밋됐다고 해석하면 안 됨.
- 6단계 신규·기존 관리자 검사 38개, Vite build, 문서 화면 검사 11개 및 별도 최종 코드 검토 통과함. 조회 기능만 선별 커밋했고 다른 기능의 미완성 변경은 보존함.
- 기존 실패 2건은 `streamImageContract.node.test.js`의 한 줄 코드 문자열 검사임. `0bcbe0a3`, `1ba54e3b`, 현재 코드에서 같은 2건이 실패함. 실제 조건이 여러 줄로 작성되어 검사 문자열과 맞지 않음. 전체 동작이 무조건 정상이라는 뜻은 아님.

## 7단계에서 확인한 것

- 로컬 workspace 1의 temperature는 0.7임. 관리자 `답변 설정` 고급 설정에 이미 변경 입력이 있으므로 중복 화면을 만들지 않음.
- `server/utils/AiProviders/gemini/index.js`는 Google OpenAI 호환 주소를 사용함. 현재 seed 전달 없음.
- Google 기본 생성 API에는 seed가 문서화되어 있으나 현재 호환 연결·모델에서 실제 적용되는지는 아직 확인하지 못함. 옵션을 받아 준다는 사실만으로 항상 같은 답변을 보장한다고 설명하지 않음.
- Google은 Gemini 3 계열 temperature 1.0 유지를 권장함. 간호 지침이라는 이유만으로 0으로 낮추지 않으며 기존 0.7도 임의 변경하지 않았음.
- 공식 근거: [생성 설정](https://ai.google.dev/api/generate-content), [OpenAI 호환 연결](https://ai.google.dev/gemini-api/docs/openai), [Gemini 3 temperature 안내](https://ai.google.dev/gemini-api/docs/gemini-3#temperature).

## 다음 작업

1. 현재 호환 연결과 모델의 seed 지원을 확정함. 실제 확인은 사용자가 승인한 동일 질문 최대 5회 안에서만 실시하고 자동 재시도를 끔. 병원 자료 대신 합성 질문만 사용함.
2. 지원되면 관리자 seed 사용 여부 저장과 직원 답변 경로에 연결함. 기존 설정 저장소를 사용하며 DB migration은 추가하지 않음. 퀴즈·임베딩 등 다른 기능에는 적용하지 않음.
3. 기존 temperature 입력을 재사용하고 seed의 한계와 권장값을 쉬운 말로 표시함. 설정 변경 때 이전 조건의 캐시 답변을 재사용하지 않도록 `server/utils/chats/answerCache.js`의 조건에 seed 설정을 포함함.
4. 가짜 검사, 관련 회귀 검사, 화면 build, 별도 검토 및 문서 갱신 후 7단계만 선별 커밋함. push 금지.

현재 7단계 코드 수정과 실제 Gemini 호출은 0회임. 승인된 최대 5회가 모두 남아 있음. `.env`·운영 데이터·기존 미완성 변경은 건드리지 않음. 작업 중인 큰 변경이 많으므로 `git add .`을 사용하지 않음.

대화가 길어져 이 지점을 다음 작업의 시작점으로 남김. 다음에는 이 기록을 먼저 읽고 6단계를 다시 만들지 않음.

## 재개: 실제 호환 연결 확인

- 동일 합성 질문으로 실제 요청 3회만 수행함. 병원 자료·개인정보는 전송하지 않았으며 키는 출력·저장하지 않음. 자동 재시도 없음.
- 대상은 현재 설정의 `gemini-3.8-flash`와 기존 Google OpenAI 호환 주소임. temperature 1, 출력 상한 256으로 요청함.

| 요청 | 차이 | 결과 |
| --- | --- | --- |
| 1 | seed 42 포함 | HTTP 400, 답변 없음 |
| 2 | seed만 제외 | HTTP 200, 답변 생성 |
| 3 | seed 42 다시 포함 | HTTP 400, 답변 없음 |

- 오류의 자세한 이유는 응답에서 확인되지 않았음. 비교 결과에 따라 현재 연결에서는 seed를 활성화하지 않음. 모든 Gemini 모델·모든 연결에서 seed를 지원하지 않는다는 뜻은 아님.
- 관리자에게 seed 사용 안 함과 사유를 표시하고 기존 temperature 변경 화면을 보완함. seed만을 위해 연결 방식 전체를 바꾸지는 않음.
- 현재 값 0.7은 유지하며 Gemini 3 공식 권장 1.0을 안내함. 간호 지침의 정확성을 온도만으로 보장하지 않음.
- 실제 확인은 여기서 중단함. 총 3/5회 사용했으며 남은 2회를 추가 실행할 필요는 없음.

## 구현과 검증

- 기존 답변 설정 고급 화면에 현재 온도와 seed 비활성화 사유를 표시함. 현재 검사한 제공자·모델 외에는 지원 미확인으로 안내함.
- temperature 입력의 빈칸·공백·범위 밖 값 저장을 막고, 작업 공간 전환 시 입력을 다시 맞추며 저장 실패 후 재시도가 가능하도록 보완함. 기존 서버 저장 API를 그대로 사용함.
- 신규 화면 6개와 기존 관리자 15개, 총 21개 검사를 주 담당자도 재실행하여 통과함. 실제 API나 DB를 바꾸지 않는 가짜 화면 검사임.
- 서버·프롬프트·검색·캐시·Agent·퀴즈 코드는 이번 단계에서 변경하지 않음. 기존 온도는 이미 캐시 키에 포함되며 seed는 보내지 않으므로 캐시 키를 추가 변경하지 않음.
- 사용 안내: [답변 일관성 설정](../답변_일관성_설정.md).
- Vite build는 26.57초, 종료 코드 0으로 통과함. 기존 Browserslist·음성 라이브러리 외부 모듈·혼합 import·큰 묶음 경고는 남음. 3001을 다시 빌드하거나 브라우저로 검증한 결과는 아님.
- 담당 코드 검토에서 중대·중요·경미 문제 없음. 최종 검토 후 이 단계만 선별 커밋함. 생성 문서 화면은 갱신하되 다른 미커밋 문서까지 섞여 있으므로 통째로 커밋하지 않음.
