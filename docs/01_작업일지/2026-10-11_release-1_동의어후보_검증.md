# release-1 동의어 후보 검증

## 반영 범위

- 일반 문서 등록 뒤 동의어 후보를 순서대로 생성하고 관리자에게 검토 대상으로 보여주는 기능임. 자동 후보는 승인 전 검색에 적용하지 않음.
- 기존 묶음에 추가할 말도 별도 승인 대상으로 보관함. 기존 활성 동의어를 자동 변경하지 않음.
- 새 DB 변경 2개는 후보 출처와 실행 결과용임. 기존 자료를 채우거나 삭제하는 작업은 포함하지 않음.
- 미완성 문서 업데이트와 같은 파일을 쓰는 업로드 연결은 동의어 관련 부분만 따로 선택함. 문서 교체 준비 차단은 유지함.

## 이번 보완

- 후보 생성이 끝날 때까지 문서 등록 응답이 기다리던 문제를 수정함. 문서 내용은 파일 이동 전에 읽되 후보 생성 완료는 기다리지 않음.
- 문서 파일명에 개인정보가 있을 수 있어 Gemini 입력에서 파일명을 제외함. 짧은 본문 줄의 기존 개인정보 필터는 유지함. 임의 문서의 모든 개인정보 제거를 보장하는 기능은 아님.
- 같은 묶음의 추가 후보를 동시에 승인할 때 단어가 사라지지 않도록 후보 조회·묶음 수정·승인 결과 저장을 한 DB 처리로 묶음. 중간 실패 시 변경을 되돌리며 처리 확정 뒤 검색용 임시 기억을 비움.
- 시험 결과 정리 도구가 관리자가 승인하거나 단어를 바꾼 자료를 지우지 않도록 전체 정리를 거절함. 이번 작업에서는 실제 정리 도구를 실행하지 않음.
- 새 판본에서 같은 후보가 발견됐을 때 출처 페이지 번호가 빠지는 문제를 수정함.

## 검증과 한계

- 업로드 지연·파일명 노출·동시 승인·중간 실패·승인 자료 정리·출처 페이지 문제는 합성 검사에서 실패를 확인한 후 수정함.
- 동의어 생성·기존 검색·체크리스트 연결·관리자 API 권한·화면 표시의 Node 검사 39개를 사용함. 최종 실행 결과는 아래 기록을 따름.
- 임시 SQLite에 기존 migration 46개와 합성 자료를 넣은 뒤 새 migration 2개 적용 검사에서 기존 표 구조와 자료가 그대로임을 확인함.
- DB 권한 검사는 실제 인증/역할 검사 코드를 사용하지만 서버 HTTP 및 실제 브라우저 클릭 시험은 아님. 동시 승인 검사는 메모리 DB의 직렬 처리·롤백 모형이며 실제 Prisma 동시 접속 시험은 별도 필요함.
- 운영 DB·기존 3001/3002/3003 변경 또는 재시작, 실제 Gemini 호출, push는 하지 않음.
- 이 기능을 배포할 때 새 migration 적용과 Prisma client 생성이 필요함. 자동 후보 생성은 Gemini 사용량을 소비하며 `SCHAT_SYNONYM_SUGGESTIONS=off`로 끌 수 있음. backfill의 dry-run도 실제 모델 호출을 할 수 있으므로 무비용 시험으로 사용하지 않음.

## 직접 확인할 순서

1. 추후 새 코드와 migration을 적용한 확인 환경에서 관리자 → 동의어 관리 → 검토 필요를 확인함. 현재 3001/3002/3003에 적용했다는 뜻은 아님.
2. 합성 문서 등록 후 후보 출처·페이지·실행 결과를 확인하고 필요한 후보만 승인함.
3. 승인 전에는 검색에 반영되지 않고 승인 후에만 반영되는지 확인함. 실제 호출은 별도 누적 한도 안에서 수행해야 함.
