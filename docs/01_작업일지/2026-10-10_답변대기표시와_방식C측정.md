# 답변 대기 표시와 방식 C 측정

## 결정

- 방식 C(추가 검색 횟수 제한, `SCHAT_AGENT_RESEARCH_MODE=bounded`)는 켜지 않음. 기본값(꺼짐)을 유지함.
- 답변 대기 화면은 A안으로 정함. 20초가 지나도 끊지 않고 안내만 하며, 70초가 되면 자동으로 멈춤.

## 방식 C 측정 결과 (로컬 Docker 3001, 질문 7개 × 꺼짐/켜짐 × 3회)

측정은 임시 계정으로 새 대화방에서 진행했고, 측정 후 임시 계정과 그 대화 기록을 삭제함. 운영 서버는 보거나 바꾸지 않음.

- 켜면 빨라지지만, 답을 못 찾았다고 말하는 경우가 2/21에서 11/21로 늘어남. 특히 AST 질문 6번이 모두 "확인되지 않습니다"가 됨.
- 꺼짐 상태에서 AST 질문이 오래 걸리는 이유는 첫 검색에 답이 있는 쪽(p.260~262)이 들어오지 않아, AI가 4~10번 더 검색하기 때문임.
- 같은 세프트리악손 질문에도 "AST 대상", "과민반응 과거력에 따라 결정", "확인되지 않습니다"로 답이 달라짐. 근본 원인은 아래 "첫 검색 조사"에 기록함.

## 답변 대기 화면 (A안)

- 진행 문구: "문서를 찾는 중…", "문서를 한 번 더 찾는 중…", "답변을 작성하는 중…"을 표시함. 경과 초는 화면에 보이지 않게 함(사용자 요청). 시간은 안에서만 세어 20초 안내와 70초 자동 멈춤에 사용함.
- 20초가 지나면 "답변이 오래 걸리고 있습니다. 조금만 더 기다려 주세요."를 추가로 표시하고 계속 기다림.
- [멈추기] 버튼은 처음부터 보임. 누르면 "답변을 멈췄습니다."와 [다시 시도]를 표시함.
- 70초가 되면 자동으로 멈추고 "응답이 늦어지고 있습니다. 잠시 후 다시 시도해 주세요."와 [다시 시도]를 표시함.
- 멈춘 질문은 빈 답변 칸으로 남지 않음. 서버가 답변 전에 미리 만든 빈 기록(`response "{}"`)을 멈출 때 지움. 이미 답이 저장된 기록은 지우지 않도록 조건을 걸었음.
- 바꾼 파일: `frontend/src/utils/schatWaitingStatus.js`(새 파일), `StatusResponse/index.jsx`, `ChatHistory/index.jsx`, `server/utils/agents/aibitat/plugins/chat-history.js`, 관련 테스트 3개.

## 첫 검색에 p.260~262가 안 들어오는 원인 (조사만, 수정 안 함)

- p.260은 "과민반응 과거력 및 Skin test 결과에 따른 항생제 사용 권고", p.261~262는 "항생제 Skin test용 희석 용매" 표, p.263은 "AST 투약 절차"임.
- "세프트리악손 AST 해야 해?"의 의미 검색 순위: p.262 3위, p.261 4·5·8위, p.260 10위. 단어 검색(BM25) 순위: p.262 5위, p.260 그림 6·7위, p.261 8위. 합친 순위에서도 p.262 4위, p.261 5·6위였음.
- 그런데 마지막 걸러내기(`filterWeakHybridTail`)에서 빠짐. 질문 단어 3개(세프트리악손, AST, 해야) 중 1개만 들어 있고, 의미 점수가 0.57~0.62로 기준 0.7보다 낮으며, 조각 안에 "AST"라는 글자가 없기 때문임. "AST"가 들어 있는 p.263·264·334가 대신 남음.
- p.261~262 조각에는 세프트리악손/Ceftriaxone이 있고, p.260 조각에는 AST·세팔로스포린 또는 Skin test가 있음. 같은 검사를 문서에서 "AST"와 "Skin test" 두 가지로 부름.
- 해결 후보:
  - A(추천): 질문의 구체적 대상어(예: 약 이름)가 들어 있고 의미 순위 상위인 조각은 걸러내지 않음. 검색 코드 변경이라 승인과 회귀검사가 필요함. 다른 질문에서 참고 조각·출처가 조금 늘 수 있음.
  - B: "해야/하나요/필요해" 같은 요청 말을 내용 단어에서 빼고, AST↔Skin test 동의어를 추가함. p.262 이어지는 조각에는 두 단어가 모두 없어 효과가 제한적임.
  - C: 표가 다음 쪽으로 이어지는 조각에 소제목을 붙여 다시 색인함. 재색인이 필요해 장기 과제임.

## 검증

- 이 PC의 Docker 3001 화면에서 실제 브라우저로 진행 문구, 20초 안내, [멈추기], [다시 시도] 후 답변 표시를 확인함.
- 70초 자동 멈춤은 확인용 브라우저의 시계만 4배 빠르게 해서 확인함. 프로그램 코드는 바꾸지 않음. 69초까지 기다린 뒤 자동 멈춤 문구와 [다시 시도]가 표시됨.
- 멈춘 질문 뒤 DB에 빈 답변 기록이 남지 않았음을 확인함.
- 화면 테스트 168/168 통과. Docker 안 서버 테스트 376개 중 375개 통과함. 실패 1개는 이번에 고치지 않은 그림 질문 걸러내기 테스트(`imageRequest.node.test.js`)이며 따로 확인이 필요함.
- 방식 C 설정은 측정 뒤 꺼진 상태로 되돌린 것을 확인함.
- 운영 서버, 검색 설정, 프롬프트, ChromaDB, 등록 PDF는 바꾸지 않음. commit·push를 하지 않음.
