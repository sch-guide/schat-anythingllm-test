# 출처 원문 파란색 하이라이트 UI — 2026-10-10

## 요청과 범위

출처 원문의 빨간 박스를 제거하고 답변에 실제 사용된 직접 근거만 연한 파란색으로 표시한다. 검색 후보·단순 참고 자료·근거 미확정 답변은 강조하지 않는다. 기존 Citation 선택과 개수, 직원 페이지 번호 숨김, PDF 페이지 이동, source metadata를 유지한다. RAG·검색·답변 생성·체크리스트·동의어·관리자 코드는 이번 작업에서 수정하지 않았다. 기존 작업의 미커밋 변경은 그대로 보존했다.

## 구현

- PC 임시 PDF: 빨간 Ink 테두리를 Highlight 주석으로 바꾸었다. 색상 #60A5FA, 불투명도 22%, 테두리 없음, 기존 글자색 유지.
- 모바일: 같은 색상과 불투명도로 실제 PDF 텍스트 좌표를 채운다. 원래 확대·스크롤·화면 배율 처리를 유지한다.
- 기존 직접 근거 판정(evidenceQuotes 우선, 정확한 문장 일치 보완)과 일치 검사 조건은 변경하지 않았다. 표시할 직접 근거를 확정하지 못하면 기존 원문 안내를 유지한다.
- 페이지 이동에 사용하는 기존 rects는 유지하고, 실제 칠할 텍스트 조각 좌표 paintRects를 별도로 전달한다. 떨어진 문장·표의 칸을 큰 박스로 묶지 않는다. 연속 문단도 글자가 있는 각 줄만 칠한다.
- 표시 성공 때만 작은 안내 “파란색 표시 = 답변에 사용된 근거”를 표시한다.
- 표의 정확히 일치한 텍스트 칸은 각각 강조한다. 이미지의 신뢰할 수 있는 부분 좌표를 새로 추출하는 기능은 추가하지 않았다. 이미지 전체나 페이지 전체를 임의로 칠하지 않는다.

## 검증 결과

- 관련 자동 검사 36개 통과. 직접 근거/참고 자료 구분, 여러 근거와 중간 미사용 문장 제외, 직원 페이지 숨김, 원본 metadata 보존을 확인했다.
- PDF 저장·재열기: 파란 Highlight 주석, 22% 불투명도, 원본 PDF 바이트 보존과 글자 보존 확인. 네 방향 회전(0/90/180/270도) 및 모바일 여섯 확대 배율에서 좌표 왕복 검증을 통과했다.
- 합성 PDF를 이미지로 렌더링하여 PC용 PDF에서 파란 배경·검은 글자 가독성·테두리 제거·표 칸 사이 빈 공간 유지를 확인했다.
- 사용자 수혈 예시를 합성 문서로 만들었다. ‘수혈 시 주의사항’, ‘환자 상태 확인 및 간호기록’, ‘RBC 수혈 기록 입력’ 세 근거만 강조하고, 위의 환자확인 및 중간·아래 미사용 문장은 일반 배경임을 확인했다.
- ESLint 및 화면 빌드 통과. 로컬 컨테이너에 화면 파일만 반영했다. 서버 코드 복사·재시작·DB 변경은 하지 않았다. 실행 중 index.js와 빌드 파일 해시 일치 및 예시 PDF의 PDF 서명과 Highlight 주석 3개를 확인했다.
- 연결된 브라우저가 없어 실제 Citation 클릭 및 PC 뷰어 조작은 미확인이다. 실제 휴대폰 육안 검증 및 실제 병원 PDF 검증도 미실시다. 모바일은 자동 좌표 검사까지 확인했다.
- 신규 자동 검사 실패 없음. 외부 AI 호출·실제 병원 자료 전송·commit/push/tag 없음.

## 확인 방법과 다음 할 일

로컬 SCHAT을 Ctrl+F5로 새로고침한다. 합성 예시: http://localhost:3001/schat-blue-highlight-test.pdf?blue=1

직접 근거가 저장된 답변의 출처를 열면 새 표시를 볼 수 있다. 이 UI 변경은 과거 답변의 근거를 새로 생성하거나 위치 찾기 실패를 강제로 표시하지 않는다. 실제 직원 화면의 Citation 클릭과 휴대폰 확대·스크롤은 다음 육안 확인 대상으로 남는다.


## 후속 요청: 안내 숨김과 기본 배율

- 사용자의 요청으로 위치 미확정 안내와 파란색 표시 의미 안내를 PC·모바일 원문 화면에서 제거했다. 내부 일치 판정과 실패 시 원문 제공은 유지한다.
- 근거가 있는 PC PDF에만 적용되던 강제 100% 확대를 제거했다. 일반 원문과 같은 화면 너비 맞춤(FitH)으로 열고 기존 페이지 및 근거의 세로 위치 이동은 유지한다. 모바일의 기본 너비 맞춤과 수동 확대는 그대로다.
- 페이지 이동 URL 검사를 새 기대값으로 바꾼 뒤 기존 강제 확대에서 실패함을 먼저 확인했다. 변경 뒤 관련 36개 검사가 통과했다. 첫 ESLint 검사에서 줄바꿈 형식 오류가 발생하여 지정 파일을 정리한 후 재검사를 통과했다. 실제 브라우저 확대 표시의 육안 검증은 미실시다.
- commit/push/tag 및 외부 AI 호출 없음.

- 후속 화면 빌드 통과 및 로컬 3001 화면 반영 완료. 실행 화면 파일과 빌드 해시 일치를 확인했다.


## 후속 요청: 양쪽 회색 여백 줄이기

기본 뷰어가 FitH 설정에도 양쪽 회색 공간을 남긴 사용자 화면을 확인했다. PC 원문 iframe의 실제 폭과 회전이 적용된 PDF 페이지 폭으로 기본 배율을 계산한다. PDF 점 단위와 브라우저 CSS 픽셀의 96/72 비율을 반영하고 스크롤바 공간 24px를 남긴다. ResizeObserver로 창 폭 변화에 다시 맞춘다. 페이지와 근거의 세로 위치 이동을 유지하며 가로 이동은 0으로 시작한다. PDF 내부 흰 여백은 자르지 않는다. 모바일의 기존 화면 너비 맞춤은 유지한다.

배율 URL 검사는 변경 전 실패함을 확인했다. 실제 Edge/Chrome에서 보이는 여백의 최종 육안 검증은 아직 하지 못했으며 브라우저별 기본 PDF 뷰어의 해석 차이는 남을 수 있다. 이번 변경도 commit/push/tag 없이 진행한다.

- 가로 폭 맞춤 변경: 관련 자동 검사 36개, ESLint, 화면 빌드 통과. 로컬 3001에 반영하고 실행 화면 파일과 빌드 해시 일치를 확인했다. 문서 검사 11개 통과.
