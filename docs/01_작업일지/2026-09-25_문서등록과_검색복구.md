# 문서 등록 누락과 검색 품질 복구

## 왜 답변 품질이 떨어졌나

큰 PDF를 올린 뒤 화면이 문서 목록의 앞 100건을 다시 읽어 선택하고 있었습니다. 이 때문에 PDF 처리는 끝났어도 workspace에는 일부 페이지만 등록될 수 있었고, 질문에 필요한 페이지가 검색 대상에 없었습니다.

색인을 복구한 뒤에는 일반적인 `종류`·`목적` 질문이 더 좁은 하위 항목을 먼저 고르는 문제가 남았습니다. 예를 들어 전체 주제의 목적을 물었는데 그 주제 안의 특정 검사 목적이 먼저 선택되는 형태였습니다.

## 변경한 내용

1. 업로드 서버가 실제 처리한 상대 문서 경로만 반환하도록 했습니다.
2. 화면은 해당 경로의 정확한 batch만 선택하며, 목록 첫 100건이나 폴더 전체를 다시 추정하지 않습니다.
3. 조회 실패나 일부 누락을 성공처럼 넘기지 않도록 했습니다.
4. 띄어 쓴 질문과 붙여 쓴 질문을 같은 토큰으로 처리합니다.
5. 일반 절차 질문에서는 예시·CICARE 자료를 제외하고 공개 근거 중복을 제거합니다.
6. 넓은 `종류`·`목적` 질문은 장 단위 직접 근거를 우선하되, 질문에 하위 범위를 명시하면 그 항목을 선택합니다.
7. 안전한 복구 도구와 회귀 검사를 추가했습니다.

검색 모델, Gemini Embedding 2, ChromaDB, BM25 가중치, closed-book 원칙과 structured 답변 경로는 바꾸지 않았습니다.

## 질문별 로컬 검색 확인

Gemini 답변 생성 없이 현재 live 색인에서 근거 선택만 확인했습니다.

- FPRS: p.100 중심 근거와 연결된 이미지 설명
- 수혈 종류 / 수혈종류: 같은 토큰과 같은 p.113·114 근거
- 수혈 절차: p.117·124
- 수혈 목적: p.113
- 진정 목적: p.159
- 진정절차: p.160·161·163

실제 Gemini 답변 7건은 병원 근거의 외부 전송 범위를 구체적으로 승인받지 않은 상태라 실행하지 않았습니다. 따라서 실제 답변 성공으로 기록하지 않습니다.
