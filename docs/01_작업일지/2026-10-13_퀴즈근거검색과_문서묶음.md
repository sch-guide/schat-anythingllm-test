# 퀴즈 근거 검색과 문서 단위 조회

## 확인과 원인

- 사용자 서버 a49bce94에서 실무지침서_중심정맥관.pdf(15쪽), 주제 중심정맥관으로 근거 없음 안내 발생. 서버에 직접 접속하지 않음.
- 오류는 Gemini 호출 전 collectEvidence의 빈 결과에서 발생함. 원본 PDF 열림과 검색 본문 연결은 별도 경로임.
- Chroma 등록의 캐시 재사용 분기는 새 문단 번호를 만들지만 내부 metadata.document_id는 예전 값을 유지할 수 있음. 퀴즈는 PDF 번호만 조건으로 조회하여 이 경우 등록 본문이 있어도 빈 결과가 됨. 가짜 재업로드 자료로 실패를 재현함. 실제 서버 원인 확정과 구분함.
- 답변 근거 보기의 목록은 등록된 쪽마다 한 줄을 반환하므로 PDF 한 개가 여러 선택 항목으로 나타났음.

## 수정

- 퀴즈 등록 문서 목록에 같은 작업공간의 쪽별 등록 번호를 보관하고, 문제 생성·재생성 때 현재 document_vectors 연결을 따라 검색 본문을 읽음. 이전 번호로 다른 자료를 임의로 찾지 않음.
- 근거 문서 목록은 PDF 번호·버전·이전 자료 상태가 같은 쪽들을 묶음. 같은 이름만으로 합치지 않음. 목록 이동은 묶음 기준이며, 본문은 등록된 쪽 순서로 조회하고 조회 도중 등록이 바뀌면 다시 조회하도록 안내함.
- 쪽마다 등록 시각이 나열되던 선택창을 문서명·전체 쪽수로 단순화함.

## 검사

- 신규 재업로드 재현: 수정 전 빈 결과 실패 → 수정 후 해당 쪽 조회 통과.
- 외부망 차단·실제 storage 미연결 임시 Docker: 퀴즈 17개 통과. 가짜 한도 오류와 임시 암호화 초기화 출력은 시험 환경 출력이며 실제 Gemini 호출 없음.
- 근거 조회 및 화면 검사 24개 통과. PDF 묶음·이전 버전 분리·쪽순서·조회 중 변경·부서 범위 검사 포함.
- 기존 미커밋 변경 보존. DB 구조 변경·자료 삭제·commit/push 없음.

## 남은 확인

- 실제 서버에서 현재 등록 문단 연결과 검색 자료의 문서 번호가 다른지 읽기 전용 진단 필요. 이 수정으로 해당 경로는 막았으나 서버 사건 원인을 확정했다고 하지 않음.
- 3001과 운영 서버에는 아직 이 변경을 반영하지 않음. 실제 브라우저·서버 문제 생성 확인은 미실시.
