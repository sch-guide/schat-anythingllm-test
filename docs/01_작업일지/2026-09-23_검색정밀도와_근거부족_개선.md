# 검색 정밀도와 근거 부족 처리 개선

## 왜 바꿨나

- `수혈 종류`처럼 범위가 분명한 질문에도 수혈 목적·동의서·확인 절차가 함께 표시됐습니다.
- 등록 자료에 `비터널형`이라는 말이 없는데 비슷한 카테터 문서를 억지로 근거로 사용했습니다.
- 안전검사에 실패하면 여러 큰 원문 청크가 그대로 이어져 직원이 읽기 어려웠습니다.
- 기존 색인의 항목명 정보가 비어 있어 `혈액제제 종류`와 `수혈 절차`를 구분하기 어려웠습니다.

## 이번에 준비한 개선

- 질문에서 조사와 요청 표현을 제외하고 병원 핵심어를 비교합니다.
- 의미 점수가 낮고 정확 핵심어도 부족한 결과는 직원 답변 근거로 사용하지 않습니다.
- 관련 근거가 한 개면 한 개만 사용하며, 약한 결과로 개수를 채우지 않습니다.
- 원본에 있는 항목명을 우선 보존하고 번호 제목·마크다운 제목·독립된 짧은 제목처럼 실제 문서에 적힌 제목만 항목명으로 저장합니다.
- 안전검사 실패 시 전체 검색 결과에서 질문과 가장 직접적으로 맞는 원문 문장만 안전 답변으로 표시합니다.
- 문서 관리 태그, 내부 식별자, SVG 코드와 `svg` 임시 문자열은 직원 답변에서 제거합니다. 정상 이미지 표시는 유지합니다.
- 기존 Python 안전검사의 숫자·단위·시간·조건·금기·행위 검사는 완화하지 않았습니다.

## 자동검사 결과

- 검색·항목명·표시 관련 독립 검사 31건 통과
- Python 안전검사 서비스 검사 18건 통과
- 직원 이미지 입력 검사 3건 통과
- 변경한 자바스크립트 문법 검사 통과
- Python 코드 검사 통과
- Git 공백 오류 검사 통과

## 재색인 전 현재 상태

- 현재 직원 작업공간에는 논리 문서 1개가 페이지 자료 100건으로 등록돼 있습니다.
- 현재 검색 청크는 116개입니다.
- 새 청크 크기는 기존 개선값인 약 900자, 겹침 약 120자를 유지하므로 예상 새 청크도 116개입니다.
- 원본 토큰 추정치는 52,955개이며 겹침을 포함한 임베딩 입력은 약 55,000토큰으로 예상합니다.
- 페이지별 등록 구조 때문에 Gemini 임베딩 요청은 약 100회, 입력 묶음은 총 116개로 예상합니다.
- 저장소 단가표의 100만 토큰당 약 0.20달러를 적용하고 1달러를 약 1,400원으로 계산하면 약 15원입니다. 실제 청구와 환율에 따라 달라질 수 있습니다.

## 왜 아직 재색인하지 않았나

재색인은 기존 병원 문서 내용을 Gemini 임베딩 서비스에 다시 보내고 현재 ChromaDB 검색 데이터를 바꾸는 작업입니다. 사용자의 사전 승인 전에는 기존 데이터를 삭제하거나 외부 호출을 하지 않는 조건이므로, 코드와 가짜 데이터 검증까지만 완료하고 멈췄습니다.
