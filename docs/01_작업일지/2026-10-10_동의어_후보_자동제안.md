# 동의어 후보 자동 제안

## 목표

- 문서 등록 → 동의어 후보 자동 생성 → `검토 필요` → 관리자 확인 → `사용` 승인 → 검색 적용 흐름을 만듦.
- AI가 만든 후보는 승인 전에는 검색과 체크리스트 연결에 쓰지 않음.

## 바꾼 내용

- 문서를 등록하면 등록이 끝난 뒤 뒤에서(업로드 응답을 기다리게 하지 않고) 동의어 후보를 만듦. 일반 업로드, 업로드 후 바로 등록, 문서 새 버전 등록 3곳에 연결함.
- AI 입력은 쪽마다 제목 줄(최대 3줄)과 영문·약어가 섞인 짧은 줄(최대 6줄, 60자 이하)만 사용함. 모든 쪽에 반복되는 머리글은 빼고, 문서 하나에 최대 6번(한 번에 6,000자 이하)만 보냄.
- 사람 이름(교수님·선생님 등 호칭이 있는 줄), 전화번호·☎·내선, 주민번호, 사번·긴 숫자, 병실·호실, 이메일이 있는 줄은 AI 입력에서 뺌.
- 현재 SCHAT의 Gemini(답변과 같은 설정)를 그대로 쓰고, 정해진 JSON 형식(단어, 분류, 확신도, 이유, 쪽)으로 받음. 새 AI 공급자를 추가하지 않음.
- 받은 후보는 다시 검사함. 보낸 줄에 글자 그대로 없는 단어, 개인정보처럼 보이는 단어, 확신도 0.5 미만, 삽입·제거가 섞인 묶음은 버림. 확신도 0.7 미만은 `낮은 확신`으로 표시함.
- 기존 묶음과 비교함. 대소문자·띄어쓰기·순서만 다르면 만들지 않음. 기존 묶음 하나에 새 단어만 있으면 그 단어만 `추가 후보`로 남기고 기존 묶음은 바꾸지 않음. 두 묶음 이상과 겹치면 애매하므로 만들지 않음.
- 같은 문서의 새 버전에서 같은 후보가 나오면 새로 만들지 않고 출처에 새 문서만 더함. 관리자가 거절하거나 지운 후보는 다시 제안하지 않음.
- 출처 기록용 새 표 `schat_synonym_suggestions`를 추가함. 기존 동의어 표는 구조를 바꾸지 않음. 문서 번호, 문서명, 쪽, 생성 시각, 생성 방식, 확신도, 이유를 저장함. 보낸 원문 줄과 AI 응답 원문은 저장하지 않음.
- 실패해도 문서 등록은 그대로 성공함. 시스템 기록에 `동의어 후보 자동 생성 실패`와 실패 종류만 남김.
- 끄는 스위치를 둠: 서버 설정 `SCHAT_SYNONYM_SUGGESTIONS=off`.

## 관리자 화면

- 기존 `전체 / 검토 필요 / 사용 / 끔` 구조를 그대로 둠. 자동 후보는 모두 `검토 필요`로 들어옴.
- 묶음마다 `직접 등록 / 초안 / 자동 제안` 배지를 보여 줌.
- 자동 제안에는 분류, 출처 문서와 쪽, 근거, 확신도, 생성 시각을 보여 줌. 쪽 번호는 관리자 화면에만 있고 직원 화면에는 보이지 않음.
- 기존 묶음에 넣을 단어는 그 묶음 아래 `추가 후보`로 보여 주고 [추가 승인] [거절]을 둠. 추가 후보가 있는 묶음은 `검토 필요` 목록에도 나옴.
- 출처 문서가 모두 삭제된 `검토 필요` 후보는 자동으로 지우지 않고 `출처 없음`으로 표시함. 이미 승인된 동의어는 문서를 지워도 그대로 둠.

## 실제 문서 확인 (로컬 Docker 3001)

- 등록된 `검사 및 시술(26.04.07).pdf` 82쪽을 읽기만 해서 후보를 만듦. 문서·검색 데이터는 바꾸지 않음.
- Gemini 호출 4번, 약 92초. 보낸 줄 634개, 20,514자(쪽 본문 49,020자의 약 42%).
- 보낸 글을 다시 검사해 전화번호·주민번호·☎·호칭·병실·긴 숫자가 0건임을 확인함.
- 결과: 새 묶음 후보 58개, 추가 후보 6개, 기존과 같아 만들지 않은 후보 3개. 모두 `검토 필요`였음.
- 기관지내시경 예시: 기존 `기관지내시경, bronchoscopy, BFS`(사용)는 새로 만들지 않고 `Bronchofiberscopy`만 추가 후보로 나옴.
- 관리자 화면에서 `검토 필요 64`, 자동 제안 배지·출처·근거를 확인함. [추가 승인] 후 그 단어가 검색 확장에 들어가고, 승인하지 않은 후보(예: PICC)는 검색에 쓰이지 않음을 확인함.
- 관리자가 거절해야 할 만한 후보도 있었음. 예: `혈관조영술`에 `Venogram`(정맥조영술, 더 좁은 개념)을 더하자는 후보, `디지털감산뇌혈관조영술 = TFCA`처럼 검사 방식이 다를 수 있는 후보. PDF 글자에 띄어쓰기가 없어 `Computedtomography`처럼 붙은 영문이 그대로 나옴. 그래서 반드시 사람이 확인한 뒤 사용해야 함.
- 확인 후 자동 후보 58개와 출처 기록 64개를 지우고, 승인 확인으로 바뀐 5번 묶음을 되돌림. 기존 동의어 23개(사용 17, 끔 6)의 내용 지문이 확인 전과 같음(`cd45992c7fa716e0`). 임시 관리자 계정도 삭제함.

## 검증

- 새 서버 테스트 16개: 후보 생성, 모두 검토 필요, 승인 전 검색 미사용, 승인 후 검색 적용, 체크리스트 이름 승인 후에만 적용, 완전 중복 미생성, 새 단어만 추가 후보, 애매한 후보 미저장, Gemini 실패 시 등록 유지, 새 버전 중복 미생성, 개인정보 미전송, 기존 묶음 미변경, 출처 없음 표시, 끄는 스위치.
- 새 화면 테스트 4개 통과. 기존 동의어 테스트 4개 통과.
- Docker 안 서버 테스트 436개 중 434개 통과. 실패 2개는 기존 그림 질문 테스트와 다른 작업의 새 테스트(Docker의 Node 18에 없는 `node:sqlite` 사용)임.
- 화면 테스트 201개 중 198개 통과. 실패 3개는 다른 작업 창이 수정 중인 출처(PDF)·문서 목록 화면 테스트임.
- BM25·Vector·Hybrid 75:25·ChromaDB·Gemini 답변·Citation·체크리스트 추출과 공개 코드는 바꾸지 않음. 검색은 전과 같이 `사용` 묶음만 읽음.
- 실제 파일 업로드로 자동 실행되는 것은 검색 데이터가 바뀌므로 하지 않았음. 업로드 연결은 코드와 테스트로 확인함.
- 운영 서버는 바꾸지 않음. commit·push·tag를 하지 않음.

## 2부: 순차 처리, 재시도, 기존 문서 한 번 실행

### 바꾼 내용

- 동의어 후보는 Gemini 호출을 포함해 한 문서씩 차례로 처리함. 문서 여러 개가 동시에 등록돼도 호출이 몰리지 않음.
- 호출 한도(429)나 일시 장애(503)가 나면 15초, 30초, 60초 기다린 뒤 다시 시도함. 최대 3번까지만 재시도하고, 그래도 안 되면 그 문서를 실패로 표시하고 나머지 문서는 `중단(호출 한도)`으로 표시함. 다시 실행해도 중복이 생기지 않음.
- 문서 하나에 보낼 수 있는 양을 Gemini 6번에서 30번으로 늘림. 461쪽 실무지침서도 줄이 빠지지 않음.
- 쪽당 글자가 50자 미만이거나 고를 수 있는 줄이 3개 미만인 문서는 Gemini를 부르지 않고 `텍스트 부족`으로 표시함(예: 그림 위주의 `3-3. 중심정맥관`, `3-4. 의약품관리`).
- 이미 등록된 문서용 한 번 실행 도구 `server/scripts/schatSynonymSuggestionBackfill.js`를 추가함. 저장된 쪽 JSON만 읽고 검색 데이터를 다시 만들지 않음.
  - `--test`: 검증용 실행. 만든 후보에 실행 번호를 붙이고, 이전부터 있던 후보의 출처는 바꾸지 않음.
  - `--remove-test-run <번호>`: 그 검증용 실행이 만든 후보만 지움. 검증용이 아닌 실행은 지울 수 없음.
  - `--dry-run`: 아무것도 저장하지 않고 결과만 보여 줌.
- 실행 결과를 새 표 `schat_synonym_suggestion_runs`에 저장함(문서 이름·쪽 수·개수·상태만, 본문 없음). 후보 표에 실행 번호 칸을 더함.
- 관리자 동의어 관리 화면에 `자동 생성 결과` 카드를 추가함. 대상 문서, 전체 후보, 새 묶음, 추가 후보, 중복 제외, 애매해서 제외, 텍스트 부족, 실패, Gemini 호출, 재시도와 문서별 후보 수·상태, 실패한 문서를 보여 줌. 검증용 실행의 후보에는 `검증용` 배지를 붙임.

### 로컬 Docker 3001 실행 결과 (검증용 실행 #1)

- 운영 서버 문서 21개는 이 PC에 없어서, 로컬에 등록된 문서 4개로 실행함. 실무지침서 461쪽 한 권에 운영 서버의 장별 문서 내용이 담겨 있음. 운영 서버는 실행하지 않음.
- 4개 모두 성공, 실패 0, 텍스트 부족 0, Gemini 호출 23번, 재시도 0번, 약 332초.
- 전체 후보 186개: 새 묶음 167개, 추가 후보 9개, 중복 제외 10개. 모두 `검토 필요`이며 자동으로 `사용`이 된 것은 0개.

- 실행 전에 이미 실제 업로드로 생긴 후보 3개가 있었음. 오늘 19:40 로컬 3001에 `실무지침서_진정간호(8.10).pdf`가 등록되면서 자동으로 만들어진 것으로, 업로드 연결이 실제로 작동함을 보여 줌. 이 3개는 검증용이 아니므로 그대로 두었고, 검증용 실행은 이 후보의 출처를 바꾸지 않음.

### 검증

- 텍스트 부족 판정은 로컬에 해당 문서가 없어 테스트로만 확인함.
