# 체크리스트 세부 줄 체크박스, 동의어 사전, 자동 생성 체크리스트

## 1. 세부 줄 체크박스

### 원래 상태

- 직원 체크리스트 창은 원래도 "체크" 항목의 세부 줄마다 체크박스를 보여 주었습니다.
  - 다만 규칙으로 자동 결정했습니다.
  - "※"로 시작하거나 괄호만 있는 줄은 체크박스 없이 참고 줄로 보였습니다.
- 관리자가 줄마다 체크박스를 정할 방법은 없었습니다.

### 바꾼 것

- **관리자 수정 창**
  - 세부 내용을 줄 단위로 고칩니다.
  - 줄마다 "체크" 켜기/끄기, 줄 추가·삭제·위아래 이동을 할 수 있습니다.
- **직원 화면 미리보기**
  - 수정 창의 "직원 화면 미리보기" 버튼을 누르면 실제 직원 창과 같은 모양이 나옵니다.
  - 미리보기에서 체크해도 저장되지 않습니다.
- **직원 화면**
  - 줄마다 따로 체크됩니다.
  - 체크 상태는 체크리스트 창이 열려 있는 동안 본인 브라우저에만 있고, 서버·DB나 브라우저 저장소에 저장하지 않습니다.
- **저장 형식**
  - 줄별 설정은 체크리스트 파일의 항목에 `detailCheckable`(줄마다 참/거짓) 칸으로 저장됩니다.
  - 이 칸이 없는 **기존 체크리스트는 예전 규칙 그대로** 보입니다. 자동으로 바꾸지 않았습니다.
- **관리자 수정 보호**
  - 관리자가 수정한 체크리스트는 문서를 다시 올려 자동 추출이 돌아도 덮어쓰지 않습니다(기존 보호 규칙 유지).
- 관리자 "체크리스트 보기" 창은 예전 결정대로 원래 모양을 유지합니다.

### 확인

- **실제 브라우저로 확인한 흐름**
  - p.60 동의서의 ② 줄 체크를 끄고 ③ 줄을 추가했습니다.
  - 미리보기에서 ②는 참고 줄, ③은 체크박스 줄로 나왔습니다.
  - 저장한 뒤 직원 창에서 ①만 따로 체크됐습니다.
  - 확인 후 파일은 원래대로 되돌렸습니다.

## 2. 동의어 사전

### 원인

- 지침서 p.59에는 "투석관", "HD Catheter Insertion"만 있습니다. 그래서 "카테터"(한글), "cath"로 물으면 단어 일치 검색에서 걸리지 않았습니다.

### 바꾼 것

- **관리자 화면**
  - `SCHAT 관리자 설정 > 동의어 관리`에서 같은 뜻의 단어를 묶습니다.
  - 상태는 검토 필요 / 사용 / 끔이고, 종류는 시술·기구 / 약물입니다.
- **적용 범위**
  - **사용** 상태 묶음만 적용됩니다.
  - 질문 단어를 같은 묶음의 단어로 넓혀 단어 일치 검색(BM25)에 씁니다. Gemini는 호출하지 않습니다.
  - 한 묶음은 질문의 한 단어로 세므로, 동의어가 없는 질문은 결과가 전과 같습니다.
  - 체크리스트를 찾는 이름에도 적용됩니다(예: "HD 카테터" → "HD cath").
- **삽입/제거 구분**
  - 삽입 계열(삽입·거치·설치·insertion)과 제거 계열(제거·발거·remove) 단어는 한 묶음에 넣을 수 없습니다.
  - 흔히 부르는 이름이나 동의어로만 찾은 체크리스트는, 질문이 반대 동작이면 나오지 않습니다(예: "HD 카테터 제거"에 삽입술 체크리스트 안 뜸).
- **초안 23개**
  - 지침서에 자주 나오는 시술·기구 이름을 "검토 필요" 상태로 한 번만 넣었습니다. 켜야 적용됩니다.
  - 약물은 넣지 않았고, 약물 묶음은 관리자가 직접 넣은 것만 쓰입니다.
- **DB:** 새 표 `schat_synonym_groups`를 Prisma migration `20260929000000_schat_synonym_groups`로 추가했습니다. 기존 표는 바꾸지 않았습니다.
- **백업:** migration 전 DB 백업을 `workspace/db_backup/anythingllm-20260929-0836-before-synonyms.db`에 두었습니다.

## 3. 문서 등록 시 체크리스트

- **예전:** 문서를 올리면 체크리스트가 자동으로 만들어지고, 원문 자동 대조를 통과한 것은 **바로 공개**됐습니다.
- **이제:** 새로 만들어지거나 내용이 바뀐 자동 체크리스트는 **항상 "검토 필요"**로 들어갑니다.
  - 원문 대조 통과 여부는 따로 기록해 관리자 화면에 이유로 보여줍니다.
  - 같은 문서로 다시 추출했는데 내용이 같으면 지금 상태를 그대로 둡니다.
- **문서를 새 버전으로 교체하면**
  - 새 파일은 새 문서 번호를 받으므로 체크리스트가 새로 만들어지고 모두 "검토 필요"입니다.
  - 옛 버전에서 공개·수정한 체크리스트는 옛 문서 번호에 남습니다. 옛 문서를 작업공간에서 빼면 화면에서도 사라집니다.
  - 관리자 수정 내용은 새 버전으로 자동으로 옮겨지지 않습니다.

## 서버 배포 시 체크리스트 파일

- 새 칸(`detailCheckable`, `autoVerified`, `statusSetByAdmin`)은 **있을 때만** 쓰입니다. 서버에 이미 있는 체크리스트 파일은 고칠 필요가 없고 그대로 읽힙니다.
- 서버에서 관리자가 고친 체크리스트 파일은 GitHub에서 같은 파일이 바뀌지 않았다면 `git pull`해도 그대로입니다.
  - 같은 파일이 양쪽에서 바뀌었다면 `git pull`이 멈추므로, 배포 안내 3-3처럼 먼저 확인·백업합니다.
