# PDF 내부 이미지 검색과 표시

## 무엇이 바뀌었나

PDF 본문 검색은 그대로 두고, 새로 처리하는 PDF의 페이지 이미지도 답변에서 활용할 수 있게 했습니다.

- 페이지의 의미 있는 이미지를 추출해 문서별 폴더에 저장합니다.
- 이미지에 보이는 내용을 짧은 검색용 설명으로 만들 수 있습니다.
- 설명은 기존 본문 벡터와 분리한 `image_description` 보조 벡터로 저장합니다.
- 답변이 사용한 근거와 연결된 이미지는 `관련 이미지` 영역에 최대 3개 표시합니다.
- 이미지를 누르면 기존 이미지 확대 화면으로 확인할 수 있습니다.

## 기존 검색 보호

- 기존 PDF 본문 벡터 생성 순서와 Gemini Embedding, ChromaDB, BM25 검색은 변경하지 않았습니다.
- 한 검색 결과에 이미지 설명 벡터는 최대 1개만 포함하고, 남는 자리는 본문 결과로 채웁니다.
- 이미지 설명 생성 실패는 해당 설명만 비우며 PDF 수집 전체를 중단하지 않습니다.
- 같은 이미지 내용은 SHA-256 해시와 저장된 설명을 이용해 중복 설명 생성을 피합니다.

## 공개 범위

직원 화면에는 이미지와 문서명·페이지·항목명만 보여줍니다. 내부 파일 경로, SourceUnit ID, 문서 ID, 벡터 ID와 전체 metadata는 공개하지 않습니다.

## 기존 문서

이미지 metadata가 없는 기존 문서는 이전과 똑같이 검색하고 답변합니다. 이미 등록된 PDF에서 이미지 기능을 사용하려면 해당 문서를 다시 업로드하거나 재색인해야 합니다. 이번 작업에서는 기존 ChromaDB를 재색인하지 않았습니다.

## 검증

- 실제 Gemini 호출 없이 mock으로 이미지 설명 성공과 실패를 확인했습니다.
- 이미지 없는 PDF와 이미지가 있는 PDF의 수집을 로컬로 재생했습니다.
- 이미지 설명 보조 벡터, 검색 결과 제한, 중복 제거와 최대 3개 표시를 자동검사했습니다.
- 기존 텍스트 검색 회귀검사와 production build를 통과했습니다.
- Docker의 SCHAT 웹, ChromaDB와 연구용 안전검사 서비스 상태를 확인했습니다.
