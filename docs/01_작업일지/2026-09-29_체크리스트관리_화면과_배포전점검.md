# 체크리스트 관리 화면과 서버 배포 전 점검

## 1. 결정 사항

- 재검색 방식 C는 계속 꺼 둡니다(`SCHAT_AGENT_RESEARCH_MODE` 설정 없음 = 꺼짐).
- "신선동결혈상" 표기는 간호사가 p.113 원본 그림을 확인한 뒤 정합니다. 지금은 고치지 않았습니다.

## 2. 체크리스트 관리 화면

`SCHAT 관리자 설정 > 체크리스트 관리`를 새로 만들었습니다.

- **목록**
  - 체크리스트마다 쪽수, 제목, 근거 문서와 쪽, 찾는 이름, 상태를 보여줍니다.
  - 검토 필요 이유도 쉬운 말로 보여줍니다.
- **필터와 검색**
  - 전체 / 검토 필요 / 공개 / 숨김 필터가 있고, 각각의 개수가 표시됩니다.
  - 이름 또는 `p.쪽수`로 찾을 수 있습니다.
- **상태 바꾸기**
  - 검토 필요 / 공개 / 숨김 중에서 고릅니다.
  - 직원 화면에는 **공개만** 나옵니다. 검토 필요와 숨김은 관리자만 봅니다.
  - 공개로 바꿀 때는 "직원 화면에 바로 나온다"는 확인 창이 한 번 뜹니다.
- **원문 대조**
  - "원본 보기 p.N"을 누르면 원문 PDF가 그 쪽으로 열립니다.
- **직접 수정**
  - 제목, 찾는 이름, 항목 종류(체크/설명), 항목 이름, 세부 내용, 순서를 고칠 수 있고 항목을 추가·삭제할 수 있습니다.
  - 빈 줄은 저장하지 않습니다.
- **관리자 결정 보호**
  - 관리자가 정한 상태와 수정 내용은 문서를 다시 올려 자동 추출이 다시 돌아도 덮어쓰지 않습니다.
- **다른 화면**
  - 문서 관리 창의 체크리스트 목록에 "숨김" 표시를 추가했습니다.
  - 시스템 상태 화면의 체크리스트 수에 숨김 수를 추가했습니다.

### 확인

- **실제 화면**
  - CT 초안(p.2)을 숨김 → 공개 → 검토 필요로 바꿨습니다.
  - 공개일 때만 직원 목록에 나타났습니다(55개 → 56개 → 55개).
  - 원본 보기 p.2와 수정 창도 확인했습니다.
  - 확인 후 체크리스트 파일은 백업으로 원래대로 되돌렸습니다.
- **자동 테스트:** 서버 290개와 화면 129개가 모두 통과했습니다.
- **DB 구조 변경은 없습니다.** 상태는 체크리스트 파일(JSON)에 저장됩니다.
- 채팅, Citation, PDF, 퀴즈 코드는 이번에 바꾸지 않았습니다.

## 3. 서버 배포 전 점검표

대상은 2026-09-28~29 개선 전체입니다: 검색 속도, 거르기 수정, 사진 질문, 체크리스트 연결, 체크리스트 관리 화면.

### 바뀌지 않는 것

- **DB 구조 변경(migration) 없음.** 백업은 평소처럼 합니다.
- 검색 색인(Chroma) 다시 만들기가 필요 없습니다.
- 서버 `.env`에 새로 넣을 설정이 없습니다.
  - 검색 캐시는 기본으로 켜집니다. 문제가 생기면 `SCHAT_SEARCH_CACHE=off`로 끌 수 있습니다.
  - 방식 A·C는 기본으로 꺼져 있습니다.

### 노트북에서 (commit·push 전)

1. 올라갈 것을 확인합니다.
   - 코드
   - 문서
   - 체크리스트 초안 16개(`server/storage/document-checklists`의 새 JSON 파일, 검토 필요 상태)
2. 올라가면 안 되는 것이 없는지 확인합니다.
   - `.env`, API 키, 환자정보, `server/storage`의 DB·문서 파일
   - 답변 전문·검토 문서(부모 폴더 `workspace/데이터_검수/`에 있어 이 저장소에 포함되지 않음)
3. 초안 16개도 함께 올릴지 결정합니다.
   - 올려도 "검토 필요" 상태라 직원에게는 보이지 않습니다.
   - 서버 관리자 화면에서 검토·공개할 수 있게 됩니다.

### 서버에서

1. DB를 백업합니다(배포 안내 3-2 ②).
2. 체크리스트 폴더를 확인합니다(배포 안내 3-3).
   - 서버에서 관리자가 고친 체크리스트가 있는지: `git status --short server/storage/document-checklists`
   - 파일 권한: `id -u`가 1000이 아니면 3-3의 한 줄 명령으로 받습니다.
3. `git pull` 후 **다시 빌드**합니다. 코드가 바뀌었기 때문입니다.
4. 빌드가 끝나면 `docker ps`로 세 개가 모두 `healthy`인지 확인합니다.
5. 메모리를 확인합니다: `docker stats --no-stream`
   - 로컬에서 재시작 직후 `schat-web`은 약 506MB였습니다.
   - 검색 캐시가 채워진 뒤의 값은 서버에서 확인이 필요합니다.

### 배포 후 운영 사이트에서 확인

1. **관리자 > 체크리스트 관리**
   - 전체 80개(공개 55 · 검토 필요 25 · 숨김 0)가 보여야 합니다.
   - 0개이거나 크게 적으면 서버의 문서 번호가 노트북과 다른 것이므로 공개하지 말고 알려 주세요.
2. 직원 계정으로 질문합니다.

| 질문 | 기대 결과 |
|---|---|
| PTNB 후 간호 알려줘 | 정상 답변, 출처 p.15, PTNB 체크리스트 버튼 |
| 폐생검 후 간호 알려줘 | PTNB 체크리스트 버튼 |
| 혈액제제 종류를 사진으로 보여줘 | 정상 답변, 출처 p.113 펼치면 계통도 사진 |
| 수혈 세트 그림 보여줘 | 정상 답변, 출처에 수혈 세트 사진 |
| 치아 미백 후 음식 제한 알려줘 | "등록된 문서에서 확인되지 않습니다" |

3. 기존 기능이 그대로인지 확인합니다.
   - 출처의 원문 PDF 보기
   - 체크리스트 창
   - 퀴즈
   - 문제 신고
4. **시스템 상태** 화면의 체크리스트 수를 확인합니다.

### 문제가 생기면

- 검색이 이상하면 서버 `.env`에 `SCHAT_SEARCH_CACHE=off`를 넣고 다시 시작합니다.
- 화면이 열리지 않거나 오류가 나면 되돌리기 전에 먼저 알려 주세요. DB 백업과 매일 디스크 스냅샷이 있습니다.

### 그 밖에

- Gemini 선불 잔액은 한 번 소진된 적이 있으니 자동 충전 또는 정기 확인을 권합니다.
- 체크리스트 초안 16개와 숨겨진 9개는 검토 대기입니다.
- 방식 C는 꺼져 있습니다.
