# 동일 질문 재검색 차단 수정

## 증상과 확인 범위

- 사용자가 같은 대화에서 '역격리 이동 시'를 두 번 질문한 캡처 제공. 첫 답변은 출처와 함께 표시되지만 다음 답변은 '등록된 문서에서 확인되지 않습니다.'임.
- 실제 서버 대화·실행 로그를 읽지 않았으므로 사건 원인 확정과 코드 결함 재현을 구분함.

## 재현한 원인

- rag-memory의 Deduplicator는 같은 Agent 세션에서 같은 입력의 도구 실행을 차단함.
- 답변 저장 후 chat-history가 clearCitations를 호출해 출처와 강제 검색 기록은 비움. 그러나 rag-memory의 중복 기록은 비우지 않았음.
- 다음 동일 질문의 강제 검색은 실행을 시도하지만 도구의 중복 차단에서 반환되어 본문과 출처가 없는 상태가 될 수 있음. 사용자 질문 문제가 아니라 도구 상태의 수명 문제임.

## 변경

- 검색용 중복 기록과 저장용 중복 기록을 분리함.
- 답변 완료 시 출처 정리와 함께 검색용 기록만 초기화함. 한 답변 안에서 반복 검색은 여전히 막고, 같은 내용의 저장 작업도 계속 막음.
- 검색 실패 안내를 억지로 숨기거나 과거 답변을 무조건 재사용하지 않음.
- 기존 memory.js의 전화번호부 후속 변경은 보존함. 변경 전체를 임의 커밋하지 않음.

## 검사와 다음 확인

- 가짜 검색·가짜 근거로 수정 전 두 번째 동일 검색이 duplicated로 차단됨을 확인. 수정 후 두 번째 질문의 근거가 다시 수집되고 같은 답변 내 반복 검색과 중복 저장은 차단됨을 확인.
- 외부망 차단·실제 DB/storage 미연결 임시 Docker에서 신규 검사와 기존 출처 검사 총 23개 통과.
- 모델 목록·요금표 외부 조회 실패 경고는 차단 환경의 예상 출력이며 실제 Gemini 호출은 0회임.
- DB 구조 변경·실제 자료 삭제·3001/운영 재시작·commit/push 없음.
- 다음은 다른 창의 미커밋 작업과 분리하여 배포 범위를 확정하고, 반영 후 같은 대화에서 동일 질문 2회의 실제 동작 확인. 운영 캡처 사건의 원인을 확정하려면 당시 검색 실행 기록도 대조해야 함.
