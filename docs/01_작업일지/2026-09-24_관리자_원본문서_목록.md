# 관리자 원본 PDF 목록 표시

## 목표

관리자 문서 화면에서 PDF의 페이지 단위 저장 행을 반복 노출하지 않고, 실제 업로드한 원본 PDF를 한 행씩 표시하도록 개선했습니다.

## 확인한 구조

- 관리자 목록의 기존 182개 행은 원본 PDF 2개에 속한 페이지 단위 JSON 문서였습니다.
- 같은 원본에서 생성된 행은 안정적인 `document_id`를 공유합니다.
- 행별 DB ID와 metadata ID는 서로 달라 원본 그룹 기준으로 사용하지 않았습니다.
- 등록일 후보인 `published`는 현재 자료에서 확인할 수 없어 화면에 표시하지 않았습니다.

## 구현 내용

- 원본 식별자 우선순위는 `original_document_id`, `source_document_id`, `document_id`입니다.
- PDF이며 안정적인 원본 식별자가 있을 때만 한 행으로 표시합니다.
- filename만 같은 서로 다른 자료는 합치지 않습니다.
- PDF 행에는 PDF 아이콘, 원본 파일명과 전체 선택 checkbox만 표시합니다.
- 페이지, section, chunk 수, 내부 ID와 경로는 기본 목록에 표시하지 않습니다.
- PDF를 선택하면 기존 자식 행 전체가 선택되며, 기존 bulk 제거 API가 정확한 자식 경로들을 처리합니다.
- 원본 단위 API가 없는 pin·watch는 PDF 행에서 제외했습니다.
- PDF가 아니거나 안정적인 식별자가 없는 과거 자료는 기존 개별 행과 기존 action을 유지합니다.

## 변경하지 않은 것

- workspace_documents, 원본 JSON과 ChromaDB 저장 구조
- 검색, RAG, embedding, chunk 생성과 metadata
- 재색인과 DB migration
- 기존 삭제 API

## 검증

- 동일 원본 PDF 10행을 화면 모델 1행으로 변환: 통과
- 같은 filename·다른 원본 ID 분리: 통과
- 원본 ID 우선순위, 비PDF와 ID 없는 자료 호환: 통과
- PDF 전체 선택과 기존 자식 경로 보존: 통과
- 실제 React renderer에서 원본 1행, 내부 ID 미노출과 좁은 폭 스타일 확인: 통과
- 실제 문서 삭제·수정 및 외부 AI 호출은 실행하지 않았습니다.
