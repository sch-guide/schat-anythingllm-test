# Gemini 상태 저장과 채팅 예산 추정

## 범위

- 기존 알림 구조를 재사용함. 새로운 비용 통합 수집기는 만들지 않음.
- 실제 Gemini 오류 상태와 채팅 예산 추정치를 별도로 관리함. 예산 초과만으로 질문을 차단하지 않음.
- commit/push/tag, 실제 Gemini 호출, Docker 재빌드·재시작, 운영 서버 작업을 하지 않음.

## 실제 한도 알림

- 현재 SDK는 OpenAI 호환 Gemini 호출을 사용함. HTTP 상태와 중첩 error/message/details의 quota 식별자를 확인함.
- 402/429 또는 RESOURCE_EXHAUSTED와 명시적인 크레딧 소진·일간/월간 quota 정보가 있으면 한도 소진으로 판단함.
- 분당·초당 제한 및 명확하지 않은 429는 일시적 혼잡으로 처리함. 단순 billing 안내만으로 한도 소진을 단정하지 않음.
- 401/403 인증·권한 오류, 네트워크, 5xx 등 나머지는 일반 오류 안내로 처리함.
- 직원 한도 문구: 현재 AI 사용량이 소진되어 답변할 수 없습니다. 지침서 원본을 확인하시고, 관리자에게 문의해 주세요. 간호교육파트 내선번호 : 6741
- 직원 혼잡 문구: 사용자가 많아 잠시 후 다시 시도해 주세요.
- 직원 기타 문구: 답변 생성 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. 계속 문제가 발생하면 관리자에게 문의해 주세요.
- 원문 오류·키·환자정보는 새 상태와 이벤트에 저장하지 않음. 시스템 기록에는 한도 감지·복구·연속 3회 혼잡을 구분하여 남김.
- 기존 system_settings에 최소 상태와 최초 발생 시각을 저장함. 반복 소진은 최초 시각을 유지함. 이후 정상 호출이 성공하면 해제함. 소진 이전부터 실행 중이던 오래된 요청의 성공은 새 소진을 지우지 않음.
- 상태 읽기/저장에 실패하면 관리자에게 확인 불가 안내를 표시함. 오류 저장 실패 때문에 정상 AI 답변을 실패로 바꾸지 않음.
- 관리자 화면은 15초마다 새 상태를 조회함. 서버 재시작 유지 여부는 저장 어댑터를 사용한 모의 재시작으로 검증함. 실제 Docker 재시작 검증은 수행하지 않음.

## 예상 예산

- 한국 시간 기준 이번 달 workspace_chats의 기록된 입력·출력 토큰과 모델 이름을 읽음. 질문 원문을 새 기록에 저장하지 않음.
- 모델별 입력/출력 100만 토큰당 예상 원화 단가와 월 예산을 관리자 시스템 상태 화면에서 설정함.
- 계산식: 입력 토큰 × 입력 예상 단가 ÷ 100만 + 출력 토큰 × 출력 예상 단가 ÷ 100만. 이를 월 예산으로 나누어 사용률을 구함.
- 80% 이상은 주의, 95% 이상은 높은 사용량 경고를 표시함. 실제 Gemini 한도 소진과는 별개임.
- 사용량·모델·단가 부족 시 0원/0%가 아닌 계산 불가를 표시함. 기존 스트림에서 입력 0은 미측정 기본값일 수 있어 안전하게 계산 불가로 처리함. 과거 자료를 임의 보정하지 않음.
- 월 예산과 단가는 사용자 지정 전에는 미설정임. 금액을 임의로 채우지 않음.
- 단가 변경은 해당 월 전체 기록에 적용됨. 과거 대화 삭제 시 추정치가 달라질 수 있음. 조회 부하를 줄이기 위해 예산 결과는 최대 30초 재사용함.
- 화면 필수 안내: 현재 표시되는 AI 예산 사용률은 SCHAT에 기록된 채팅 사용량을 기준으로 계산한 추정치입니다. 임베딩, PDF 이미지 설명, 퀴즈 생성, 동의어 자동 생성 등 일부 Gemini 사용량은 포함되지 않아 실제 사용액과 다를 수 있습니다.

## 검증 및 발견한 문제

- 테스트를 먼저 추가해 기능 부재로 실패하는 것을 확인한 뒤 구현함. 실제 API 한도를 소진시키지 않음.
- 코드 검토에서 미측정 입력 토큰 0을 비용으로 계산하는 문제를 발견하고 계산 불가로 보완함.
- 초기 설정 읽기 실패 뒤 과거 정상/소진 상태가 새 관측을 덮는 문제를 재현하고 보완함.
- 오류 분류·관리자 권한·복구·모의 재시작·최초 시각·예산 79/80/95·계산 불가·기존 사용 통계 테스트를 실행함.
- frontend 화면 렌더링 검사와 production build를 통과함. 기존 Browserslist 갱신·큰 번들·외부 모듈 경고는 남아 있음.
- 최종 서버·유틸 검사 44개, 관리자 화면 검사 6개, 문서 분리 검사 11개를 통과함. git diff --check도 통과함. 문서 생성기의 기존 escape sequence 경고는 남아 있으나 생성과 검사는 성공함.
- 실제 브라우저 자동제어에 연결된 브라우저가 없어 PC·모바일 클릭 검증은 미수행임.
- 검색 비율, Gemini 입력/프롬프트, 토큰 수집, 체크리스트, 동의어, 퀴즈, 원본 PDF는 이 작업에서 변경하지 않음. 다른 창의 변경사항은 보존함.

## 직접 확인할 순서

1. 이번 코드가 반영된 테스트 웹환경에서 관리자 → 시스템 상태 → Gemini AI 상태와 예상 예산을 확인함. 현재 Docker 3001에는 확장판을 반영하지 않았음.
2. 설정 전에는 계산 불가와 제외 사용량 안내가 표시되는지 확인함.
3. 월 예산·기록된 모델별 입력/출력 예상 단가를 입력하고 저장함. 새로고침 후 설정이 유지되는지 확인함.
4. 실사용 한도를 일부러 소진하지 않음. 80/95%와 오류 상태는 가짜 데이터 자동 테스트로 확인함.
5. 운영 중 자연스럽게 한도 오류가 발생하면 최초 시각 유지, 정상 호출 후 배너 해제를 확인함.

## 남은 제한사항

- 모든 Gemini 호출의 비용 통합은 다음 개선 과제로 남김. 현재 값은 선불 실제 잔액이 아님.
- 여러 서버 프로세스에서 동시에 상태를 쓰는 구성은 별도 조정이 필요함. 현재 단일 SCHAT 서버 프로세스 기준임.
- 입력창 자동 복원은 이번에 추가하지 않음. 실제 화면 클릭과 Docker 반영은 별도임.
