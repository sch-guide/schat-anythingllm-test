- 수정:
  - `server/utils/answerFeedback.js` `resolve(id, {resolution})`: 처음 처리 완료할 때 👎를 보낸 직원에게 알림을 넣는다(같은 알림 표, `report_id` 없음, kind `feedback_resolved`, 내용은 이유·질문 200자·처리 결과). 이미 완료된 것을 다시 완료하면 알림을 다시 보내지 않음. 직원이 다시 👎를 보내 열리면 다음 완료 때 새 알림.

  - `server/endpoints/answerFeedback.js`: 처리 완료 요청에 처리 결과 글을 받음.

## ② 체크리스트 새 판

- 원인(3001 자료): 수술 문서에 같은 제목 체크리스트가 여럿("유방암 Breast Cancer" ×3, "prof. 전섭, 양은정" ×3, "방광종양 Bladder tumor" ×2, "Prof. 김윤숙" ×2). 제목이 겹치면 내용이 글자 하나까지 같아도 늘 "ambiguous"(검토 필요). 지운 예전 판의 체크리스트가 여러 벌 남아 내용이 서로 다르면 그것도 "ambiguous".
- 수정(`versionMatch.js`, `processDocuments.js`): 예전 공개본 중 내용(원본 추출 지문)이 똑같은 것이 있으면 제목이 겹쳐도·예전 판이 여러 벌이어도 그 공개본과 짝지어 다시 공개(관리자 수정 내용도 이어받음). 같은 공개본을 두 체크리스트가 함께 가져가지 않음. 내용이 바뀐 체크리스트만 검토로 남음.
- 운영 확인(읽기 전용 명령): 검사 및 시술(20261002) same 24 · changed 32 · previous-not-public 16 · previous-unverifiable 1, 수술(20261023) new 67 · ambiguous 10.

- 추가 수정(`versionMatch.js` looseFingerprint, `repository.js`): 빈칸을 모두 빼고 한 항목의 여러 줄을 이어 붙인 지문으로도 비교. 글자·숫자·순서가 같으면 다시 공개, 하나라도 다르면 검토. 새로 저장하는 체크리스트에 이 원본 지문(`sourceLooseFingerprint`)을 함께 저장해 나중에 관리자가 고쳐도 다음 판과 비교 가능. 손으로 쓴 초안은 비교하지 않음.
- 3001 반영(`schat-admin-build:checklist-loose-20261109`). 시험 3개 추가(띄어쓰기·줄바꿈만 다름 → same, 글자·숫자 다름 → changed, 관리자 수정본은 저장된 원본 지문으로만).
