# 엑셀 전화번호부 등록 지원

## 요청과 원인

사용자가 전화번호부를 엑셀로 올리겠다고 요청했습니다. 기존 문서 처리기는 `.xlsx`를 읽을 수 있었지만, 문서 등록 화면과 폴더 끌어놓기는 PDF만 허용했습니다. 기존 엑셀 변환은 단순 쉼표 구분 텍스트여서 번호와 열 이름이 떨어질 수 있었고, 한글 시트 이름이 내부 파일명에서 사라져 여러 시트가 같은 파일에 저장되는 문제도 재현했습니다.

## 바꾼 내용

- 파일 선택·끌어놓기에서 PDF와 `.xlsx`·`.xls`를 허용합니다.
- 각 행마다 열 이름을 붙이고, 가로로 반복된 동일 표는 별도 묶음으로 나눕니다. 빈칸을 옆 사람이나 윗행 값으로 채우지 않습니다.
- 엑셀에서 보이는 번호 앞의 0을 보존합니다. 파일·시트 이름과 같은 엑셀 파일의 공통 식별번호를 보존합니다.
- 한글 시트 이름이 같게 변환되더라도 시트별 고유 파일명으로 저장합니다.
- 같은 이름의 엑셀 자동 교체와 엑셀이 섞인 PDF 교체 묶음은 기존 PDF 전용 교체 기능으로 보내지 않고 안내합니다. 기존 자료를 바꾸지 않습니다.
- 번호 입력 권장 방식과 지원 범위를 [등록 안내](../00_현재상태/엑셀_전화번호부_등록_안내.md)에 정리했습니다.

## 검증

- 가짜 자료의 화면·묶음 업로드·행 변환 집중검사 22개 통과.
- 네트워크가 차단된 임시 컨테이너에서 실제 `.xlsx`·`.xls`를 만들어 변환 검사 2개 통과. 여러 한글 시트, 표시 형식 `0000`, 텍스트 앞자리 0, 빈 시트, 직접 첨부 읽기까지 확인했습니다. 임시 파일은 해당 검사 종료 때 정리됩니다.
- 화면 빌드 성공. 기존 브라우저 호환성 정보·큰 화면 묶음 등의 경고가 있었지만 빌드는 성공했습니다.
- 기존 업로드 목록·묶음 처리 검사 18개와 기존 PDF 업로드 검사 2개도 통과했습니다. PDF 검사 2개는 호스트의 `uuid` 라이브러리 부재로 처음 실행되지 않아, 기존 라이브러리가 설치된 격리 컨테이너에서 실행했습니다. 이번 관련 검사 합계는 44개입니다.
- 코드 검토에서 제목 `연락처`를 열 이름으로 오인하는 경우를 발견해 재현 검사 후 보완했습니다.
- 실제 병원 엑셀 등록과 Gemini 답변은 실행하지 않았습니다. 이번 검증의 외부 API 비용은 0원입니다.
