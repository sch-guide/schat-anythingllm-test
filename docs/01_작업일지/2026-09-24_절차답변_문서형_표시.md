# 절차 답변 문서형 표시

## 목표

검색 결과와 임상 내용은 바꾸지 않고, 직원 화면의 절차 답변만 짧은 요약·단계 제목·bullet 구조로 읽기 쉽게 표시하도록 개선했습니다.

## 구현 내용

- 절차 질문의 structured 출력에 요약, 단계명, 행동 항목과 근거 ID를 담도록 최소 확장했습니다.
- Gemini OpenAI 호환 API가 깊게 중첩된 schema를 거부하는 것을 실제 1회 호출에서 확인해, 같은 정보를 `summary_text`, `summary_source_ids`, 평면 `items`로 받도록 단순화했습니다.
- 서버가 허용된 근거 ID를 확인하고 항목을 단계별로 묶은 뒤 공개용 `sourceIndexes`만 presentation에 넣습니다.
- 내부 SourceUnit ID, metadata, chunk/document ID와 SVG 흔적이 표시 문자열에 있으면 응답을 중단합니다.
- 프런트는 procedure presentation이 있을 때만 요약, `1단계. 제목`, 짧은 bullet 전용 renderer를 사용합니다.
- 답변 맨 아래의 출처 번호를 누르면 기존 출처 sidebar가 열립니다. 기존 하단 출처 UI도 유지합니다.
- presentation이 없거나 잘못된 경우 기존 text·Markdown renderer를 그대로 사용합니다.
- 저장된 presentation은 대화 기록에서 복원되며, 기존 text는 계속 저장되어 복사와 TTS가 그대로 동작합니다.
- 본문 폭은 PC에서 최대 약 780px, 모바일에서는 전체 폭이며 줄간격은 약 1.7입니다.

## 유지한 범위

- Gemini Embedding 2, ChromaDB, BM25와 검색·근거 선택 로직
- closed-book prompt와 허용 출처 ID 검증
- 근거 0건 차단, retry 0
- `SCHAT_SAFETY_ENABLED=true`, `SCHAT_SAFETY_GATE_ENABLED=false`
- Python 안전검사 코드와 기존 테스트
- 기존 Markdown 답변, 과거 대화, 복사, TTS

재색인, 검색 알고리즘 변경, safety gate 변경, Git commit·tag·push는 실행하지 않았습니다.

## 검증 결과

- 절차 schema parsing과 평면 items의 단계 그룹 변환: 통과
- 여러 section, bullet, 공개 출처 번호 연결: 통과
- plain text와 과거 대화 하위 호환: 통과
- 모바일 전체 폭, PC 780px 제한, line-height 1.7: 통과
- 내부 ID·metadata·SVG 미노출: 통과
- 프런트 production 번들: 통과
- 관련 서버·검색 회귀 51건: 모두 통과
- presentation 프런트 mock 3건: 모두 통과
- Docker 세 서비스: 모두 healthy

## 실제 질문 1회 결과

질문은 `수혈 절차 쉽게 설명해줘` 한 건만 실행했고 Gemini 재시도는 0회였습니다.

최초 중첩 schema 요청은 Gemini API가 HTTP 400으로 거부했습니다. 직원 화면에는 `근거를 안전하게 확인할 수 없어 답변하지 않습니다.`가 표시됐고 내부 ID·metadata·SVG는 노출되지 않았습니다.

실제 호출 한도를 지키기 위해 Gemini를 다시 호출하지 않았습니다. 대신 schema를 기존에 작동하던 structured 출력과 같은 중첩 깊이로 단순화한 뒤 mock과 production build로 검증했습니다. 따라서 수정된 평면 schema의 실제 Gemini 결과는 다음 승인된 1회 검수에서 확인해야 합니다.

## 데이터 상태 참고

이번 작업에서는 ChromaDB를 변경하거나 재색인하지 않았습니다. 다만 종료 전 읽기 전용 점검에서 현재 컬렉션의 원시 벡터는 총 207개로 확인됐으며, 문서별로 기존 실무지침 116개와 별도 검사·시술 문서 91개였습니다. 기존 상태 문서의 116개 표기와 실제 저장 상태가 다르므로 별도 확인이 필요합니다.

## bullet 표시 보완

후속 화면 확인에서 브라우저 기본 목록 marker가 보이지 않는 환경이 확인되어 presentation renderer의 시각적 표시만 보완했습니다.

- 기존 `<ul>`·`<li>` 구조를 유지하면서 각 항목 안에 `•`를 직접 표시합니다.
- 요약은 `font-medium`, 단계 제목은 `font-semibold`를 사용합니다.
- 단계 사이는 32px, bullet 사이는 8px 간격입니다.
- 본문은 모바일에서 전체 폭이며 PC에서는 최대 780px, 줄간격은 1.7입니다.
- presentation 데이터, 출처 badge, 기존 Markdown fallback과 text 호환성은 변경하지 않았습니다.
- 실제 React 정적 렌더 mock에서 `<ul>` 2개, `<li>` 3개, 명시적 bullet 3개와 스타일 계약을 확인했습니다.
- 실제 Gemini 호출은 실행하지 않았습니다.

## 출처 위치 조정

후속 요청에 따라 각 bullet 뒤에 반복되던 출처 번호를 제거하고 절차 답변 맨 아래에 한 번만 표시하도록 바꿨습니다.

- 모든 단계에서 사용한 출처를 답변 순서대로 모으고 같은 번호는 한 번만 표시합니다.
- 마지막 출처 번호를 누르면 이전과 동일하게 해당 출처 sidebar와 근거 원문 상세가 열립니다.
- presentation 데이터와 `sourceIndexes`, 기존 하단 출처 UI, 검색·근거·schema는 변경하지 않았습니다.
- 실제 React 렌더 검사에서 문장 뒤에 출처가 없고 `[1]`, `[2]`가 마지막에 각각 한 번만 표시되는 것을 확인했습니다.
- 실제 Gemini 호출은 실행하지 않았습니다.
