# 개인 체크·메모 서버 저장

## 승인한 범위

- Secret Manager·키 폐기를 사용하지 않음. 자유 메모는 그대로 저장하며 서버에서 만료된 자료도 기존 스냅샷에 최대 약 17일 남을 수 있음을 사용자가 승인함.
- 환자정보 한 칸·기타메모 한 칸의 모양 유지, 안내 문구 추가 없음. 남은 시간만 작은 회색 한 줄로 표시함.
- 브라우저에서 환자정보의 이름을 가린 후 전송함. 숫자와 병실의 `호`를 유지함. 이미 가린 이름을 이어 입력해도 가운데 글자를 다시 가림.
- 보수적으로 5글자 이상 한글 덩어리도 가림. 이름 판독 AI가 아니므로 일반 단어도 가려질 수 있음. 자유 메모와 영문·띄어 쓴 이름까지 익명화한다는 의미는 아님.
- 본인 계정·체크리스트별 한 묶음으로 저장함. 체크/환자정보/메모 중 내용 변경 시 마지막 수정 시각이 갱신됨. 조회나 동일 내용 저장은 기한을 연장하지 않음.
- 기존 브라우저 자료는 이전하지 않고 체크/메모 접두사의 사본만 정리함. 이 정리는 직원 브라우저에서 새 기능을 실행할 때 적용되며 이번 개발 중 기존 자료를 직접 삭제하지 않음.

## 구현

- 전용 개인 상태 API와 `schat_checklist_personal_state` 테이블 추가. 기존 체크리스트 정의·공개 상태와 별개임.
- 서버의 로그인 계정과 작업공간 문서 접근 권한을 확인함. 관리자도 자신의 상태만 조회하며 다른 직원 메모 조회 API 없음.
- revision을 SQL 한 문장에서 비교하여 다른 PC의 최신 내용을 조용히 덮어쓰지 않음. 충돌 시 안내 후 명시적으로 다시 불러옴.
- 24시간 경과 시 API 조회 차단, 서버 시작 및 1분 주기로 만료 행 정리함. 서버 중단 중 실제 삭제는 재시작 후 수행됨.
- 개인 자료 전용 Prisma 연결은 로그 비활성화. 오류 원문을 반환하거나 기록하지 않음. 잘못된 JSON·큰 요청은 내용 없는 고정 오류로 거절함.
- 브라우저 영구 저장 안 함. 로그아웃 이벤트·다른 탭의 인증 변경 시 화면 사본 정리. 일반 패널 닫기는 저장을 마친 뒤 메모리를 정리하며, 미저장 상태의 브라우저 종료는 확인 요청함.
- 정상 내용은 별도 보호 키 없이 DB에 저장됨. DB·스냅샷 접근 권한을 가진 운영자는 읽을 수 있으며 이름 가리기는 완전 익명화가 아님.

## 현재 확인 결과

- 신규 자동 검사 29개 통과: 이름 가리기, 전송 데이터, 소유권, 24시간 경계, 동일 내용 기한 유지, 충돌, 늦은 조회, 로그아웃 뒤 응답, 닫기 중 저장 완료.
- 기존 체크·메모·화면 구조 검사 30개 통과. 일부는 기존 브라우저 저장 도구에 대한 회귀 검사이며 신규 저장 동작의 증명과 구분함.
- 외부망 없는 읽기 전용 별도 Docker에서 실제 Prisma와 임시 SQLite로 저장·조회·계정 분리·충돌 검사 통과함. 운영/기존 로컬 DB는 연결하지 않음.
- 코드 검토에서 마스킹 누락·늦은 조회·창 닫기 저장 취소를 발견하여 회귀 검사 후 수정함.
- Vite build 2회 통과. 최신 보완 후 재빌드도 통과함. 기존 대형 번들·브라우저 호환 데이터 경고는 남음.
- 문서 화면 자동 생성 후 분리 검사 11개 통과함. 생성 도구의 기존 escape 경고는 남음.
- 실제 Gemini 호출, 운영 서버 접속, 기존 DB migration 적용, 로컬 3001 재배포, push 없음.

## 적용 전 필요한 확인

1. 새 테이블 migration이 포함된 배포에서만 서버 저장을 사용할 수 있음. 미적용 시 개인 상태 기능은 오류 안내하며 채팅 기능은 유지함.
2. 별도 PC/브라우저로 같은 계정 로그인 후 합성 메모와 체크가 보이는지 확인함.
3. 두 창에서 같은 자료를 수정하여 충돌 안내를 확인함.
4. 로그아웃하면 다른 열린 창에서도 내용이 없어지고 다시 로그인하면 서버 저장분이 돌아오는지 확인함.
5. 실제 3001 브라우저의 한글 입력·패널 닫기·모바일 동작은 아직 실측하지 않음. 이 기록을 운영 검증 완료로 해석하지 않음.

## 커밋 범위

이번 기능과 그 화면이 의존하는 기존 체크리스트 메모·이전 체크 안내 파일만 함께 포함함. 다른 문서 업데이트·Gemini 예산·동의어·출처 표시 변경, storage 데이터와 기존 문서 변경은 포함하지 않음. 새 migration은 파일만 추가하며 실제 기존 DB에 적용하지 않음. 공유 현재 상태의 다른 작업 갱신은 작업공간에 보존함. 저장소 pre-commit 훅이 stage된 파일을 기준으로 문서 화면 2개를 자동 생성하여 함께 커밋함.
