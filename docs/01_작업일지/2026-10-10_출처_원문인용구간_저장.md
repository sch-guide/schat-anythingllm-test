# 출처 원문 인용 구간 저장 — 2026-10-10

## 재현 질문과 문제

사용자 질문: “항생제 반응검사 절차 알려줘”. 사용자 화면에서 출처 3개가 모두 위치 미확정으로 표시됨. 앞선 답변·원문 문장 일치 방식은 바꿔 쓴 답변을 처리하지 못했으며 기능 완료로 취급하지 않음.

## 이번 구현

- 답변을 생성하는 동일한 AI 응답에서 사용한 원문 인용 구간과 출처 식별값을 함께 받도록 연결함. 별도의 AI 호출을 추가하지 않음.
- 검색 문맥에 출처 식별값을 붙이고, 모델에 답변을 뒷받침한 문장·표 내용만 그대로 인용하도록 지시함. 페이지 전체와 관계없는 제목은 인용 대상으로 삼지 않도록 함.
- 인용은 지정한 출처의 원문에서 띄어쓰기·줄바꿈을 제외하고 유일하게 존재해야 저장함. 없는 문구·다른 출처 식별값·반복되어 확정할 수 없는 인용은 제외함.
- 내부 인용 정보는 화면에 보내는 답변 조각에서 제거함. 시작 표시가 글자 단위로 나뉘어 전달되어도 화면에 노출되지 않도록 검사함.
- 검증한 인용은 출처의 evidenceQuotes에 저장되어 대화 기록에도 함께 남음. 화면은 답변 표현이 달라도 이 인용 구간을 우선 사용함. 같은 PDF·페이지의 출처가 합쳐질 때 인용도 합침.
- PC·모바일은 동일 인용 구간 좌표로 빨간 네모를 그림. 원본 PDF는 수정하지 않음.

## 검사와 적용 범위

외부 AI API를 실제 호출하지 않고 합성 원문·가짜 AI 응답으로 검사함. 재현 질문 문구는 실제 코드 연결 검사에 사용하되 의료 내용은 합성 시험 문구로 대체함. 검증된 인용이 답변→출처→대화 저장을 거쳐 유지되는지, 답변이 바뀌어 표현되어도 PDF의 해당 구간만 선택하는지 확인함.

기존에 생성한 답변에는 원문 인용 기록이 없으므로 이번 저장 방식으로 소급 확정할 수 없음. 새 답변부터 적용되는 변경임. 모델이 인용 정보를 누락하거나 인용을 검증하지 못한 경우, PDF의 글자 경계·반복 문구·표 읽기 순서 때문에 좌표를 확정하지 못한 경우에는 원문 안내를 유지함. 인용의 원문 존재 검증이 답변의 의료적 정확성 검증을 의미하지는 않음.

로컬 적용 및 최종 검사 결과는 아래에 이어 기록함. 커밋·push 및 병원 문서 실제 API 테스트는 수행하지 않음.

## 최종 검사와 로컬 반영

- 서버 합성 검사 41개, PDF·근거 선택 검사 16개, 기존 출처 화면·연결 검사 18개 통과(합계 75개).
- 화면 빌드 및 근거 좌표 계산 코드 검사 통과.
- 코드 검토에서 같은 이름·페이지·내용인 서로 다른 PDF의 출처 식별값 충돌 가능성을 찾아 원본 PDF 구분값을 포함하도록 수정함. 동일 원본의 중복 출처 객체는 인용을 함께 유지하도록 검사함.
- 검증된 인용이 있는 출처는 답변 표현 유사도 대신 해당 인용으로 직접 근거를 표시함. 사용한 인용이 없는 나머지 검색 출처를 직접 근거 목록에 섞지 않음. 모든 인용이 없으면 기존 원문 안내를 유지함.
- 기존 실행 서버의 수정 대상 2개 파일을 임시 폴더에 백업하고 수정 전 Git 기준 코드와 일치함을 확인함. 관련 서버 코드 3개와 화면 파일만 기존 로컬 컨테이너에 반영하고 schat-web만 재시작함. DB·등록 문서 변경이나 전체 이미지 교체는 수행하지 않음.
- 로컬 HTTP 정상 응답과 배포한 index.js 파일 일치를 확인함.
- 컨테이너 내부 반영이므로 컨테이너를 새로 만들 때는 이번 소스 코드로 다시 빌드해야 함.
- 외부 API 실제 호출 및 병원 원문 테스트 없음. 커밋·push 없음.

## 사용자 확인 및 다음 시작 위치

Ctrl+F5 후 “항생제 반응검사 절차 알려줘”를 새 질문으로 입력해 새 답변의 근거 구간을 확인해야 함. 과거 답변을 다시 열기만 해서는 새 인용 기록이 생기지 않음. 실제 AI가 해당 원문의 인용을 반환하는지와 실제 PDF에서 좌표를 확정할 수 있는지는 아직 미확인임. 인용 누락·검증 실패·PDF 좌표 미확정 때에는 원문 안내를 유지하므로, 모든 출처에서 반드시 박스가 나온다고 보장하지 않음.
