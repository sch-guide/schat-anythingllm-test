# Gemini 답변 충분성 개선

## 왜 답변이 짧았나요?

절차 질문도 일반 질문과 같은 수의 근거만 전달했고, 항목명이 비어 있는 뒤쪽 절차 본문은 관련 근거에서 제외했습니다. 그래서 Gemini가 실제 문서에 이어지는 단계들을 보지 못하고 한두 단계만 답할 수 있었습니다.

## 무엇을 바꿨나요?

- 종류 질문은 기존처럼 핵심 종류만 간결한 목록으로 표시합니다.
- 절차 질문에만 직접 관련된 근거를 최대 6개까지 전달합니다.
- 같은 문서에서 뒤이어 나오는 확인·준비·시행·관찰·회복·기록 근거를 순서대로 보완합니다.
- 항목명이 비어 있어도 본문에서 같은 절차와 질문 대상을 확인할 수 있으면 근거로 사용할 수 있게 했습니다.
- 목적·정의·대상 설명은 절차를 채우기 위한 근거로 사용하지 않습니다.
- 소아·성인처럼 다른 대상의 절차는 섞지 않습니다.
- Gemini에게 직접 관련된 근거를 충분히 설명하되, 숫자·시간·조건·금기와 행위 종류·강도가 불확실하면 원문 표현을 그대로 쓰도록 지시했습니다.

## 절차 근거를 한 번 더 정리했습니다

단순히 앞뒤 페이지라는 이유만으로 근거를 붙이던 부분을 보완했습니다.

- 실제 처방·동의·평가·준비·확인·시행·관찰·회복·퇴실·기록 행위가 있는 근거만 절차 후보로 사용합니다.
- `예시`, `교육용`, `작성 예`처럼 업무 절차가 아닌 설명 자료는 제외합니다.
- 넓은 절차 질문에는 수집·세척·폐기·보관·처리처럼 더 좁은 별도 처치법을 끼워 넣지 않습니다.
- 선택된 근거만 Gemini와 Python 안전검사에 전달합니다.
- 안전검사를 통과한 `짧은 단계명: 설명` 형식은 직원 화면에서 번호와 소제목으로 표시합니다.

따라서 이전 수혈 답변에 섞였던 DPAR 기록 예시와 PC 수혈세트 세부 처리법, 이전 진정 답변에 섞였던 DPAR 기록 예시는 이번 근거에서 제외됐습니다.

## 안전장치는 그대로인가요?

그대로입니다. 숫자, 단위, 시간, 속도, 조건, 예외, 부정, 금지·금기, 행위 종류·강도, 대상 분기, 근거 없는 사실과 잘못된 출처 연결은 계속 차단합니다. 검색 기준, ChromaDB 색인 116개, 원문 기반 대체 답변과 재시도 0회도 바꾸지 않았습니다.

## 실제 질문 4건 결과

- 수혈 종류: 네 종류가 목록으로 표시됐고 안전검사를 통과했습니다.
- 수혈 절차: 근거는 여러 단계로 전달됐지만 생성 답변의 행위 표현이 달라져 차단됐으며, 직원에게는 원문 기반 안전 답변이 표시됐습니다.
- 진정 절차: 당시 두 단계 답변이 안전검사를 통과했습니다. 이후 빈 항목명의 뒤쪽 절차 근거도 전달하도록 보완했으나, 승인된 호출 횟수를 지키기 위해 다시 호출하지 않았습니다.
- 비터널형 카테터: 등록 근거가 없어 답변 생성을 중단했습니다.

## 2026-09-24 최종 질문 2건 확인

승인된 비민감 질문만 각각 한 번 실행했고 자동 재시도는 하지 않았습니다.

- `수혈 절차 알려줘`: p.117의 수혈 절차와 p.124의 수혈 직전 환자 확인 근거만 선택했습니다. Gemini 후보는 만들어졌지만 행위 강도 변경 검사에 걸려 직원에게 노출되지 않았습니다. 직원 화면에는 선택된 근거에서 만든 원문 기반 안전 답변과 두 출처가 표시됐습니다.
- `진정 절차 알려줘`: p.160, p.161, p.163의 직접 관련 근거를 사용했습니다. Gemini 답변은 세 단계로 생성됐고 안전검사를 통과해 직원 화면에 표시됐습니다. DPAR 기록 예시가 있던 p.164와 p.165는 포함되지 않았습니다.

두 답변 모두 문서 내부 식별자, `document_metadata`, SVG 문자열을 노출하지 않았습니다. 진정 절차는 이전보다 자연스러운 단계형 답변에 가까워졌지만, 수혈 절차는 위험 가능성이 있는 표현을 안전검사가 차단했으므로 아직 원문 기반 답변입니다.

## 확인 방법

가짜 데이터 자동검사로 관련 절차 포함, 예시·기록 예문·좁은 별도 처치 제외, 선택 근거만 전달, 안전 실패 시 선택 근거만 대체 답변에 사용하는 것을 확인했습니다. 이번 최종 확인의 실제 Gemini 호출은 두 건이며 자동 재시도는 0회였습니다.
