# 직원 개인계정·일괄등록·문제 신고

> 같은 날 뒤이어 임시비밀번호 방식을 없애고 직원이 처음 로그인할 때 비밀번호를 직접 정하는 방식으로 바꿨습니다. 아래의 임시비밀번호 관련 내용은 그 전 상태의 기록입니다. 바뀐 내용을 적은 `2026-09-27_처음로그인_비밀번호_직접설정.md`는 2026-10-01 문서 정리 때 합쳐져 지금 폴더에는 없습니다. 원본은 보호 커밋 `5793ea77`에서 볼 수 있고, 현재 동작은 [현재 프로젝트 상태](../00_현재상태/현재_프로젝트_상태.md)의 직원 기능에 적혀 있습니다.

설계: 개발 설계 기록(2026-09-27-employee-accounts-and-reports-design.md)

## 1. 로그인

- 직원은 개인계정으로 로그인합니다. 로그인 화면에서 부서(목록 선택), 사번, 이름, 비밀번호를 입력합니다.
- 서버 확인 순서
  1. 사번으로 계정을 찾습니다.
  2. 사용중인 계정인지 확인합니다.
  3. 부서와 이름이 일치하는지 봅니다(앞뒤·중복 공백은 정리).
  4. 비밀번호를 확인합니다.
- 어느 단계에서 실패해도 "로그인 정보를 다시 확인해주세요."만 보입니다. 실패 기록에는 입력값을 남기지 않고 IP만 남깁니다.
- 사번이 없는 기존 계정(현재 관리자 1명, 테스트 직원 2명)은 로그인 화면 아래 `사번이 등록되지 않은 기존 계정으로 로그인` 링크로 기존 방식을 계속 씁니다.
  - 이 링크는 사번 없는 계정이 남아 있을 때만 보입니다.
  - 관리자가 `사용자 관리 > 수정`에서 본인 사번·이름·부서를 등록하면, 그 계정도 부서·사번·이름 로그인으로만 들어올 수 있습니다.
- 사번이 있는 계정은 기존 아이디 로그인으로 들어올 수 없습니다.

## 2. 비밀번호

- 비밀번호는 기존 방식(bcrypt)으로 해시만 저장합니다. 화면·응답·로그에 비밀번호나 해시가 나오지 않습니다.
- 관리자가 직원을 만들거나 비밀번호를 초기화하면 12자 임시비밀번호가 자동으로 만들어집니다. 직원마다 다르고 헷갈리는 글자는 뺍니다. 발급 직후 한 번만 보여 주고 다시 조회할 수 없습니다.
- 임시비밀번호로 처음 로그인하면 새 비밀번호 설정 화면만 보입니다. 서버도 그 전에는 다른 기능을 막습니다.
- 새 비밀번호 조건: 8자 이상, 영문·숫자·특수문자 중 두 가지 이상, 사번 포함 금지
- 직원은 오른쪽 위 사용자 메뉴의 `비밀번호 변경`으로 언제든 바꿀 수 있습니다.

## 3. 사용자 관리(관리자)

- 직원 목록: 이름, 사번, 부서, 권한(일반사용자/관리자), 상태(사용중/사용중지), 최근 로그인
  - 검색: 이름·사번
  - 필터: 부서·권한·상태
- `직원 추가`: 한 명씩 등록합니다.
- `수정`: 이름, 부서 이동, 권한, 사용중지를 바꿉니다. 계정·사번·비밀번호·과거 신고는 그대로 유지됩니다.
  - 본인 권한·상태와 마지막 관리자는 바꿀 수 없습니다.
- `비밀번호 초기화`: 새 임시비밀번호를 만들고, 다음 로그인 때 변경을 강제합니다.
- 삭제 대신 사용중지합니다. 사용중지하면 즉시 로그인할 수 없고, 기존 신고와 통계는 남습니다.
- `부서 관리`: 부서 추가, 이름 변경, 사용중지. 부서는 삭제하지 않으므로 직원 연결이 끊기지 않습니다.
- 새 직원은 SCHAT 작업 공간을 바로 사용할 수 있게 자동으로 연결됩니다.

## 4. 직원 일괄등록

1. `일괄등록 양식 다운로드`(xlsx)
   - 1번 시트: `부서 | 사번 | 이름 | 권한`
   - 2번 시트: 권한 입력값과 현재 사용중인 부서 안내
2. xlsx 또는 csv 파일 올리기(5MB·1,000명 이하)
   - 파일은 서버 메모리에서만 읽고 저장하지 않습니다.
3. `등록 전 확인`: 총 인원, 정상, 오류(행 번호·사번·사유)
   - 검사 항목: 필수 칸, 빈 행, 부서 누락·미등록·사용중지, 사번·이름 누락, 잘못된 권한, 파일 안 사번 중복, 같은 사번의 다른 이름·부서, 이미 등록된 사번(`이미 등록됨`, 덮어쓰지 않음)
4. `정상 N명 등록` 또는 `취소`
   - 확인 결과는 10분짜리 일회용 확인값으로 한 번만 등록할 수 있습니다.
   - 사번은 DB에서도 중복될 수 없어, 버튼을 여러 번 눌러도 계정이 두 번 생기지 않습니다.
5. 결과: `N명의 계정이 생성되었습니다.`와 임시비밀번호 표를 보여 줍니다. `등록 결과 다운로드`(csv)는 브라우저에서 만들고 서버에는 저장하지 않습니다.

- 기존 직원의 부서 이동·사용중지를 파일로 한꺼번에 하는 기능(`직원 정보 일괄수정`)은 이번에 만들지 않았습니다. 신규등록과 분리된 구조로 둘 예정이며, 지금은 한 명씩 처리합니다.

## 5. 문제 신고·알림·FAQ·통계

- 직원: 사용자 메뉴에 `문제 신고`, `내 신고`, 오른쪽 위에 알림 종 아이콘(읽지 않은 수)
  - 신고할 때 이름·사번·부서를 입력하지 않습니다. 로그인 계정 id로 연결하고, 신고 당시 이름·사번·부서·권한을 따로 기록합니다.
  - 신고 화면에 개인정보 입력 금지 안내가 있습니다.
  - 제목·내용을 쓰면 승인된 FAQ를 키워드로 찾아 `관련 도움말`로 보여 줍니다. 외부 AI는 호출하지 않으며, 신고는 막지 않습니다.
- 관리자: `SCHAT 관리자 설정 > 문제 신고`
  - 신고 목록: 번호·제목·종류·신고자·사번·부서·등록일·상태
    - 검색: 제목·내용·이름·사번
    - 필터: 부서·종류·상태·기간
  - 상태를 `처리중`·`완료`로 바꾸면 신고한 직원에게만 알림이 갑니다. 완료하려면 처리 결과를 적어야 합니다.
  - 완료된 신고는 `FAQ로 등록`할 수 있습니다. FAQ는 `직원에게 보이기`를 켠 것만 노출됩니다.
  - 통계: 전체, 미처리·처리중·완료, 최근 7일·30일, 평균 처리시간, 종류별, 부서별(신고 당시 부서). 직원 개인별 순위는 없습니다.

- 테스트 부서 `테스트병동A/B`, 가상 직원 22명(`T9xxxx`)으로 확인했습니다.
- 개별 등록 → 임시비밀번호 12자 표시 → 부서·사번·이름·임시비밀번호로 로그인 → 새 비밀번호 설정 화면 강제 → 변경 후 SCHAT 진입
  - 사용자 메뉴에 `테스트직원가 / 테스트병동A · T9***1 / 일반사용자`가 표시됩니다.
- 잘못된 부서·사번·이름·비밀번호와 사용중지 계정 5가지 모두 같은 문구로 실패하고, 로그인 정보가 저장되지 않았습니다.
- 일괄등록
  - 양식은 정상 xlsx입니다.
  - 테스트 파일 28명 → 정상 20·오류 8(이미 등록됨, 부서 누락, 이름 누락, 잘못된 권한, 파일 안 중복 2행, 같은 사번 다른 이름 2행)
  - 등록 버튼 3번 연속 클릭 → 20명만 생성, 임시비밀번호 20개 모두 서로 다름
  - 같은 파일(csv)을 다시 올리면 전부 오류이고 21명이 `이미 등록됨`으로 표시되며 등록 버튼이 비활성화됩니다.
- 문제 신고
  - 직원 A 신고 → 관리자 목록에 이름·사번·부서 표시 → 처리중 → 완료(처리 결과) → 직원 A 알림 2개, 내 신고 `완료`와 처리 결과 표시
  - 직원 B: 신고 0건, 알림 0건. 관리자 API(사용자·신고 목록)는 401로 막힘
  - 비밀번호를 바꾸기 전에는 신고 API도 403으로 막힘
- DB·로그
  - 테스트 계정 22개 모두 bcrypt 해시이고 사번 중복은 없습니다.
  - 컨테이너 로그에는 테스트 이름·사번·비밀번호가 한 번도 남지 않았습니다.
- 테스트 계정과 테스트 부서는 확인 뒤 모두 사용중지했습니다(삭제하지 않음). 사용자 관리에서 `사용중지` 필터로 볼 수 있습니다.
