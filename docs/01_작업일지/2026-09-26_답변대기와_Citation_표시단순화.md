# 2026-09-26 · 답변 대기와 Citation 표시 단순화

## 변경 내용

- 직원 채팅에서 Agent와 도구의 내부 실행 문구를 숨겼습니다.
- 질문을 보낸 뒤 답변이 시작될 때까지 `답변 생성 중 · N초`만 1초 간격으로 표시합니다.
- 같은 PDF의 같은 페이지에서 여러 검색 조각이 사용돼도 Citation은 페이지당 한 행만 표시합니다.
- Citation 기본 행은 항목명을 숨기고 `출처 N · 파일명 · p.N`으로 단순화했습니다.

## 유지한 기능

- 검색 결과, Gemini에 전달되는 근거와 rag-memory 결과는 변경하지 않았습니다.
- 같은 페이지의 여러 근거 중 원문 대체 표시가 필요할 때는 가장 충분한 excerpt를 대표로 사용합니다.
- PDF 원본 보기와 excerpt fallback, 직접 연결 이미지 데이터는 유지합니다.

## 검증

- 답변 대기와 Citation 회귀 테스트 16개가 모두 통과했습니다.
- 같은 PDF p.113 두 건은 화면에서 한 건으로 합쳐지고, p.113과 p.114는 두 건으로 유지됨을 확인했습니다.
- 서로 다른 PDF의 같은 페이지 번호는 각각 표시됨을 확인했습니다.
- frontend production build가 통과했습니다.

## 실제 Docker 브라우저 재검증

- 이전 검증 뒤 `schat-web` 컨테이너가 최신 frontend bundle로 다시 만들어지지 않아, 실제 화면에는 과거 UI가 남아 있었습니다. production 이미지를 재빌드하고 컨테이너를 재생성했습니다.
- WebSocket에서 Agent 상태와 첫 답변 조각이 같은 UUID를 쓸 때 상태 문구가 답변 앞에 합쳐지는 별도 원인도 확인했습니다. 첫 답변 조각은 내부 상태를 이어 붙이지 않고 교체하도록 최소 수정했습니다.
- 외부 Gemini와 문서 검색을 호출하지 않는 실제 Chromium 로컬 이벤트 재생에서 `답변 생성 중 · 2초`만 표시되고 `undefined: Found...`, `rag-memory`, tool 실행 문구가 대기·답변 시작·완료 화면 모두에 나타나지 않았습니다.
- 실제 저장 답변의 source 4개 중 p.113 두 개는 한 행으로 합쳐졌고, 화면에는 p.113·p.116·p.114 Citation 3개만 표시됐습니다. section/항목명은 표시되지 않았습니다.
- p.113의 `근거 원문 보기`는 기존 PDF viewer로 113페이지를 열었고 인증 PDF 요청은 HTTP 200이었습니다.
- Agent 상태·타이머·Citation 관련 회귀 테스트 17개와 production build가 통과했고 Docker 세 서비스가 healthy 상태임을 확인했습니다.
