# 개인 메모와 1차 반영본 격리 확인

## 로그인 재확인과 직원 계정 추가

- 3002·3003 앱과 연결 통로가 실행 중임을 확인함. 재시작 없이 두 주소 화면 HTTP 200을 확인함.
- 각 환경의 기존 preview1(관리자), preview2(직원)는 비밀번호를 바꾸지 않고 보존함. preview3(직원)를 각 시험 DB에 추가함. 기존 체크·메모와 3001은 변경하지 않음.
- 총 6계정 모두 실제 `/api/request-token` 로그인 성공 및 인증 후 시험 체크리스트 목록 접근을 확인함. 비밀번호와 토큰은 문서·Git에 저장하지 않음.
- 첫 로그인 화면은 부서·사번·이름 방식임. 이번 시험 계정은 사번 없는 기존 계정 방식이므로 화면 아래 **사번이 등록되지 않은 기존 계정으로 로그인**을 먼저 누르고 아이디·비밀번호를 입력해야 함. 앞선 안내에 이 선택 단계가 빠져 있었음. 사용자의 실패 화면을 직접 관찰하지 못했으므로 모든 실패 원인이 이것이었다고 단정하지 않음.
- 브라우저 자동 제어 도구는 재시도해도 시작 오류가 발생함. 실제 HTTP 로그인은 검증했으나 브라우저 클릭 완료로 기록하지 않음.
- 연결 통로 컨테이너의 unhealthy 표시는 원본 이미지에서 물려받은 3001 상태검사와 실제 중계 포트 3002·3003이 다른 점을 따로 확인할 필요가 있음. 실제 두 주소의 화면·로그인·인증 후 API는 성공함.

## 준비한 환경

| 목적 | 정확한 코드 | 주소 | 전용 폴더 |
| --- | --- | --- | --- |
| 개인 체크·메모 | ce89927e | http://localhost:3002 | 사용자 임시 폴더의 schat-preview-ce89927e |
| 1차 반영본 | 81ffe720 | http://localhost:3003 | 사용자 임시 폴더의 schat-preview-81ffe720 |

- 두 폴더 모두 Git의 별도 작업 복사본이며 미커밋 기능을 섞지 않음. 각 frontend를 해당 커밋으로 빌드함.
- 각 폴더의 `preview-storage`에 빈 DB를 새로 만들었음. 기존 3001·운영 DB·Chroma·원본 자료를 연결하거나 복사하지 않음. Git에 이미 들어 있던 storage 파일도 실행 환경에는 연결하지 않음.
- 각 환경에 preview1(관리자), preview2(일반 직원)를 생성함. 비밀번호는 전달 메시지에만 안내하며 공식 문서·Git에 넣지 않음.
- 합성 체크리스트 `동기화 확인용` 1개만 등록함. 실제 환자정보를 입력하지 않음.
- 앱 컨테이너는 외부 통신이 없는 내부 네트워크에 둠. 브라우저 연결 전용 중계 컨테이너가 localhost에만 3002·3003을 열어 줌. 다른 PC에서 직접 접속하는 환경은 아님. Chrome/Edge 또는 일반 창/시크릿 창으로 서로 다른 로그인 상태를 확인함.
- 실제 Gemini 호출·임베딩·문서 변환·Chroma 검색을 제공하는 시험은 아님. 키를 넣거나 외부망 차단을 해제하지 않음.
- 기존 3001 컨테이너 재시작·재빌드·DB 변경 없음. push·운영 반영 없음.

## 확인 결과

- 두 화면 빌드 성공, 기존 번들 크기·브라우저 호환 경고는 남음.
- 3002·3003의 `/` 및 `/api/ping` HTTP 200 확인함.
- ce89927e 신규 자동 검사 29개 통과함.
- 3002 실제 HTTP 검사: 로그인, 체크리스트 목록, 계정별 저장, 같은 계정의 별도 로그인 세션 공유, 다른 계정 조회 차단, 오래된 revision 저장 409, 재로그인 후 보존, 잘못된 토큰 401 통과함. 시험 합성 내용은 빈 값으로 되돌림.
- 첫 HTTP 시험 스크립트가 API 필드명을 잘못 써서 400을 받았음. 실제 규격 patient/other로 시험 스크립트만 고친 뒤 통과함. 앱 코드 변경 없음.
- 브라우저 자동 제어는 도구 시작 오류로 수행하지 못함. 실제 화면 입력·한글 조합·로그아웃·동시 수정 안내는 사용자 확인 필요함.

## 직접 확인 순서

1. 3002에서 preview1으로 로그인 후 `http://localhost:3002/workspace/memo-preview/checklist/preview-checklist`를 엶.
2. 가짜 이름 `612호 / 홍길동`을 입력하고 다른 칸을 누름. `612호 / 홍○동`으로 바뀌는지 확인함. 체크와 하단 메모도 입력함.
3. Edge 또는 시크릿 창에서 같은 preview1로 로그인하여 같은 링크를 엶. 저장 내용이 보이는지 확인함.
4. 별도 브라우저에서 preview2로 로그인함. preview1의 내용이 보이지 않아야 함.
5. 같은 계정 두 창에서 모두 새로고침한 뒤, 양쪽 메모를 거의 동시에 수정함. 먼저 한 창에서 저장하고 다른 창은 기존 내용으로 저장하면 충돌 안내가 나와야 함. 자동 저장·주기 조회가 있으므로 두 번째 창에서 이미 최신 내용을 불러왔다면 충돌 없이 정상 수정되는 것이 맞음.
6. 메인 화면의 사용자 메뉴에서 로그아웃함. 열려 있던 메모 창에서도 내용이 사라지는지 확인함. 같은 계정으로 다시 로그인하면 24시간 내 저장 내용이 다시 보여야 함.
7. 3003은 이전 1차 기능 확인용임. 개인 메모 서버 저장 기능은 포함하지 않음. 관리자 화면의 동시답변 설정·답변 재사용·검색 조각 조회·답변 설정을 확인함. 가짜 문서뿐이므로 실제 검색 품질 평가는 할 수 없음.

## 1차 DB 변경 확인

- 비교 기준은 로컬 origin/main `b5aa77bd` → `81ffe720`임. `server/prisma` 전체 변경 없음. 새 테이블·migration 없음.
- `81ffe720` → `ce89927e`에는 schema 및 `20261011020000_checklist_personal_state` migration 추가가 있음. 이것은 3002의 새 DB에만 적용함.
- 운영 서버의 실제 HEAD와 migration 적용 상태는 접속하지 않아 미확인임. 운영 기준이 b5aa77bd보다 오래됐다면 이 결론을 그대로 적용하지 말고 다시 비교해야 함.
- DB 구조 변경이 없다는 뜻이지 로그인·설정 변경 등이 DB 값을 전혀 쓰지 않는다는 뜻은 아님.

## 문서 업데이트 재개 점검

- 최신 진행일지와 guard/service/문서 모델의 연결 상태를 다시 확인함. 키별 잠금 시험 10개를 재실행하여 통과함.
- 실제 service.acquire/owned 및 Document 변경 감싸기는 아직 키를 넘기지 않는 이전 형태임. 따라서 기초 함수 시험 통과만으로 좁은 충돌 보호가 실제 연결됐다고 볼 수 없음.
- 준비 차단 false를 유지함. 이번 두 확인 환경에는 이 미커밋 기능을 섞지 않음.
- 다음: 같은 문서 식별값 통일 → Collector·등록·삭제·초기화에 키별 잠금 연결 → 작업 기록 기반 재시작 복구 → 구본·신본 검색 혼합 방지 → 격리 Collector/Chroma 시험 → 별도 커밋임.
- 문서 업데이트 구현 완료·커밋은 아직 하지 않음.

## 다시 시작할 때

Docker Desktop이 실행 중이어야 함. 생성된 시험 컨테이너 이름은 `schat-preview-ce89927e`, `schat-preview-81ffe720`, `schat-preview-browser`임. 이미 만들어진 컨테이너는 `docker start`로 시작할 수 있음. 시험 DB는 재시작 시 초기화하지 않음. 임시 폴더가 운영체제 정리로 사라지면 다시 준비해야 함. 기존 3001 컨테이너와 혼동하지 않음.
