# 답변 완료 뒤 안내와 출처 강조 보완

## 승인 범위

- release-admin-9의 7870b6af 이후 작업. 정상 답변 뒤 '못 찾음' 계열 안내가 뜰 수 있는 경로를 조사하고 진짜 답변 실패 안내는 보존함.
- 검색 실패 통계는 새 답변부터 실제 답변 실패 기준으로 변경하되 과거 기록의 기존 집계 기준은 유지함. 새 DB 구조 없이 기존 답변 JSON 안에 기준 표시를 저장하는 방식임.
- 출처 인용 강조만 연한 연두색(#e6f7c8에 가까운 합성색)으로 변경. 다른 강조는 수정하지 않고 목록을 보고함.
- 가짜 호출 우선, 실제 Gemini는 필요 시 최대 3회까지 승인됐으나 현재 0회. 운영 서버는 접속하지 않음.
- 3001 백업·반영·PC/휴대폰 확인 후 release-admin-9만 push. 다른 미커밋 변경과 실제 자료는 보존함.

## 원인 조사 중 확인한 것

- 사용 통계는 기존에 출처 0개를 검색 실패로 셌음. 정상 답변 여부와 독립된 판단이므로 과다 집계 가능성이 있음. 통계가 직원 화면의 안내를 직접 띄우는 구조라고 확인한 것은 아님.
- 정확한 '관련 내용을 찾을 수 없습니다' 고정 문자열은 아직 발견하지 못함. 부서의 queryRefusalResponse 설정으로 문구를 바꿀 수 있음. 저장 설정 원문이나 운영 자료를 읽어 특정 사건 원인으로 단정하지 않음.
- 일반 답변은 완료 전송 뒤 기록 저장을 기다리는 동안 생성 제한 타이머가 살아 있어 늦은 오류가 붙을 수 있는 경로를 발견함. Agent 연결 유지 중 완료/대기와 실행 상태가 구분되는지도 조사 중임.
- 안전 근거 검증 실패를 정상 답변으로 간주하거나 숨기지 않음. 일부 글이 표시된 것과 답변이 정상 완료된 것을 구분함.

## 현재와 다음

알림 흐름 가짜 재현·수정, 통계의 새/옛 기준 검사, 연두 강조 검사를 나눠 진행 중. 아직 추가 변경 커밋·3001 반영·push는 하지 않음. 다음은 통합 검사와 독립 검토 → 백업·3001 확인 → 문서 갱신과 선별 커밋·push임.
