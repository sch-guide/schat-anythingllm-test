# 2026-09-30 · 문서 새 버전에서도 체크리스트가 이어지게

## 왜 했나

- 문서를 새로 올리면 문서 번호(document_id)가 바뀜.
- 체크리스트는 문서 번호에 묶여 있어서, 새 버전의 체크리스트가 전부 "검토 필요"로 만들어지고 직원 화면에서 사라졌음.
- 관리자가 공개하거나 고친 내용도 옛 문서 번호에 남고 새 버전으로 이어지지 않았음.
- 수술 양식 쪽(수술 전·수술 후 표)은 자동 추출이 되지 않았음.
- 원본 PDF 글자 좌표를 읽지 못하면 체크리스트가 조용히 빠졌음.

## 바뀐 동작

### 자동 추출 대상

- 파일 이름에 `검사 및 시술`이 들어간 문서와 `수술`이 들어간 문서만 체크리스트를 자동으로 만듦.
- 실무지침서 같은 일반 문서와 줄글 문서는 자동 추출하지 않음.
- 파일 이름의 날짜·버전은 달라도 됨. 예: `검사 및 시술(26.10.01).pdf`.

### 수술 양식

- `수술 전 / 수술 후`(또는 `시술 전 / 시술 후`) 표에 `수술부위 표시`, `피부준비`, `적정성` 칸이 있는 쪽을 새 양식으로 인식함.
- 기존 검사·시술 추출 엔진을 그대로 쓰고, 칸 이름 목록만 하나 추가함.
- 칸 이름과 세부 내용은 모두 원문에서 가져오고 원문과 다시 대조함.
- 실제 지침서에서는 `수술부위 표시 · 피부준비 · 적정성` 세 칸이 한 줄에 나란히 있음. 처음에는 세 칸이 모두 왼쪽 칸 이름 열에 있다고 가정해서 실제 쪽(p.5·21·23·63)을 읽지 못했음. 두 번째·세 번째 칸을 "같은 줄 칸 이름"(IV line과 같은 방식)으로 바꿔 해결함.

### 새 버전을 올렸을 때

| 경우 | 결과 |
|---|---|
| 이전 버전에서 공개된 체크리스트와 제목·항목·세부 내용·숫자가 모두 같음 | 자동 공개 |
| 숫자·시간·단위·문구·항목 추가/삭제·순서가 바뀜 | 검토 필요 (변경됨) |
| 이전 버전에 없던 체크리스트 | 검토 필요 (신규) |
| 이전 버전이 공개 상태가 아니었음(검토 필요·숨김) | 검토 필요 |
| 같은 제목이 새 문서에 두 개 이상 있음 | 검토 필요 |
| 이전 버전이 초안이거나, 옛 형식이라 원문 비교 기준이 없음 | 검토 필요 |
| 새 문서의 원문 자동 대조 자체가 실패함 | 검토 필요 |

- 같은 체크리스트인지는 문서 번호·쪽·파일 이름이 아니라 **문서 종류(검사·시술/수술) + 제목 + 내용 전체**로 판단함.
- 쪽이 바뀌어도 내용이 같으면 같은 체크리스트로 봄.
- 옛 체크리스트를 복사하지 않음. 새 문서에서 다시 추출한 내용이 옛 공개본의 원문과 완전히 같을 때만 공개함.
- 새 문서에서 사라진 체크리스트는 새 문서에 만들어지지 않음.
- 옛 문서의 체크리스트는 그대로 둠(삭제하지 않음).

### 관리자가 고친 체크리스트

- 이전 버전의 원문과 새 버전의 원문이 완전히 같을 때만 관리자 수정본과 공개 상태를 이어받음.
- 원문이 조금이라도 바뀌면 관리자 수정본을 적용하지 않고 새 원문으로 "검토 필요"를 만듦.
- 이를 위해 체크리스트를 저장할 때 "자동 추출 원문 지문"(`sourceFingerprint`)을 함께 저장함. 지문이 없는 기존 파일도 관리자 수정이 없으면 현재 내용으로 비교함.

### Renal biopsy

- 전용 추출기가 "56쪽"일 때만 동작하던 조건을 "검사 및 시술 문서 + 쪽 내용" 기준으로 바꿈.
- 쪽이 바뀌어도 기존 이름(renal biopsy, renal bx, 신장 조직검사, 신생검)을 그대로 유지함.

### 조용한 실패 방지

- 체크리스트 양식처럼 보이는데 원본 PDF 좌표를 못 읽거나 표 모양을 못 읽으면, 건너뛰지 않고 실패로 셈.
- 실패한 쪽과 이유는 서버 로그와 관리자 `시스템 상태 > 최근 시스템 기록`에 "체크리스트 자동 추출 실패"로 남음. 쪽 원문은 남기지 않음.

### 관리자 화면

- `체크리스트 관리` 목록의 상태 옆에 `자동 공개`, `신규`, `변경됨` 표시를 추가함.
- 검토 필요 이유에 "새 문서에서 내용이 바뀌었습니다" 같은 쉬운 설명을 추가함.

## 바꾸지 않은 것

- BM25, Vector 검색, Hybrid 75:25, ChromaDB, Gemini Embedding, Citation, 답변 생성, RAG 평가 구조
- 직원 화면의 체크리스트 연결 규칙(별칭·흔한 이름·동의어)
- 기존 체크리스트 파일, DB, 원본 PDF, `server/storage` (DB migration 없음)
