# 문서 업데이트: 이전 문서 보관 연결 보호

## 목적과 범위

- 비교 테스트 저장소의 문서 업데이트 기능에 필요한 보관 문서 필터를 추가함.
- 보관 표시(`schat_document_update_archived: true`)가 있는 이전 문서를 새 답변 근거나 일반 등록 대상으로 다시 사용하지 않도록 함.
- 실제 병원 문서, 운영 DB, 검색 저장소는 이번 검증에서 읽거나 변경하지 않음. Production 반영을 뜻하지 않음.

## 바뀐 내용

- 고정 문서와 작업공간의 현재 문서 목록에서 보관 문서를 제외함.
- 문서 요약 도우미의 사용 가능한 근거 목록에서도 보관 문서를 제외함.
- 문서 선택기는 보관 연결만 남은 파일을 숨김. 다른 작업공간의 활성 연결이 있으면 공용 목록에 유지함.
- 일반 등록은 해당 작업공간에서 보관한 문서 및 보관 연결만 남은 문서의 재등록을 거절함. DB 조회 실패 때도 등록을 진행하지 않음.
- 보관 문서의 고정·감시 설정 수정과 일반 연결 제거를 차단함.
- 파일 및 폴더 삭제 전 보관 연결을 확인함. 보관 연결이 있거나 조회에 실패하면 실제 파일과 캐시 삭제를 시작하지 않음.
- 파일·폴더 삭제와 고정 문서 읽기를 문서 업데이트 잠금과 연결함.

## 유지한 연결과 한계

- `Document.forWorkspace`, `Document.where`의 전체 조회 의미는 바꾸지 않음. 이전 출처의 원본 PDF 접근에 필요한 보관 연결을 유지함.
- 저장공간 정리는 DB 전체 연결을 직접 조회하므로 보관 자료도 연결된 자료로 확인함.
- `models/vectors.js`의 전체 조회는 작업공간 전체 제거 시 검색 연결 정리용이므로 변경하지 않음.
- 관리자 상태 화면의 문서 통계에는 보관 연결이 포함될 수 있음. 활성 문서 수와 보관 문서 수의 별도 표시는 이번 범위가 아님.
- 폴더의 전체 파일 수는 디스크 파일 수 기준이므로 숨긴 보관 문서 수가 포함될 수 있음.
- 실제 DB·Chroma 교체, 브라우저, 동시 HTTP 요청과 운영 반영은 이 검증에 포함되지 않음.

## 검증 결과

- 구현 전 고정 자료·등록·수정·목록·요약 필터가 없는 상태에서 새 검사의 의도한 실패를 확인하고 수정함.
- `server/__tests__/utils/documentArchive.node.test.js`: 가상 문서·DB 응답을 이용한 검사 10개 통과.
- 위 검사와 기존 잠금 검사 2개, 원본 PDF 저장공간 정리 검사 8개를 함께 실행해 총 20개 통과.
- 수정 파일의 `git diff --check` 통과.
- 외부 API 호출, 실제 자료 삭제, commit, push는 수행하지 않음.
- 현재 상태 문서와 생성 화면 갱신은 전체 문서 업데이트 기능 통합 담당 작업에서 함께 수행함.

## 검토 후 보강

- 일반 수정에서 보관 여부 조회 실패가 문서 없음으로 처리되어 수정으로 이어질 수 있는 경로를 차단함. DB에서 직접 조회하고, 실패하거나 해당 문서가 없으면 저장하지 않음.
- 일반 문서 수정도 업데이트 잠금 적용 대상에 포함함. 업데이트 진행 중에는 DB 읽기·수정을 시작하지 않음.
- 재등록 입력의 `./`와 역슬래시, 반복 구분자를 동일한 상대경로로 통일함. 보관 여부 조회·파일 읽기·검색 저장·DB 저장 모두 같은 경로를 사용함.
- 상위 폴더 이동, 절대경로, 드라이브 경로, 특수 스트림 및 제어문자를 포함한 경로는 등록 전에 거절함.
- 새 회귀검사 5개가 수정 전 실패하는 것을 확인한 뒤 보강함. 보관 검사 15개와 기존 잠금·원본 정리 검사를 함께 실행해 총 25개 통과함.
- 검사 출력의 `DB_UNAVAILABLE`은 의도적으로 만든 DB 조회 실패 사례의 로그이며 실제 DB에 접속한 결과가 아님.
- 수정한 코드 문법 검사와 변경 형식 검사를 다시 통과함. 실제 자료 변경과 commit·push는 하지 않음.
