# 검색 속도 개선과 재검색 방식 비교

## 1. 먼저 확인한 것

### 짧은 답변(Q05·Q09·Q10)

- 실제 답변은 셋 다 "등록된 문서에서 확인되지 않습니다."였습니다(19자).
- **정상이 아니라 검색 문제입니다.** 문서에 근거가 있는데 마지막 거르기 단계에서 모두 빠졌습니다.
  - 혈액제제 사진: 실무지침서 p.113~114가 의미 검색 1~4위였습니다.
  - 수혈 세트: p.125~126이 후보였습니다.
  - PTNB: 검사 및 시술 p.15가 1위였습니다.
- 원인은 마지막 거르기 기준입니다. 문서가 통과하려면 둘 중 하나가 필요합니다.
  - 질문 단어의 2/3 이상이 문서에 그대로 있어야 합니다.
  - 또는 의미 유사도가 0.7 이상이어야 합니다.
- 그런데 "사진·그림·보여줘"가 질문 단어로 세어져 일치율이 0.5가 됩니다. "알려줘"는 빠지는데 이 말들은 빠지지 않습니다. 유사도는 0.63~0.70으로 0.7에 조금 못 미쳤습니다.
- 이번 작업 범위(코드 수정 없이 확인)에 따라 고치지 않았습니다. 별도 개선 과제로 남깁니다.

### 안전 검사(Python)가 호출되지 않는 이유

- 2026-09-24에 직원 답변 경로의 Python 안전검사 Gate를 끄기로 한 결정이 그대로입니다(`SCHAT_SAFETY_GATE_ENABLED=false`, [작업일지](2026-09-24_Python_안전검사_Gate_분리.md)). 서비스와 코드는 연구용으로 보존합니다.
- 또 현재 Automatic(에이전트) 답변 경로는 안전검사와 연결되어 있지 않습니다. 설정을 켜도 Automatic 답변에는 적용되지 않습니다.

## 2. 속도 개선 ①②③ (적용)

- ① 질문 임베딩(Gemini)과, 조각 목록 불러오기·BM25 계산을 동시에 진행합니다.
- ② BM25용 조각 목록과 단어 색인을 서버 메모리에 보관합니다. 다음 경우 새로 불러옵니다.
  - 문서 등록·삭제·교체 등 서버 안에서 Chroma가 바뀌면 즉시
  - 검색마다 조각 ID 목록(약 10~20ms)을 비교해 다른 프로세스에서 바뀐 것을 발견하면
  - 불러온 지 60초가 지나면(관리자 스크립트의 제자리 수정까지 반영)
- ③ 같은 검색어의 임베딩과 검색 결과를 재사용합니다. 검색 결과는 문서가 바뀌면 버리고, 최대 10분만 씁니다.
- 끄는 설정: `SCHAT_SEARCH_CACHE=off`(기본은 켜짐)

### 결과가 같은지 확인

- 대표 질문 10개와 짧은 재검색어 10개, 모두 20개를 확인했습니다.
- 변경 전 코드와 변경 후 코드에 같은 질문 벡터를 넣고 결과 전체를 비교했습니다.
- 캐시가 처음 채워질 때, 캐시를 재사용할 때, 캐시를 비운 뒤, 세 경우 모두 **20/20 값이 같았습니다**.
- Chroma는 문서 정보의 항목 순서를 매번 섞어서 돌려줍니다(변경 전 코드끼리도 다름). 그래서 항목 순서는 정렬해 비교했습니다.

### 속도 (같은 방식, 질문 10개 × 3회)

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 검색 1회 | 1.40초 | 0.64초 |
| 질문당 검색 시간 | 3.7초 | 1.5초 |
| 질문당 BM25 계산 | 1.1초 | 0.3초 |
| 질문당 Chroma 전체 불러오기 | 0.6초 | 0.1초(바뀌었는지 확인만) |
| 첫 글자까지(전체 평균) | 10.6초 | 7.7초 |
| 답변 완료(전체 평균) | 13.0초 | 10.1초 |

- 첫 글자·완료 시간에는 AI가 재검색을 몇 번 하느냐(매번 달라짐)가 크게 섞여 있습니다. 검색 단계 시간이 개선 효과를 더 정확히 보여 줍니다.

## 3. 재검색 줄이기 비교 (기본값은 현재 그대로)

- 방식 A: 미리 검색에서 근거를 찾았으면 그 차례에 검색 도구를 뺍니다. 설정 `SCHAT_AGENT_SKIP_TOOLS_AFTER_FORCED_SEARCH=true`로 켜며, 기본은 꺼짐입니다.
- 방식 B: `AGENT_MAX_TOOL_CALLS=2`입니다. 기존 설정이며 기본값(10)은 그대로입니다.
- 질문 10개 × 각 1회를 비교했습니다(첫 글자 / 완료 / 질문당 입력 토큰 평균).
  - 현재: 9.5초 / 12.0초 / 25,754
  - 방식 A: 6.1초 / 7.3초 / 3,250
  - 방식 B: 8.1초 / 10.2초 / 34,121
- 방식 A는 빠르지만 일부 질문의 답변이 없어졌습니다.
  - Q02 수혈 종류: "상세 내용은 확인되지 않습니다"
  - Q08 항생제 피부반응검사: "확인되지 않습니다"
  - 미리 검색이 찾은 근거가 부족할 때 더 찾지 않기 때문입니다.
- 방식 B는 대체로 재검색을 2회로 줄였습니다. 하지만 Q08에서는 한도 뒤에도 Gemini가 검색 요청을 계속 보내 9회까지 갔습니다(입력 31만 토큰). 지금 설정만으로는 한도가 보장되지 않습니다.
- 답변 전문 비교 문서는 병원 지침 내용이 들어 있어 이 저장소가 아닌 로컬 전용 위치에 두었습니다(Git 제외): 상위 폴더 `workspace/데이터_검수/2026-09-28_재검색_방식_비교/재검색_방식_비교.html`

## 정리

- 측정용 대화방 84개(측정 31, 확인 3, 개선 후 측정 30, 방식 비교 20)와 그 대화·실행 기록을 삭제했습니다. 대화 수는 측정 전과 같은 204개입니다.
- 채팅·Citation·PDF·체크리스트·퀴즈 기능 코드는 바꾸지 않았습니다.
- 서버 테스트 272개 통과(새 검사 5개 포함), Docker 다시 만들기 정상입니다.
- 비용: 개선 후 측정·방식 비교 50회 실행에서 Gemini 답변 호출 125회(입력 약 85만, 출력·thinking 약 3만 9천 토큰)로 약 0.79달러(약 1,100원, 1달러≈1,400원)입니다. 확인용 3회와 결과 비교용 임베딩 약 60회는 이보다 훨씬 적습니다.
