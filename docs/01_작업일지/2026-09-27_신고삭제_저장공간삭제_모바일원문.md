# 문제 신고 삭제 · 저장공간 실제 삭제 · 모바일 원문 보기

## 1. 문제 신고 삭제

- 위치: `SCHAT 관리자 설정 > 문제 신고 > 신고 목록`에서 신고를 누르면 나오는 상세 화면 맨 아래 `위험 영역 > 신고 삭제`. 목록에는 삭제 버튼을 두지 않았습니다.
- 확인창: "문제 신고를 삭제하시겠습니까?"와 제목·신고자·등록일, "삭제 후 복구할 수 없습니다" 안내, `취소`·`삭제`.
- 삭제 방식: 데이터베이스에서 **완전 삭제**합니다(숨김 처리 아님).
  - 이 신고로 직원에게 보낸 처리 알림도 함께 지웁니다.
  - 이 신고로 만든 FAQ는 남고 연결만 끊깁니다.
  - 관리자 기록에는 신고 번호·종류·상태와 삭제한 관리자만 남기고, 신고 내용은 복사하지 않습니다.
- 삭제 뒤 목록에서 바로 사라지고, 목록 위 건수와 통계(전체·미처리·처리중·완료·종류별·부서별)가 새 숫자로 바뀝니다.
- 권한: 서버에서 관리자 권한을 확인합니다. 직원 계정으로 주소나 API를 직접 불러도, 다른 신고 번호를 넣어도 거부됩니다(401).

## 2. 저장공간 정리 실제 삭제

- 그동안 막혀 있던 이유: 조회·미리보기만 승인된 상태여서 `삭제 진행` 버튼을 일부러 꺼 두었습니다.
- 이제 순서는 다음과 같습니다.
  1. 삭제 후보 선택
  2. `선택 항목 확인`: 서버가 현재 자료와 다시 대조해 삭제 전 미리보기를 보여 줌
  3. `삭제 진행`
  4. 최종 확인창("예전 데이터를 삭제하시겠습니까?")
  5. `삭제`
- 서버 안전장치
  - 미리보기를 거친 같은 선택만 삭제할 수 있습니다(10분 안에 한 번만 쓰는 확인값).
  - 삭제 직전에 서버가 자료를 **다시 전부 확인**합니다. 화면의 `삭제 가능` 표시는 믿지 않습니다.
  - 다음 중 하나라도 해당하면 삭제하지 않습니다.
    - 작업 공간에서 사용 중
    - 검색 데이터 연결
    - 이미지 설명 검색 데이터 연결
    - 체크리스트 연결
    - 현재 원본 PDF·PDF 보기 연결
    - 관련 이미지(relatedImages) 연결
  - 삭제 뒤 다시 확인해 현재 운영 수치(문서·페이지·본문 검색 데이터·이미지 설명 검색 데이터·체크리스트·원본 PDF)가 하나라도 달라지면 성공으로 표시하지 않습니다.
  - 삭제 기록(매니페스트)을 서버 진단 폴더에 남깁니다.
  - 여러 정리 작업이 동시에 실행되지 않습니다.
- 삭제 대상: 확인된 예전 업로드의 파일만 지웁니다.
  - 예전 페이지 기록
  - 예전 이미지 폴더
  - 쓰이지 않는 예전 원본 PDF
  - 예전 검색 준비 파일(vector-cache)
- 지우지 않는 것
  - 검색 데이터(Chroma)와 데이터베이스
  - 이미지 설명 저장본
  - 현재 문서
- 참고: 앞선 설계의 "백업 폴더로 옮긴 뒤 되돌리기" 대신, 요청대로 확인 후 바로 삭제하는 방식으로 만들었습니다. 되돌릴 수 없다는 안내를 확인창에 표시합니다.

### 실제로 지운 것

| 항목 | 결과 |
|---|---|
| 대상 | `검사 및 시술(26.04.07).pdf` 예전 업로드 1(현재 사용 안 함) |
| 삭제한 파일 | 164개(예전 페이지 기록 82개 + 예전 검색 준비 파일 82개) |
| 확보 용량 | 약 6MB |
| 삭제 전후 운영 수치 | 문서 2개 · 543쪽 · 본문 검색 데이터 654개 · 이미지 설명 검색 데이터 1,331개 · 체크리스트 64개 · 원본 PDF 2개로 같음 |
| 새로고침 후 | 목록에 다시 나타나지 않음(예전 업로드 4건 → 3건) |

- 삭제 뒤 확인: 체크리스트 API 정상, 현재 원본 PDF 2개 정상(부분 요청 206 포함), 기존 대화의 출처 원본 연결 정상, 로컬 BM25 검색 정상.
- 남은 정리 대상: 실무지침서 예전 업로드 3건(약 816MB 표시). 지울지는 관리자가 화면에서 정하면 됩니다.

## 3. 모바일 근거 원문 보기

- 기존 문제
  - 휴대폰에서 `근거 원문 보기`를 누르면 PDF가 작은 칸 안에 보였습니다.
  - 원문을 제대로 보려면 `원본 PDF를 새 창에서 열기`를 다시 눌러야 했습니다.
  - `텍스트 원문으로 보기`로 바꾸면 PDF로 돌아갈 방법이 없었습니다.
- 바뀐 점(화면 폭 767px 이하에서만, PC는 그대로)
  - `근거 원문 보기 ▸`를 누르면 원문 전용 전체 화면이 열립니다.
  - 위쪽에 `← 채팅으로`, 문서명·쪽(예: `2026실무지침서 (26.7).pdf · p.114`), `PDF 원문`·`텍스트 원문` 전환 버튼이 있습니다.
  - PDF 원문이 기본입니다. 출처 쪽만 화면 폭에 맞춰 그리고, 확대·축소(100~300%)를 할 수 있습니다.
  - PDF 원문과 텍스트 원문을 몇 번이든 오갈 수 있습니다. 예전의 새 창 열기·텍스트 보기 링크는 모바일에서 나오지 않습니다.
  - `← 채팅으로`나 휴대폰 뒤로가기로 닫으면 같은 대화로 돌아갑니다. 스크롤 위치는 `← 채팅으로`에서 그대로였고, 다른 출처를 연 뒤 뒤로가기에서는 27px 차이 안으로 유지됐습니다.
  - 원본 PDF가 없거나 불러오지 못하면 텍스트 원문을 먼저 보여 주고 "원본 PDF를 불러올 수 없어 텍스트 근거를 표시합니다."를 안내합니다.
- PDF는 기존과 같은 로그인 확인 원본 PDF 주소와 `pdfRef`로 가져옵니다.
- 휴대폰에서 PDF 쪽을 그리기 위해 PDF 표시 부품(pdf.js 4.8.69)을 추가했습니다. 모바일에서 원문을 열 때만 내려받습니다.

## 4. 오른쪽 위 사용자 아이콘

- 원형 사람 아이콘을 22px에서 26px로 약 18% 키웠습니다.
- 모양과 선 두께는 그대로입니다.
- 버튼 크기(35px)와 높이는 알림 종 버튼과 같게 유지했습니다(PC·모바일 확인).

## 바꾸지 않은 것

- 사용자 관리, 직원 계정·로그인, Excel 일괄등록, 비밀번호 설정
- Automatic·AgentHandler·rag-memory·BM25·Chroma·Gemini 검색과 답변
- Citation 출처 선택·같은 PDF 쪽 중복 제거, pdfRef 보안, 원본 PDF 주소와 부분 요청(206)
- 체크리스트, 이용 가이드 데이터
- PC의 근거 원문 보기 화면

## 검증

- 실제 브라우저(관리자·테스트 직원 계정)
  - 신고 삭제: 상세·확인창·취소·삭제·새로고침·통계
  - 직원 권한 거부
  - 저장공간 삭제 전 과정과 새로고침
  - 모바일(390px) 원문 화면·전환·확대·돌아가기·실패 시 대체 화면
  - 밝은·어두운 화면
  - PC 기존 화면 유지
- 테스트용 신고 1건만 만들고 지웠습니다. 실제 운영 신고는 지우지 않았습니다.
- 권한 확인에 쓴 테스트 계정(T90001)은 다시 사용중지로 돌려놓았습니다.
- 화면 테스트 115개, 서버 테스트 254개 통과. Docker 다시 만들기 후 정상 동작.
- 새 질문은 보내지 않았고 외부 AI 호출은 하지 않았습니다.

## 추가 수정: PC 근거 원문의 PDF ↔ 텍스트 전환

- 문제: PC에서 `텍스트 원문으로 보기`를 누르면 원본 PDF를 "불러올 수 없음"과 같게 처리해, 다시 PDF로 돌아갈 수 없었습니다.
- 수정
  - `텍스트 원문으로 보기`는 보기만 바꿉니다.
  - 텍스트 화면 오른쪽 위에 `PDF 원문으로 보기`가 생겼습니다(원본 PDF가 있을 때만).
  - PDF → 텍스트 → PDF → 텍스트를 자유롭게 오갈 수 있습니다.
- 채팅 출처와 지침서 퀴즈의 출처는 같은 화면을 쓰므로 둘 다 적용됩니다. 모바일 원문 화면은 전과 같습니다.
- 확인: 실제 브라우저(기존 대화 출처, 새 질문 없음), 화면 테스트 122개 통과, Docker 정상.
