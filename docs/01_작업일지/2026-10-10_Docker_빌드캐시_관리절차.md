# Docker 빌드 캐시 원인 확인과 관리 절차

- 사용자 서버 점검에서 디스크 부족 주원인으로 Build Cache 21GB(87개)를 확인함. Images 6.9GB, storage 1.4GB, 로그·백업은 작다고 전달받음.
- CPU 2개, 메모리 3.8GB, 스왑 사용 1.3GB임. 동시접속 정원이나 현재 메모리 장애까지 확정하지 않음.
- 배포 문서에 빌드 성공·정상 동작 확인 후 `sudo docker builder prune -f`와 남은 공간 확인을 추가함. DB·Chroma volume 삭제 금지를 명시함.
- [자동 관리 안내](../Docker_빌드캐시_자동관리.md)에 빌더 확인·설정 백업·5GB GC 기준·기존 설정 병합·검사·재시작 영향·사후 확인을 정리함.
- [점검 보고서](../운영_안정성_점검_2026-10-10.md)에 사용자 확인 결과와 문서 조치를 반영함.
- 서버 접속·캐시 삭제·설정 적용·재시작은 실행하지 않음. 회수량과 적용 완료는 미확인임.
- 기능 코드·DB·운영 파일 변경 및 commit/push/tag 하지 않음. 다음은 사용자 적용 후 회수 공간·컨테이너 정상 상태 확인임.
