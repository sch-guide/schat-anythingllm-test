# 출처 근거 구간 빨간색 네모 표시 — 2026-10-10

## 요구사항 변경

사용자가 노란 형광 표시를 속이 빈 빨간색 네모박스로 바꾸도록 요청함. 근거 전체 일치 확인, 여러 근거 표시, 첫 위치 이동, 위치 미확정 시 원문 안내 조건은 유지함.

## 구현과 확인

- PC: 원본을 수정하지 않고 임시 PDF에 빨간색 사각형 선을 추가함. PDF의 Ink 주석으로 닫힌 사각형을 저장함.
- 모바일: 동일 좌표에 빨간 테두리를 그림. 글자를 가리지 않도록 채우기를 제거하고 근거 좌표에 2포인트 여유를 둠.
- 관련 자동 검사 12개 통과: 정확한 일치 조건, 원본 보존, PDF 회전 0·90·180·270도 저장 확인 포함.
- 화면 빌드와 수정한 화면 코드 검사 통과. 합성 PDF를 이미지로 그려 빨간 테두리 5개와 빈 내부를 확인함.
- 기존 로컬 컨테이너의 화면 파일만 교체함. 서버·DB·검색 자료 변경이나 컨테이너 재시작 없음. HTTP 정상 응답, 배포한 화면 파일 일치, 샘플 PDF 빨간 Ink 주석 5개 확인.
- 실제 브라우저에서 출처 클릭 및 모바일 자동 이동은 연결된 브라우저가 없어 미확인임.
- 병원 문서 및 외부 AI API 호출 없이 합성 문서만 사용함. 이번 변경의 추가 커밋·push 없음.

## 확인 주소와 다음 작업

- 화면: http://localhost:3001 — 강력 새로고침(Ctrl+F5) 후 출처를 다시 열기.
- 샘플: http://localhost:3001/schat-redbox-test.pdf
- 컨테이너 내부 화면 반영이므로 컨테이너를 새로 만들면 소스에서 다시 빌드하여 반영해야 함.
- 다음 확인: 사용자가 실제 PC·모바일 출처 화면에서 테두리와 첫 위치 이동을 확인함. 다른 창의 문서 교체 작업은 이 변경과 별도임.

## 샘플 404 복구

사용자 캡처로 샘플 주소의 404 화면을 확인함. 컨테이너가 새로 실행되어 public 내부에만 복사했던 샘플 파일이 사라졌음. 파일 없는 주소는 HTTP 200의 HTML을 반환하므로 응답 코드만으로 PDF 제공 여부를 판단할 수 없음. 합성 샘플을 복구하고 frontend/public/schat-redbox-test.pdf에도 저장하여 다음 화면 빌드에 포함하도록 함. 복구 후 application/pdf 응답 형식, %PDF- 파일 서명과 빨간 Ink 주석 5개를 확인함. 실제 출처 클릭 동작은 이번 샘플 복구 확인과 별도임. 커밋·push 없음.

## 근거 전체를 감싸는 네모로 변경

사용자 확인 후 단어·줄·표 칸별 작은 네모 대신 근거 chunk 전체를 하나의 큰 빨간 네모로 감싸도록 변경함. 근거가 여러 개면 근거별로 네모를 분리함. PC·모바일이 공유하는 좌표 계산에서 근거 전체의 바깥 경계를 구함. 기존 정확한 일치 조건과 미확정 안내는 유지함. 자동 검사 12개 통과(여러 줄 근거는 하나, 별도 근거는 별도 네모, PDF 회전 4종 포함). 합성 샘플도 전체 문장과 표를 하나의 근거로 묶어 큰 네모 하나로 변경함.

전체 네모 변경의 화면 빌드·코드 검사·문서 검사 11개 통과. 합성 PDF 이미지로 큰 네모 하나를 확인하고 로컬 화면 파일만 갱신함. HTTP PDF 응답과 빨간 주석 1개 및 배포 화면 파일 일치를 확인함. 실제 브라우저 출처 클릭은 미확인. 추가 커밋·push 없음.

## 페이지 전체 표시 문제 조사와 보수적 범위 축소

사용자 캡처에서 일부 출처는 위치 미확정 안내, 일부는 페이지 대부분을 감싸는 박스가 표시됨을 확인함. 공개 출처 데이터의 text와 excerpt는 검색된 chunk 전체이며, 답변에 사용한 세부 원문 구간이 별도로 전달되지 않음을 코드에서 확인함. 기존 chunk 전체 표시 요구보다 답변에 사용한 부분만 표시하는 최신 요청을 우선함.

화면에서 답변과 원문이 띄어쓰기·줄바꿈을 제외하고 정확히 일치하는 문장만 표시 대상으로 선택하도록 변경함. 연속된 일치 문장은 큰 네모 하나로 묶고, 중간에 답변에 없는 문장이 있으면 구간을 분리함. 참고 자료에는 박스를 생성하지 않음. 내용 유사도나 단어 몇 개만으로 근거 위치를 추정하지 않음.

제약: 표현이 바뀐 답변은 이 방식으로 실제 사용 문장을 확정할 수 없으며 기존 위치 미확정 안내를 유지함. PDF의 글자 항목 경계 불일치·표 읽기 순서 차이도 기존 보수적 처리 대상임. 이 변경은 답변 생성 시 사용 근거 구간을 추적하는 기능을 완성한 것이 아님. 답변 생성 단계의 정확한 인용 구간 전달이 추가로 필요함. 실제 병원 자료·외부 API 호출 없이 합성 자료로 검증함.

검증: 근거 선택 단위 검사 10개, PDF 저장·회전 검사 4개, 기존 PDF 연결 검사 1개 통과. 화면 빌드와 근거 계산 코드 검사 통과. 로컬 컨테이너 화면 파일만 갱신하고 index.js 파일 일치를 확인함. 브라우저에서 사용자 캡처 사례의 재확인은 아직 수행하지 못함. 추가 커밋·push 없음.

## 재발 확인 — 세 출처 모두 위치 미확정

사용자 캡처에서 같은 질문의 출처 3개 모두 위치 미확정 안내가 표시됨을 확인함. 문장 그대로 일치 조건을 추가한 이전 수정으로 사용자 요구를 충족하지 못했음. 완료로 취급하지 않음.

### 코드에서 확인한 원인

- buildPublicRagSource는 검색 source.text 전체를 excerpt와 text로 복사함.
- addRagMemorySources는 검색 시점의 출처를 보관하고 getRagMemorySources가 그대로 반환함.
- chat-history는 답변 저장 시 해당 검색 출처 목록을 함께 저장함. 답변이 실제 사용한 원문 구간을 별도로 기록하는 단계가 없음.
- 화면의 answerHighlightTexts는 답변과 원문의 문장 그대로 일치만 검사하므로 바꿔 쓴 답변에서 빈 배열이 될 수 있음. 빈 배열이면 PDF 위치 검사 이전부터 박스 후보가 없음.
- PDF 글자 경계, 표 읽기 순서 문제는 별도 원인이며 해당 캡처만으로 확정할 수 없음.

### 다음 시작 위치

1. 사용자에게 요청한 재현 질문을 확인함. 외부 API 호출·병원 원문 전체 저장 없이 합성 문서와 가짜 답변으로 재현함.
2. 답변 생성 단계에서 사용한 원문 인용 구간을 출처별로 전달·저장하는 설계를 구현함. 인용 문구는 해당 출처 원문에 실제 존재하는지 검증하고 다른 출처·페이지의 문구가 섞이지 않도록 함.
3. PC·모바일은 검증된 인용 구간으로 좌표를 찾고, 공간적으로 이어지는 근거만 큰 네모로 묶음. 단순 단어 유사도로 사용 근거를 추정하거나 페이지 전체로 돌아가지 않음.
4. 표현이 바뀐 답변, 문장 여러 개, 표, 여러 출처, 틀린 인용, PDF 줄바꿈·글자 경계, 저장된 과거 답변을 합성 자료로 검사함.
5. 서버 코드 변경이 필요하므로 다른 창 작업과 겹치는 파일 및 로컬 반영 시점을 확인한 뒤 배포함. 기존 자료 변경·외부 API 실제 테스트·push 금지.

이번 조사에서는 코드나 실행 화면을 추가 변경하지 않았음. 이전 자동 검사 통과는 사용자 사례 해결의 증거가 아님.
