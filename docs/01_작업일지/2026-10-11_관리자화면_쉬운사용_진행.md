## 4. 옛 원본 PDF 정리 — 기초 구현 중

- 앞의 조사 이후 연결 건수 집계를 추가함. 대화·퀴즈 묶음·문항·생성 기록·체크리스트 연결을 구분하며, 같은 대화에서 같은 문서를 여러 번 인용해도 대화는 1건으로 셈.
- 공개 보고서에는 건수만 담음. 질문·답변 내용과 내부 파일 이름, 변경 확인용 지문은 보내지 않음. 조사 실패 시 새 확인표는 거절함.
- 대화·퀴즈는 연결된 항목 식별자가 바뀌면 확인용 지문도 달라짐. 별도 검토에서 체크리스트·작업공간·검색·이미지는 아직 건수/존재 여부만 비교한다는 제한을 발견함. **삭제 승인에 연결하기 전에 이 부분의 실제 연결 식별자를 반영해야 함.** 현재 지문만으로 모든 변경을 감지한다고 판단하지 않음.
- 신규 6개와 기존 저장공간 검사 19개, 합계 25개 통과함. 첫 전체 검사에서 기존 uuid 의존성이 로컬 server에 없어 3개가 로드 실패함. 이미 설치된 frontend/node_modules를 시험 프로세스의 NODE_PATH로 지정한 뒤 25개 전부 통과함. 새 패키지 설치나 환경 파일 수정 없음.
- 실제 서버 DB/자료는 읽거나 지우지 않음. 삭제 검사는 기존처럼 시스템 임시 폴더의 합성 자료만 사용함. 화면·삭제 API는 아직 연결하지 않았으며 기존 삭제 권한도 넓히지 않았음.
- **이어갈 곳:** 참조 식별자 비교 보완 → 관리자 전용 확인표 API와 관리자/선택목록/만료시간에 묶인 일회용 확인 → 삭제 직전 재검사·문서 교체 충돌 보호 → 화면의 연결 목록/그래도 삭제 확인 → 삭제된 원본 안내(PC·모바일) → 통합 검사 → 4번만 커밋. 현재 변경은 미커밋으로 유지함. 그다음 5~7번과 3001 백업·반영.

### 4번 후속 — 연결 변경 비교와 일회용 확인

- 체크리스트 고유 항목, 작업공간 문서 행, 검색 자료 번호, 이미지 파일 목록을 내부 변경 비교에 반영함. 건수가 같더라도 다른 항목으로 바뀌면 지문이 달라짐. 해당 식별 정보를 확보하지 못하면 새 확인표를 만들지 않음.
- 확인표는 같은 관리자·같은 선택·같은 연결 상태에서 10분 안에 한 번만 사용할 수 있는 기초 함수를 추가함. 다른 관리자 사용, 재사용, 만료, 파일 크기 변경, 선택 변경 거절을 시험함. 확인표 최대 100개로 메모리도 제한함.
- 원본 삭제 함수에 동기식 확인 검사를 추가함. 확인 실패 시 미연결 원본을 포함한 선택 파일을 하나도 지우지 않는 임시 폴더 시험을 통과함. 아직 실제 API에서는 이 확인 함수를 사용하지 않으며 검토 필요 원본의 삭제도 허용하지 않음.
- 최신 합성 검사 29개 통과함. 새 실패를 먼저 재현한 뒤 보완함. 기존 설치 의존성을 시험 프로세스에서만 참조함. DB 구조·운영/로컬 실행 서버·실제 자료·외부 API를 변경하지 않음.
- **다음 시작점:** `createOriginalReviewGate`를 관리자 전용 미리보기 API에 연결하고 삭제 요청의 새 스캔에서 consume 검증 → 문서 교체와의 충돌 보호 → 실제 검토 원본 삭제/삭제 표식 및 PC·모바일 안내 → 관리자 선택·연결 목록·그래도 삭제 화면 → 통합 검사 후 4번 전체 별도 커밋. 아직 기초 구현이므로 완료 커밋하지 않음.

### 4번 마무리 — 연결 확인 후 옛 PDF 삭제

- 관리자 전용 확인 API와 연결 건수 목록, `그래도 삭제` 확인창을 연결함. 확인표는 같은 관리자·선택·연결 상태에서 10분 안에 한 번만 사용함. 확인 불가 자료는 삭제하지 않음.
- 문서 교체 잠금과 원본별 저장·복원 보호를 적용함. 잠금을 확보한 뒤 다시 조사하며, 조사 중 새로 나타난 원본은 지우지 않음. 복원·삭제 보호는 현재 단일 HTTP 서버 프로세스 기준임. 여러 앱 프로세스로 확장할 때는 공유 잠금 설계가 필요함.
- 삭제 표식을 먼저 준비하고 PDF가 실제로 없을 때만 삭제 안내를 반환함. 복원된 파일은 삭제됨으로 표시하지 않음. 현재 부서 문서 또는 해당 사용자의 과거 답변 출처임을 확인한 뒤 안내함.
- PC·모바일에 `원본이 삭제되었습니다` 안내를 연결함. 일반 불러오기 실패와 구분함. 실제 브라우저 수동 확인은 아직 하지 않았으며 3001 최종 반영 뒤 확인 예정임.
- 임시 폴더의 합성 PDF만 사용한 서버 검사 45개, 관리자·출처 관련 화면 검사 25개 통과. 별도 출처 연결 검사 1개도 통과함. 배포용 화면 빌드 47.20초 성공. 기존 큰 묶음·브라우저 목록 경고는 남아 있음.
- 검사 중 기존 문구 기대값과 예전 PDF 로더 위치를 검사하던 항목을 현재 동작에 맞춰 수정함. 위험한 PDF 기능을 끄는 설정은 공통 로더에 그대로 있음.
- 별도 검토에서 발견한 동시 복원·삭제 경쟁과 부서 권한 확인을 보완한 뒤 추가 중요 문제 없음 확인. 운영 자료 삭제·DB 구조 변경·실제 Gemini 호출·기존 서버 재시작·push 없음.
