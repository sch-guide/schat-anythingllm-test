# Excel 삭제 안전 점검 누락 수정

## 원인
문서 목록은 모든 보관 폴더를 읽었지만 삭제 안전 점검은 PDF의 custom-documents 폴더만 읽었다. 별도 Excel 폴더의 등록 전 문서는 점검 결과와 연결되지 않아 삭제 버튼이 나타나지 않았다.

## 수정
Excel 보관 폴더도 점검한다. 실제 보관 경로를 기준으로 현재 사용 문서와 검색 연결을 확인하고, 삭제 대상 경로가 보관 영역을 벗어나거나 심볼릭 링크를 통과하면 거부한다. 원본 파일은 이번 작업에서 삭제하지 않았다. 과거 답변·퀴즈 연결 보호 등 실행 중인 삭제 정책은 그대로 유지했다.

전용 브랜치: fix/excel-cleanup-scan-20261014. 수정 파일: server/utils/schatAdmin/storageCleanup.js 및 관련 자동 검사. 기존 다른 작업의 수정은 보존했다. 로컬 3001에는 실행 중 파일을 바탕으로 이번 수정만 분리해 반영했다.

## 검증
가상 파일을 이용한 자동 검사 16개 통과. 현재 사용 Excel 보호, 미사용 Excel 경로 연결, 경로 이탈 거부를 확인했다. 로컬 Docker 이미지 빌드 성공. 화면 변경이 없어 frontend build는 재실행하지 않았다. 서버 재기동 직후 검증은 연결 거부가 발생해 기동 후 재검증했다. 실제 문서 삭제는 하지 않았다. 외부 AI 호출·운영 배포·commit/push/tag 없음. 추가 비용 0원.

실제 로컬 API 재검증: 현재 사용 Excel 2건은 in_use, 등록 전 Excel 2건은 old_upload. 두 등록 전 문서의 삭제 미리보기 모두 HTTP 200, ok=true, 차단 항목 없음. 실제 삭제 요청은 보내지 않았다. 첫 화면 HTTP 200 및 문서 검사 11개 통과. 브라우저 직접 클릭은 미확인.
