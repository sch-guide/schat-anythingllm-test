# 같은 대제목 아래 체크리스트 수술명 구분

- 날짜: 2026-10-17
- 요청: 원문의 대제목이 같은 여러 수술의 체크리스트 버튼이 같은 이름으로 나오는 문제 수정.

## 원인과 변경

원문 수술명은 체크리스트를 찾는 이름에만 사용했고, 표시 제목에는 병명 대제목을 그대로 사용했다. 직원에게 전달하는 목록에 원문의 `수술명:`·`시술명:`·`검사명:` 값을 표시 제목으로 적용했다. 이름은 각 쪽의 해당 양식에서 읽고, 원문에 없는 설명은 만들지 않는다. 이름을 확인할 수 없으면 기존 제목을 유지한다.

저장된 체크리스트와 항목 ID, 체크 상태, 관리자 화면의 제목은 바꾸지 않는다. 이미 등록된 문서도 저장된 쪽 글자가 남아 있으면 서비스 반영 후 목록을 새로 읽을 때 적용된다.

## 검증과 반영 상태

- 가상 문서로 같은 병명·서로 다른 수술명 사례를 추가하고, 수정 전 실패와 수정 후 통과를 확인했다.
- 서버 체크리스트 관련 자동 검사 81개, 화면 체크리스트 연결 검사 13개 모두 통과.
- 실행 서비스 배포·재시작과 첨부 화면의 실제 재확인은 하지 않았다.
- 기존 수정 파일의 변경을 유지했다. 외부 API 호출과 병원 자료 전송 없음. 추가 비용 0원. Git commit·tag·push 없음.

변경 코드: `server/utils/documentChecklists/sourceNames.js`, `presenter.js`, `server/endpoints/workspaces.js`, `server/__tests__/utils/documentChecklists/sourceNames.node.test.js`.

## 추가 확인: 폐엽절제술 체크리스트가 나타나지 않는 이유

사용자가 제목 수정 뒤에도 체크리스트가 나타나지 않는다고 알려 실제 등록 상태를 읽기 전용으로 확인했다. 수술 지침서 68쪽의 `폐암 Lung cancer` 체크리스트는 생성되어 있으나 `needs_review`(검토 필요), 비공개 상태였다. 원문 자동 대조는 통과했고 문제 목록은 비어 있으며, 새 체크리스트로 기록되어 있다.

등록된 해당 쪽 글자와 현재 연결 코드로 확인한 결과, `폐엽절제술`·`lobectomy` 모두 현재 검토 상태에서는 0개, 공개 상태를 가정한 메모리 내 검사에서는 1개가 연결되었다. 실제 저장 상태는 변경하지 않았다. 이 체크리스트 한 개의 공개 전환 여부를 사용자에게 확인 요청했다. 다른 검토 대기 항목은 공개하지 않는다. 실행 중인 서비스에서의 실제 표시 확인은 아직 하지 않았다.
