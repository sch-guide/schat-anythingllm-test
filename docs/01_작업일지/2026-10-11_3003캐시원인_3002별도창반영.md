# 3003 답변 재사용 원인과 3002 별도 창 반영

## 확인 결과

- Git에는 기존 다른 기능의 미커밋 변경이 남아 있음. 이번에 되돌리거나 함께 커밋하지 않음.
- 3003 앱 시작은 한국 시간 13:04:36임. 관리자 화면의 집계 시작 13:13:03은 Gemini 일일 집계 객체의 초기 조회 시각이며 서버 재시작 증거가 아님.
- 실제 기록: 달빛검사 질문은 13:05:07(마침표 있음), 13:08:32(없음), 13:10:46(있음). 별빛 인계 질문은 13:05:55와 13:08:48에 기록됨.
- 관리자 API도 캐시 저장 0개·아낀 호출 0회로 응답함. 현재 작업공간은 chat 모드이며 SCHAT 안전 답변 경로 활성화 설정도 없음. 캐시의 query 모드·안전 답변 경로 조건을 충족하지 않음.
- 기존 대화 이력이 있는 질문, Agent/명령, 개인 첨부 등이 있는 질문도 재사용에서 제외됨. 마침표는 구분하고 끝 물음표·느낌표는 정규화함. 이번 저장 0개의 원인은 마침표보다 먼저 적용되는 설정 조건임.
- 캐시는 메모리에만 있어 실제 앱 재시작 시 비워지지만, 이번 기록에서는 13:13 재시작으로 지워졌다고 볼 근거가 없음.
- 일반 운영 질문 대부분이 재사용 대상이라고 볼 수 없음. 현재 구현은 안전한 독립 문서 질의의 첫 질문만 대상으로 하는 제한적 기능임. 시험 화면에서 같은 대화를 반복해도 증가하지 않는 것은 해당 보호 조건의 결과임. 이 범위를 임의로 넓히지 않음.
- 시험 중계 주소는 공식 Gemini 도메인과 달라 앱의 일일 호출 집계가 0으로 나옴. 시험의 실제 호출 수는 별도 `/preview-usage` 기준임. 운영의 일일 집계가 고장났다는 결론이 아님.

## 이번 반영

- 3002 별도 폴더에 1207658e의 프런트엔드 변경 파일 5개만 반영함. DB·계정·메모 데이터는 변경하지 않음.
- 3002 세션 검사 16개, production build 통과. 변경 문구가 포함된 실제 화면 파일 HTTP 200 확인함.
- 3003 TXT 안내 화면 파일 및 기존 은하 PDF 인증 조회 HTTP 200 확인함. 문서를 중복 생성하지 않음.
- 캐시 가짜 검사 14개 통과함. 캐시 코드 결함으로 판단한 변경이 없으므로 새 기능 커밋은 만들지 않음.
- 50회 제한을 가짜 카운터로 검사 2개 통과함. 시험 중계기만 재시작하고 실사용 카운터는 18 그대로 유지함. 확인 결과 used 18 / limit 50임. 실제 API 추가 호출 없음.
- 두 앱 시작 시각은 그대로임: 3002 12:39:07, 3003 13:04:36. 3001·운영 반영·push 없음. 이후 재시작하지 않음.
- 브라우저 실제 다중 창 클릭은 미실시함. 사용자 확인이 필요함.

## 사용자 확인 순서

1. 3003 관리자 답변 재사용: 현재 설정에서는 0개가 예상 결과임. 실제 재사용 성공을 보려면 안전 문서 질의 모드 등 조건을 갖춘 별도 시험 설계가 필요함. 이번에는 설정이나 기존 대화를 바꾸지 않음.
2. 3003 Ctrl+Shift+R → 메모 확인용 작업공간 → 은하검사 준비물 질문 또는 기존 답변 → PDF 출처의 근거 원문 보기. TXT는 같은 버튼에서 제한 안내와 텍스트 확인함.
3. 3002 Ctrl+Shift+R → 체크리스트 별도 창 열기 → 합성 체크·메모 입력 → 본창 로그아웃 → 별도 창의 PC 저장 표시와 내용 확인 → 이어서 수정 → 별도 창 새로고침.
4. 다른 계정으로 로그인해도 해당 별도 창이 서버 저장으로 돌아가지 않는지 확인함. 실제 환자정보로 시험하지 않음.
