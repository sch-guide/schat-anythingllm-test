# Gemini 예산 반영 검증

- 채팅 입력·출력 토큰과 관리자 예상 원화 단가로만 비용을 추정함. 실제 잔액이 아니며 임베딩·이미지 설명·퀴즈·동의어 생성 비용은 포함하지 않음.
- 기존 system_settings에 예산 설정과 한도 상태를 저장하며 새 DB migration은 없음. 80% 주의·95% 높은 사용량 경고는 실제 API 한도 소진과 독립적이며 직원 질문을 차단하지 않음.
- 답변 재사용 기록(명시적 cache hit, 입력·출력·전체 토큰 모두 0)이 계산 불가를 유발하던 문제를 실패 검사로 재현한 뒤 수정함. 실제 측정값이 없는 경우는 0원이 아닌 계산 불가로 유지함.
- 이번 실행: 합성 서버·화면·오프라인 미리보기 검사 37개 통과함. 앞선 실제 Prisma/임시 SQLite 검사에서는 서로 다른 프로세스의 예산 저장·재조회·최초 소진 시각 유지·복구 저장을 확인함. 기존 서비스 재시작 시험은 아님.
- 실제 관리자 브라우저 연결은 다시 실패함. 사용자 승인에 따라 재시도를 중단하고 직접 확인 항목으로 남김. 정적 렌더링 검사와 미리보기를 실제 로그인·저장 버튼 클릭 통과로 간주하지 않음.
- 직접 표시 확인: docs_view/gemini-alert-preview.html을 브라우저로 열고 80% → 95% → 계산 불가를 선택함. 이 화면은 실제 컴포넌트로 만든 오프라인 예시이며 API 호출·설정 저장을 하지 않음. 앱 반영 후에는 관리자 > 시스템 상태에서 설정 저장·새로고침을 추가 확인해야 함.
- 3001·3002·3003은 변경·재시작하지 않음. 실제 Gemini 호출·push·운영 반영 없음. 시험 DB·PDF·계정·preview-storage는 커밋하지 않음.
- Vite production build를 임시 출력 폴더에서 수행하여 통과함(63초). Browserslist·브라우저용 외부 모듈·큰 번들 경고는 남아 있음. 현재 미커밋 작업을 포함한 화면 코드 빌드이며 예산 기능만의 격리 전체 앱 시험으로 표현하지 않음.
