# Gemini 한도 소진 알림

## 적용 범위

- 일반 Gemini 답변·Automatic 답변·Gemini Embedding 호출의 오류를 구분함. 질문·검색 근거·모델 설정과 검색 비율을 바꾸지 않음.
- 명확한 한도 소진이면 직원에게 다음 문구를 표시함.

> 현재 AI 사용량이 소진되어 답변할 수 없습니다. 지침서 원본을 확인하시고, 관리자에게 문의해 주세요. 간호교육파트 내선번호 : 6741

- 분당 제한이면 다음 문구를 표시함.

> 사용자가 많아 잠시 후 다시 시도해 주세요.

- 기타 오류는 AI 연결 문제 안내로 표시함. 원문 오류에 포함될 수 있는 요청 내용·키·주소는 새 안내에 노출하지 않음.
- 관리자 화면 상단에 한도 경고와 최초 발생 시각을 한국 시간으로 표시함. 15초 간격으로 서버 상태만 조회하며 Gemini를 호출하지 않음.
- 동일 키·모델·호출 종류의 다음 정상 응답에서 경고를 해제함. 다른 모델 성공과 이미 진행 중이던 오래된 요청의 성공은 새 경고를 지우지 않음. 여러 한도 문제가 있으면 모두 복구될 때까지 경고를 유지함.
- 끝까지 받지 못한 스트림과 사용자가 취소한 요청은 정상 복구로 간주하지 않음. 기존 응답 처리가 완료 조각을 받은 즉시 반복을 종료하는 경로도 검사함.

## 구분 기준

| API 정보 | 판단 |
|---|---|
| 429 또는 RESOURCE_EXHAUSTED + PerDay·일일 한도·명시적 잔액 소진 | 한도 소진으로 구분함. |
| 같은 오류 + PerMinute·분당/초당 제한·명시적 짧은 시간 제한 | 일시적 혼잡으로 구분함. |
| 상세 이유 없는 429·단순 quota/billing 안내·인증·통신 오류 | 기타 오류로 구분함. |

- 429만으로 충전액 소진을 단정하지 않음. Google은 분당·일일·짧은 지출 제한에서도 같은 오류를 사용할 수 있음. [Google 공식 한도 안내](https://ai.google.dev/gemini-api/docs/rate-limits)를 기준으로 확인함.
- SDK의 기존 내부 재시도는 유지함. 안전한 한국어 오류도 기존 오류 종류를 유지하도록 검사함.

## 검증

- 신규 기능 검사 17개와 기존 사용 통계 검사 15개, 합계 32개를 통과함. 모두 가짜 오류·임시 상태를 사용함.
- 로그인하지 않은 사용자·직원은 관리자 경고 조회가 차단됨을 실제 인증/권한 미들웨어로 검사함.
- 관리자 배너를 HTML로 렌더링해 한국 시간과 경고 해제를 확인함. 화면 검사 중 React 참조 누락을 수정하고, 실행 환경의 한국어 시간 형식 차이를 검사에 반영함.
- frontend production build를 통과함. 파일 접근 제한으로 후처리가 한 번 실패했으나 같은 후처리를 승인된 권한으로 실행해 통과함. 기존 browserslist·큰 번들 등의 경고는 남아 있음.
- 실제 API 호출·한도 소진·병원 자료 전송·DB 변경·Docker rebuild·push는 하지 않음.

## 제한사항과 다음 단계

- 경고는 현재 서버 프로세스 메모리에 유지함. 서버 재시작 시 사라지며 여러 서버 프로세스 사이에서 공유되지 않음. 영구 장애 이력 저장이나 다중 서버 지원은 별도 작업임.
- 잔액 자체를 조회하지 않으므로 Google 오류가 구체적이지 않으면 한도 소진 여부는 확정할 수 없음.
- 충전액 대비 추정 사용량 경고는 이번 범위에서 제외함. 모델별 요금과 집계 시작점 확인 후 별도 진행함.
- 브라우저 제어 환경에서 사용 가능한 브라우저가 없어 실제 3001 화면은 미검증임. 이번 코드는 Docker에 반영하지 않았으므로 기존 3001 화면은 그대로임.
- 다른 창의 문서 업데이트·체크리스트·동의어·출처 변경을 보존함. 생성 문서 화면은 다른 미커밋 문서 내용도 포함하므로 이번 기능 전용 커밋에 통째로 넣지 않음.

## 직접 확인할 방법

### 추가 기록: 로컬 Docker 반영 완료함

- 이후 사용자 요청으로 로컬 3001 반영을 수행함. 위의 Docker 미반영 기록은 최초 코드 완료 당시 기록임.
- 실행 중 이미지에는 경고 화면 문구가 있지만 Gemini 서버 파일 2개가 없었음. 기존 서버 수정 대상 4개 파일이 기능 추가 직전 Git 버전과 해시까지 같음을 확인함.
- 다른 창의 미완료 문서 교체·DB 변경을 함께 빌드하지 않도록 서버 파일 6개만 `schat-web`에 복사하고 해당 컨테이너만 재시작함. 전체 이미지 재빌드는 하지 않음.
- 현재 컨테이너의 파일 변경이므로 재시작에는 유지되지만 이전 이미지로 컨테이너를 다시 만들면 사라짐. 다음 이미지 재빌드 시 커밋 `e09f362c`가 포함된 소스를 사용해야 함.
- 로컬 웹 접속 200, 관리자 경고 API의 비로그인 접근 401, 세 컨테이너 healthy를 확인함. DB 파일 존재와 기존 storage·Chroma 연결을 확인함. DB·환경파일·PDF 삭제·교체·재색인은 수행하지 않음.
- Windows 문자 전달 문제로 한 번 실행되지 않은 검사를 파일 복사 방식으로 재실행해 Docker Node 18에서 가짜 오류 검사 12개를 통과함. 실행 중 서버의 경고 상태나 실제 Gemini 한도를 조작하지 않음.
- 브라우저 로그인·실제 경고 발생 화면은 미검증임. 정상 상태에서는 배너가 숨겨지는 것이 정상임.
- 이번 반영 기록은 로컬 문서에 남기며 추가 commit·push와 운영 서버 작업은 하지 않음.

### 사용자 확인 순서

1. 이번 기능이 반영된 테스트 환경에서 관리자 화면을 열어 평상시 경고가 없는지 확인함.
2. 개발 검증은 `server/__tests__/utils/geminiAvailability.node.test.js`와 `geminiAvailabilityEndpoint.node.test.js`, frontend의 `geminiAvailability.node.test.mjs`와 `geminiErrorDisplay.node.test.mjs`를 실행함. 실제 키를 바꾸거나 API를 반복 호출하지 않음.
3. 실제 오류가 자연스럽게 발생했을 때 직원 안내와 관리자 최초 발생 시각을 확인함. 같은 모델 호출이 복구되면 다음 상태 조회에서 경고가 사라짐.
