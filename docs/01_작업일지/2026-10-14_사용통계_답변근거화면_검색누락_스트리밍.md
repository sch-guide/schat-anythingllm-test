# 사용통계 소규모 부서 포함, 답변 근거 화면, 임상 질문 검색 누락, 답변 출력 개선

- 날짜: 2026-10-14
- 상태: 로컬 코드 수정과 검사 완료. 사용자 요청으로 3001 반영함. 운영 서버 반영, commit/push는 하지 않음.
- 범위: 사용통계, 답변 근거 보기(지침별·질문별), Automatic 답변의 선행 검색, BM25 약어 인식, 검색 오류 안내, 단계별 시간 기록, 답변 스트리밍 표시.
- 바꾸지 않은 것: Gemini 모델, Embedding, Vector 75 : BM25 25 가중치, Top-K(4), 유사도 기준(0.25), 관리자 프롬프트, ChromaDB·DB·등록 PDF.

## 1. 사용통계: 5명 미만 부서 포함

- 원인: `server/utils/schatAdmin/usageStats.js` 한 곳에서만 숨김. SQL 조건은 없었음.
  - 부서를 고른 조회에서 1~4명 부서가 있으면 통계 전체를 막음.
  - 전체 조회의 부서별 표에서 1~4명 부서를 "인원이 적어 표시하지 않음"으로 바꿈.
- 수정: 두 조건을 없애고 부서별로 `사용자 n명 · 질문 n건`을 보여 줌. 화면 문구도 바꿈.
- 개인정보: 관리자 전용 권한은 그대로임. 응답에는 이름·사번·계정·개인별 기록이 없고 부서별 합계만 있음. 기존 검사(`user_id|username|employee|display_name` 미포함)도 유지함.
- 0명 부서: 기존 정책을 유지함. 기간 안에 질문이 없는 부서는 표에 나오지 않고, 0명 부서만 골라 조회하면 0건으로 표시됨.
- 기존 기록은 지우거나 바꾸지 않음(읽기만 함). 5분 캐시가 있어 반영 직후 최대 5분은 이전 결과가 보일 수 있음.
- 복사본 DB 확인: 그동안 숨겨지던 132병동(2명)과 교육파트(1명)가 표시됨.

## 2. 답변 근거 보기: 지침별로 보기

- 문단마다 그 문단을 근거로 쓴 답변 수를 배지로 표시함(`질문 n건`).
- 문단을 펼치면 `이 문단을 근거로 쓴 답변 n건`을 다시 접기/펼치기로 보여 줌. 질문을 누르면 질문별 보기의 해당 답변으로 이동함.
- 문서 선택 목록과 문서 제목 옆에 문서 전체의 참조 질문 수를 표시함.
- 긴 문서명·소제목은 한 줄로 줄이고, 마우스를 올리면 전체를 보여 줌. 본문은 줄 간격을 넓히고(`leading-7`) 높이를 360px로 제한함.
- 연결 기준: 문서명과 쪽이 같고, 저장된 인용 문장 앞부분(공백 제외 40자)이 문단 안에 있으면 연결함. 인용이 없는 과거 기록은 같은 쪽이면 연결함.
- 범위: 최근 질문 3,000건을 읽어 계산하고 60초 동안 보관함. 계산이 실패해도 문단 조회는 그대로 됨.
- 쪽·등록 버전·이전 버전 표시, 단어 검색, 이전/다음 목록 기능은 유지함.
- 복사본 확인: 문서 목록 조회 0.19초, 중심정맥관 문서 문단 조회 0.49초.

## 3. 답변 근거 보기: 질문별로 보기

- 질문을 누르면 `답변 원문 보기`와 `검색 근거 상세 보기`를 나눠 보여 줌.
- 답변 원문 보기는 직원 채팅의 답변 컴포넌트(`PromptReply`)를 그대로 사용함. Markdown·표·목록·강조·출처·관련 그림이 채팅과 같은 방식으로 표시되고, 사용자 질문이 먼저 나옴.
- 서버는 저장된 `response.text`, 출처, 관련 그림, 절차 표시 정보를 그대로 돌려줌. 새로 만들거나 요약하지 않음.
- 저장되지 않은 항목이 있으면 "예전 기록이라 … 저장된 범위까지만 표시" 안내를 보여 줌. 복사본 DB의 질문 449건 중 19건은 답변 본문이 없음.
- 검색 근거 상세 보기는 기존 문서·쪽·버전·참고 내용·근거 문단에 검색 유사도를 추가함.
- 유사도: 과거 기록에는 저장되어 있지 않아 "저장되지 않음"으로 표시함. 새 답변부터는 의미 검색 유사도(코사인, 0~1)를 출처에 함께 저장함. 검색 순위 계산에는 쓰지 않음.
- 넓은 화면은 왼쪽 질문 목록·오른쪽 상세의 2단, 좁은 화면은 위아래로 배치함.
- 한계: 체크리스트 버튼, 피드백 버튼처럼 채팅 화면의 조작 버튼은 관리자 재현 화면에 넣지 않음. 질문의 전화번호·긴 숫자는 기존 정책대로 가림.

## 4. 검색 누락과 응답 시간

### 4-1. 측정 방법

- 3001과 분리한 임시 컨테이너에서 측정함. `server/storage` 복사본(643MB)을 사용했고 ChromaDB는 읽기만 함. 측정 후 컨테이너를 삭제함.
- 실제 Gemini Embedding·Gemini 답변을 호출함. 답변 모델은 기존 `gemini-3.1-flash-lite`임.
- 수정 전·후 각각 질문 7개 × 2회 실행함. 아래 시간은 서버 내부 기준이며 브라우저·네트워크 시간은 포함하지 않음.

### 4-2. 원인

1. 등록 자료 확인 결과 3001 복사본의 2,186개 문단에는 I&D(절개 및 배농) 지침이 없음.
   - `I&D`, `배농`, `local block`, `local anesthesia`는 0건임.
   - `I&D`가 들어간 유일한 원문 파일은 `PFTII&DLCO`(폐기능 검사명)였음.
   - 따라서 "확인되지 않습니다"는 검색 실패가 아니라 자료가 없는 경우임. 운영 서버의 등록 자료는 직접 확인하지 않음.
2. Automatic 답변은 병원 단어 목록(간호·수혈·진정 등)에 있는 말이 들어 있을 때만 문서를 먼저 검색함.
   - 수정 전에는 `중심정맥관 관리`, `국소마취하 절개 및 배농`, `정형외과 local block 하 I&D`가 이 목록에 걸리지 않음.
   - 그래서 AI가 검색 도구를 쓰지 않고 바로 답함.
   - 수정 전 `중심정맥관 관리`는 출처 0개로, 문서 근거 없이 일반 지식으로 답함(2/2회).
   - I&D 질문 일부는 "SCHAT은 병원 간호 지침 질문에 답합니다"라는 범위 밖 답변이 나옴(2회 중 1회).
3. BM25 단어 검색은 `I&D`를 i·d로 쪼갠 뒤 짧아서 버렸음. 그래서 질문에서 이 약어가 사라짐.
4. 검색 오류가 나면 AI에게 영어 오류문만 전달해 "문서에 없음"과 구분되지 않았음.

### 4-3. 수정

- 선행 검색 조건을 넓힘. 대상은 다음과 같음.
  - 임상 단어: 마취·외과·내과·정맥·동맥·절개·배농·배액·천자·도뇨·드레싱·소독·주사·수액·산소·흡인·상처·욕창·낙상·혈압·혈당
  - `I&D`처럼 &로 이은 약어
  - 3글자 이상 영어 단어(인사말 제외)
  - 일상 대화("오늘 날씨 어때?", "안녕", "hello" 등)는 예전처럼 검색하지 않음.
- BM25 토큰화에서 한 글자씩 &로 이은 약어(`I&D`, `I & D`)를 한 단어로 봄. `PFTII&DLCO`처럼 긴 영문 사이의 &는 그대로 둠.
- 검색 오류 시 AI에게 "문서에 없다고 하지 말고 일시 오류로 안내"하도록 전달함. 내부 오류 내용은 서버 로그에만 남김.
- 단계별 시간 기록(`[SCHAT timing]`)을 추가함. 질문 원문은 남기지 않음. `SCHAT_TIMING_LOG=off`로 끌 수 있음.
- 동의어: I&D↔절개 및 배농, local block↔국소마취/국소차단, Foley↔유치도뇨관은 코드에 넣지 않음. 관리자 승인 절차가 있는 동의어 관리 화면에서 등록하는 것을 권장함.
  - 이유: 현재 동의어 사전은 띄어쓴 영문 구(예: local anesthesia, central line)를 단어 검색에 쓰지 못하는 제한이 있음. 테스트 자료에 해당 내용도 없어 효과를 검증할 수 없음.
  - 복사본 DB에는 Foley 묶음이 없음. CVC↔중심정맥관 묶음은 사용 중임.

## 5. 답변 출력(스트리밍)

- 실제 경로는 Automatic(웹소켓)임. 서버는 Gemini 조각을 받는 즉시 전달하고 있었음.
- 끊겨 보이는 원인: Gemini가 문장·문단 단위의 큰 조각을 보내고, 화면은 조각마다 한 번에 붙였음.
- 수정: 받은 글자를 다음 프레임들(최대 약 0.2초)에 나눠 이어서 표시함.
  - 새 조각은 항상 0.2초 안에 모두 표시되고, 답변이 끝나면 남은 글자를 즉시 모두 표시함. 인위적 지연이나 타이머는 없음.
  - 글자가 늘어나는 동안 다시 그리는 범위는 그 답변 본문뿐이며, 대화 전체는 다시 그리지 않음.
  - 줄이 끝나지 않은 표 행은 그 줄이 올 때까지 잠깐 빼서 깨진 표가 보이지 않게 함.
  - Automatic 답변이 이어지는 동안에도 자동 스크롤이 프레임마다 아래를 따라감.
  - 동작 줄이기 설정을 켠 사용자는 바로 전체를 표시함.
- 남은 원인: 답변 끝에 숨겨진 인용 확인 블록(`<schat_evidence>`)을 AI가 만드는 동안 출처 표시가 잠시 늦게 붙음. 근거 확인 기능이라 이번에는 바꾸지 않음.
- 실제 브라우저에서 눈으로 확인하지는 않았음. 계산·연결은 자동 검사로 확인함.
