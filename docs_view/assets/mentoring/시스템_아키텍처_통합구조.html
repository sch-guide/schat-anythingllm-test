SCHAT 통합 아키텍처

직접 개발한 Hybrid 검색(버전 2)과 AnythingLLM의 서비스 기반·임베딩 구조가 현재 SCHAT(버전 3)에서 어떻게 합쳐졌는지 정리함. 그림과 표는 2026-10-01 기준 저장소 코드에서 확인한 내용만 사용함.

무엇을 그대로 썼나

AnythingLLM의 로그인·권한·Workspace, 문서 업로드, 채팅(Automatic), 임베딩·벡터DB 연결 구조를 그대로 사용함.

무엇을 끼워 넣었나

AnythingLLM이 모든 채팅에서 부르는 검색 입구는 그대로 두고, 그 뒤 Chroma 검색 부품 안에 SCHAT Hybrid 검색(BM25 + 75:25 결합 + 근거 거르기)을 넣음.

버전 2에서 가져온 것

Python으로 검증한 "의미 검색 + BM25 보완" 방식과 Gemini Embedding·ChromaDB 선택을 가져와 Node.js로 새로 구현함. 코드를 복사하지는 않음.

1. 전체 구조도

  • AnythingLLM 기반 (그대로 사용)
  • SCHAT이 추가·수정한 부분
  • 버전 2에서 검증한 방식
  • 외부 서비스·저장소

점선 상자(Chroma 검색 부품)가 두 시스템이 실제로 합쳐진 곳임. 위쪽은 AnythingLLM의 흐름 그대로이고, 이 상자 안만 SCHAT 방식으로 바뀌었기 때문에 Automatic 채팅·일반 채팅·API 채팅이 모두 같은 Hybrid 검색을 쓰게 됨.

2. 무엇과 무엇이 합쳐졌나

버전 2 · 직접 개발 (Python)

  • Streamlit 화면과 자체 로그인 (app.py, auth.py)
  • 토큰 기준 조각 나누기 (chunking.py)
  • Gemini Embedding + ChromaDB (gemini_embedding.py, chroma_store.py)
  • BM25 + 순위 결합: Gemini 순위를 기본으로 BM25가 놓친 후보 보완 (retrieval.py)
  • 질문별 정답 문서 검색 평가 (evaluate.py)

AnythingLLM · 서비스 기반

  • 로그인·권한·Workspace·대화 저장 (Prisma + SQLite)
  • 문서 업로드와 collector(PDF 글 추출)
  • 임베딩 작업 큐와 임베딩 부품 (Gemini embedder 포함)
  • 벡터DB 부품 교체 구조 (Chroma provider)
  • Automatic 채팅 (AgentHandler · aibitat · rag-memory 도구)

버전 3 · 현재 SCHAT

  • 화면·로그인·문서 관리·채팅은 AnythingLLM 그대로 쓰고, 관리자 화면과 직원 기능(사번 로그인·이용 가이드·퀴즈 등)을 추가함
  • 조각 규칙은 900자·120자 겹침으로 Chroma 부품 안에 고정함 (schatPolicy.js)
  • 임베딩은 AnythingLLM Gemini embedder를 쓰고 기본 모델과 키 공유만 고침
  • 버전 2의 "의미 검색 + BM25 보완"을 Node.js로 새로 구현함. 결합은 75:25 등수 방식으로 바꿈 (schatBm25.js)
  • 병원 질문 강제 검색·근거 거르기·Citation·원본 PDF·체크리스트를 추가함
  • 평가는 Python 도구로 현재 Chroma 데이터를 다시 계산함 (A8: Hybrid Hit@10 100%, MRR 0.738)

3. 질문 한 개가 처리되는 순서

  1. 직원이 질문함AnythingLLM

    채팅 화면 → Workspace 권한 확인 → Automatic 채팅(AgentHandler)으로 전달됨.

  2. 병원 질문이면 먼저 지침서를 검색함SCHAT

    AI가 검색 도구를 부르기 전에 서버가 한 번 검색해 근거를 질문에 붙임(강제 검색).

  3. 검색 공통 입구로 들어감AnythingLLM

    performSimilaritySearch. AI가 추가 검색을 할 때도 같은 입구를 지남.

  4. 의미 검색과 단어 검색을 동시에 함버전 2 방식SCHAT 구현

    질문 임베딩(Gemini) → ChromaDB 코사인 검색과, 같은 조각 목록에 대한 BM25 검색을 함께 돌림. 같은 질문은 캐시로 다시 계산하지 않음.

  5. 두 순위를 합치고 약한 근거를 거름SCHAT

    0.75 ÷ Vector 등수 + 0.25 ÷ BM25 등수로 정렬한 뒤, 질문 단어 일치율(2/3)·의미 유사도(0.7)·약어·사진 질문 규칙으로 거름.

  6. 근거 안에서만 답함AnythingLLMSCHAT 규칙

    Gemini가 답을 쓰고, 근거가 없으면 "등록된 문서에서 확인되지 않습니다"로 답함.

  7. 출처와 원본을 보여 줌SCHAT

    질문과 직접 관련된 출처만 표시하고, 원본 PDF 쪽·근거 원문·체크리스트 버튼을 함께 제공함.

4. Hybrid 검색이 들어간 방법

최종 순위 점수 = 0.75 ÷ Vector 등수 + 0.25 ÷ BM25 등수

왜 공통 입구 뒤에 넣었나

AnythingLLM의 채팅 경로(Automatic·일반·API·임베드)는 모두 VectorDb.performSimilaritySearch를 부름. 이 입구의 모양은 그대로 두고 Chroma 부품 내부만 바꿔서, 채팅 코드를 하나씩 고치지 않고도 모든 경로가 같은 Hybrid 검색을 쓰게 함.

BM25를 따로 저장하지 않는 이유

BM25는 별도 DB 없이, ChromaDB에 저장된 같은 본문 조각을 메모리에 불러와 단어 색인을 만듦. 그래서 Vector와 BM25가 항상 같은 조각을 대상으로 하고, 문서를 등록·삭제하면 캐시를 비워 바로 맞춰짐.

버전 2와 달라진 점

버전 2는 Gemini 순위를 기본으로 BM25가 놓친 후보를 뒤에 보완하는 방식(RRF 계열)이었음. 버전 3은 두 등수를 75:25로 더하는 방식으로 바꿨고, 이 결합으로 Hybrid Hit@10 100%, MRR 0.738을 확인함.

BM25에만 들어가는 SCHAT 보완

동의어 사전("사용" 상태만), 띄어쓰기 차이 보완(한글 2글자 이상 단어), 요청 표현 제외(알려줘·보여줘 등)는 단어 검색과 거르기 단계에만 적용함. 의미 검색과 임베딩은 바꾸지 않음.

영어 약어(예: PTNB)는 따로 3글자 이상일 때만 특별 취급함. 질문에 있는 약어가 모두 들어 있는 조각은 일반 단어가 빠져도 남김.

5. 임베딩이 합쳐진 방법

그대로 쓴 것

AnythingLLM의 임베딩 작업 큐, Gemini embedder 부품, 문서별 임베딩 캐시(vector-cache)를 그대로 사용함.

고친 것

Gemini embedder의 기본 모델을 gemini-embedding-2로 바꾸고, 임베딩 전용 키가 없으면 답변용 키를 함께 쓰게 함(커밋 44566c1d). 조각 규칙(900자·120자 겹침)과 메타데이터(document_id·쪽·그림 설명 구분)는 Chroma 부품에서 정함.

임베딩 모델을 바꾸면 저장된 검색 데이터 전체를 다시 만들어야 함. 그래서 관리자 화면에서는 임베딩 키만 바꿀 수 있고 모델은 바꿀 수 없게 막아 둠.
